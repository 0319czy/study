实时操作系统

Real-Time Operating System · RTOS

系统

能在可预期的时间范围内响应事件、管理任务与资源的嵌入式操作系统内核。

比喻：有经理排班的餐厅，而不是一个人从早忙到晚。

在章节中学习 →

任务

Task

调度

拥有独立栈和入口函数的执行流，是 RTOS 调度的基本单位。

比喻：餐厅里各司其职的员工。

在章节中学习 →

调度器

Scheduler

调度

根据优先级和状态决定下一个运行哪个任务的内核组件。

比喻：决定谁先接待客人的经理。

在章节中学习 →

抢占

Preemption

调度

更高优先级任务就绪时，立即打断当前任务并切换过去。

比喻： VIP 客人到了，经理立刻把服务员叫走。

在章节中学习 →

协作式调度

Cooperative Scheduling

调度

任务不被强制打断，只有主动让出 CPU（阻塞、延时、yield）时才切换。

比喻：员工做完手头这段才愿意接新活。

在章节中学习 →

优先级

Priority

调度

表示任务紧急程度的数值；FreeRTOS 中数值越大优先级越高，与 Zephyr/RT-Thread 相反。

比喻：急诊分诊的等级。

在章节中学习 →

时间片

Time Slice / Time Quantum

调度

同优先级任务轮流运行时，每个任务一次最多连续运行的 tick 数。

比喻：几个同等级客人轮流使用一个充电口。

在章节中学习 →

轮转调度

Round Robin

调度

同优先级就绪任务按时间片依次运行，保证公平。

比喻：发牌一样，一人一张轮着来。

在章节中学习 →

上下文切换

Context Switch

调度

保存当前任务的寄存器现场并恢复另一个任务现场的过程，需要额外 CPU 时间。

比喻：换人接手前，把桌面上的材料收好、再摊开下一人的材料。

在章节中学习 →

就绪态

Ready State

调度

任务已经具备运行条件，只差 CPU；调度器会在合适时机选中它。

比喻：员工已到岗，等着经理派活。

在章节中学习 →

运行态

Running State

调度

任务当前正占用 CPU 执行代码；单核同一时刻只有一个运行态任务。

比喻：正在操作台前干活的那位员工。

在章节中学习 →

阻塞态

Blocked State

调度

任务在等待事件、信号量、队列数据或延时到期，期间不参与调度。

比喻：员工在等原料到货，暂时干不了活。

在章节中学习 →

挂起态

Suspended State

调度

任务被显式暂停，不参与调度，也不会因超时自动恢复，必须调用恢复 API。

比喻：员工被安排休假，必须等通知才回来。

在章节中学习 →

空闲任务

Idle Task

调度

调度器自动创建的最低优先级任务，在没有其他任务就绪时运行，可挂接空闲钩子。

比喻：店里没客人时负责打扫的保底员工。

在章节中学习 →

任务饥饿

Starvation

调度

低优先级任务长期得不到 CPU，通常由高优先级任务忙等或不阻塞造成。

比喻：小客户永远排不到窗口。

在章节中学习 →

优先级反转

Priority Inversion

调度

高优先级任务被低优先级任务持有的资源阻塞，而中优先级任务又抢占了低优先级任务，导致高优先级任务被“间接”拖延。

比喻：低优先级员工拿着唯一打印机，高优先级员工等着，中优先级员工却先插队。

在章节中学习 →

优先级继承

Priority Inheritance

调度

当低优先级任务持有互斥量并阻塞高优先级任务时，临时提升低优先级任务的优先级，释放后恢复。

比喻：临时给持钥匙的人一个“加急牌”，让他赶紧办完。

在章节中学习 →

截止时间

Deadline

调度

任务必须完成处理的最后时刻；实时性关注的是是否在截止时间前完成，而不是平均速度。

比喻：外卖承诺送达时间。

在章节中学习 →

响应时间

Response Time

调度

从事件发生到系统开始处理（或完成处理，需明确口径）所经过的时间。

比喻：按门铃到有人开门的时间。

在章节中学习 →

抖动

Jitter

调度

多次响应时间或周期之间的波动；控制系统通常既怕慢，也怕忽快忽慢。

比喻：公交有时 5 分钟一班、有时 20 分钟一班。

在章节中学习 →

确定性

Determinism

调度

相同条件下系统行为与最坏响应时间可预测、可分析的性质。

比喻：每天固定时刻发车，而不是“看心情”。

在章节中学习 →

系统节拍

Tick

调度

RTOS 的周期性时钟中断，用于计时、延时与时间片；周期通常为 1/configTICK_RATE_HZ 秒。

比喻：整个系统的秒针。

在章节中学习 →

无节拍空闲

Tickless Idle

调度

系统空闲时停止周期 tick，让 MCU 进入低功耗，并在下一个到期事件前唤醒。

比喻：店里没客人就关灯打盹，有预订再提前醒。

在章节中学习 →

任务控制块

Task Control Block · TCB

调度

内核用来描述一个任务的数据结构，保存状态、栈指针、优先级、链表节点等信息。

比喻：每个员工的档案袋。

在章节中学习 →

钩子函数

Hook Function

调度

由内核在特定时机调用的用户回调，例如空闲钩子、tick 钩子、栈溢出钩子。

比喻：流程里的“到此一游”打卡点。

在章节中学习 →

甘特图

Gantt Chart

调度

用时间轴展示各任务占用 CPU 区间的图，是分析调度行为的常用可视化。

比喻：一张谁在什么时间段用会议室的排期表。

在章节中学习 →

信号量

Semaphore

同步

带计数的同步对象，用于事件通知或限制同时访问资源的数量。

比喻：停车场入口显示“剩余车位”的牌子。

在章节中学习 →

二值信号量

Binary Semaphore

同步

计数只有 0/1 的信号量，常用于任务与中断之间的事件通知。

比喻：一张一次性通行证。

在章节中学习 →

计数信号量

Counting Semaphore

同步

可累计多个计数的信号量，适合管理 N 个相同资源或统计事件次数。

比喻：停车场有 N 个车位，出场释放一个。

在章节中学习 →

互斥量

Mutex

同步

带所有权的锁，用于保护共享资源；FreeRTOS 互斥量支持优先级继承。

比喻：卫生间唯一的钥匙，谁拿到谁用，用完必须还。

在章节中学习 →

递归互斥量

Recursive Mutex

同步

同一任务可以重复获取多次的互斥量，获取与释放次数必须匹配。

比喻：同一人可以把钥匙借给自己好几次，但要还同样次数。

在章节中学习 →

队列

Queue

同步

按值拷贝固定大小数据的 FIFO 缓冲，支持任务阻塞等待与中断安全版本 API。

比喻：传送带，放上去的东西按顺序被取走。

在章节中学习 →

事件组

Event Group

同步

用多个事件位表示条件，任务可等待“全部满足”或“任意一个满足”。

比喻：集齐多把钥匙才能开的宝箱。

在章节中学习 →

任务通知

Task Notification

同步

直接发给某个任务的轻量级 32 位通知值，可替代部分信号量和队列场景。

比喻：直接拍某个同事的肩膀，不用广播。

在章节中学习 →

流缓冲区

Stream Buffer

同步

面向字节流的环形缓冲，适合单写者/单读者场景，不保留消息边界。

比喻：水管里的水，连续流动、没有分界。

在章节中学习 →

消息缓冲区

Message Buffer

同步

在流缓冲区基础上记录每条消息长度，适合变长消息。

比喻：水管里装了一个个小包裹，每个包裹有长度标签。

在章节中学习 →

生产者消费者

Producer–Consumer

同步

一类经典并发模型：生产者放数据，消费者取数据，中间用队列解耦与缓冲。

比喻：后厨出菜、传菜员送菜、顾客取菜。

在章节中学习 →

死锁

Deadlock

同步

两个或多个任务互相等待对方持有的资源，导致永远无法继续。

比喻：两人各拿一半钥匙，都等对方先松手。

在章节中学习 →

竞态条件

Race Condition

同步

多个执行流访问共享数据且结果依赖执行顺序，导致偶发错误。

比喻：两个人同时改同一张表格，后写的覆盖先写的。

在章节中学习 →

临界区

Critical Section

同步

访问共享资源时必须互斥执行的代码段；实现方式可能是关中断或加锁。

比喻：手术室一次只允许一台手术。

在章节中学习 →

原子操作

Atomic Operation

同步

不可被中断或并发打断、要么全做要么全不做的操作。

比喻：一扇旋转门，一次只能过一个人。

在章节中学习 →

中断服务程序

Interrupt Service Routine · ISR

中断时间

硬件事件触发后由 CPU 自动跳转执行的函数，应尽量短小，不能调用可能阻塞的 API。

比喻：火警响起时的紧急处置流程。

在章节中学习 →

中断延迟

Interrupt Latency

中断时间

从硬件中断发生到 ISR 第一条指令开始执行的时间，受关中断时长、优先级和硬件影响。

比喻：火警响起到保安起身的时间。

在章节中学习 →

延迟处理

Deferred Processing

中断时间

ISR 只做紧急的最小工作，把耗时处理通过队列/通知交给任务完成。

比喻：火警时先疏散，事后写报告。

在章节中学习 →

中断安全 API

FromISR API

中断时间

FreeRTOS 中专门供 ISR 调用的函数后缀（如 xQueueSendFromISR），不能使用会阻塞的普通版本。

比喻：火警通道专用电梯，不能走普通客梯。

在章节中学习 →

更高优先级任务被唤醒

xHigherPriorityTaskWoken

中断时间

FromISR API 的输出参数，告诉 ISR 是否需要在退出时请求上下文切换。

比喻：紧急处理完，提醒经理“该换人了”。

在章节中学习 →

嵌套向量中断控制器

Nested Vectored Interrupt Controller · NVIC

中断时间

ARM Cortex-M 的中断控制器，负责中断使能、优先级与嵌套；Cortex-M 中数值越小优先级越高。

比喻：前台的分诊系统。

在章节中学习 →

系统节拍定时器

SysTick Timer

中断时间

Cortex-M 内置的 24 位递减定时器，常被 FreeRTOS 用作 tick 时基。

比喻：系统心脏的起搏器。

在章节中学习 →

可挂起系统调用

PendSV

中断时间

Cortex-M 中优先级最低的异常，FreeRTOS 常用它完成上下文切换，避免在中断中直接切换。

比喻：等所有急事处理完，再做换班交接。

在章节中学习 →

系统服务调用

Supervisor Call · SVC

中断时间

Cortex-M 中用于从任务态进入异常处理的指令，FreeRTOS 启动第一个任务时会用到。

比喻：按铃叫经理来处理。

在章节中学习 →

软件定时器

Software Timer

中断时间

由内核定时器守护任务执行的延时/周期回调，不是硬件定时器，回调中不能阻塞。

比喻：手机里的闹钟 App，不是墙上的机械钟。

在章节中学习 →

定时器守护任务

Timer Daemon Task

中断时间

FreeRTOS 中负责管理软件定时器命令与回调的内核任务，优先级和栈由配置决定。

比喻：专门负责看闹钟、按闹钟的助理。

在章节中学习 →

看门狗

Watchdog Timer

中断时间

独立倒计时硬件，程序未按时喂狗就触发复位；它不是 FreeRTOS 内核的一部分。

比喻：定时巡逻的保安，发现没人签到就拉闸。

在章节中学习 →

中断优先级

Interrupt Priority

中断时间

决定中断能否嵌套及先后顺序；Cortex-M 数值越小越高，FreeRTOS 对可调用 API 的中断优先级有限制。

比喻：医院分诊等级，数字越小越先处理。

在章节中学习 →

堆

Heap

内存

用于动态分配的内存区域；FreeRTOS 提供 heap_1~heap_5 等不同实现。

比喻：一块可以临时划车位的地。

在章节中学习 →

栈

Stack

内存

保存函数调用现场、局部变量和返回地址的内存；每个任务有独立栈。

比喻：每个人自己的桌面，放着当前手头材料。

在章节中学习 →

栈溢出

Stack Overflow

内存

任务栈使用超过分配大小，破坏相邻内存，常导致 HardFault 或随机死机。

比喻：桌面堆满，材料掉到别人桌上。

在章节中学习 →

内存碎片

Heap Fragmentation

内存

空闲内存总量足够，但被切成不连续的小块，导致较大请求分配失败。

比喻：停车场总共有 10 个空位，但分散在各处，停不下一辆大巴。

在章节中学习 →

内存池

Memory Pool

内存

预先分配一组固定大小块，按块分配释放，避免碎片并保证分配时间可预测。

比喻：一排同样大小的储物柜。

在章节中学习 →

静态分配

Static Allocation

内存

编译期或启动时确定内存，不依赖堆，行为可预测，适合安全关键系统。

比喻：房子装修前就把每个柜子位置定死。

在章节中学习 →

动态分配

Dynamic Allocation

内存

运行时从堆申请/释放内存，灵活但可能失败、产生碎片并带来时间不确定性。

比喻：临时租用仓库，方便但价格和空位不稳定。

在章节中学习 →

栈高水位

Stack High Water Mark

内存

任务运行以来栈剩余空间的最小值，用来判断栈是否接近溢出。

比喻：水位线留下的最高水痕。

在章节中学习 →

内存保护单元

Memory Protection Unit · MPU

内存

按区域设置读/写/执行权限的硬件，可阻止任务越界访问，提升安全边界。

比喻：不同区域的门禁权限。

在章节中学习 →

FreeRTOS 堆方案

heap_1 ~ heap_5

内存

FreeRTOS 提供的五种堆实现：从只分配不释放到多内存区域合并，取舍在确定性、碎片与功能之间。

比喻：五种不同规则的共享仓库。

在章节中学习 →

内核

Kernel

系统

操作系统中负责任务调度、同步、时间与内存管理的核心部分。

比喻：餐厅的经理团队。

在章节中学习 →

移植层

Port

系统

把 RTOS 内核适配到具体 CPU 架构的代码，通常包含上下文切换、临界区和 tick 实现。

比喻：把通用管理方案翻译成本店规矩的适配手册。

在章节中学习 →

板级支持包

Board Support Package · BSP

系统

针对具体开发板的驱动、时钟、引脚与外设初始化集合。

比喻：为某家分店定制的开店清单。

在章节中学习 →

硬件抽象层

Hardware Abstraction Layer · HAL

系统

把芯片外设操作封装成统一接口，降低上层代码对具体硬件的依赖。

比喻：统一的电源插座标准。

在章节中学习 →

FreeRTOS 配置文件

FreeRTOSConfig.h

系统

通过一系列 config 宏裁剪内核功能、设置 tick 频率、优先级数量和内存参数的头文件。

比喻：这家餐厅的营业规则手册。

在章节中学习 →

Kconfig 配置系统

Kconfig

系统

Zephyr 等项目使用的编译期配置系统，通过菜单生成 .config 并裁剪功能。

比喻：点菜菜单，勾选后厨房只准备这些。

在章节中学习 →

设备树

Devicetree

系统

用结构化描述文件说明板上的硬件资源与连接，Zephyr 用它生成编译期设备定义。

比喻：一张标明每个插座、管道位置的房屋图纸。

在章节中学习 →

CMSIS

Cortex Microcontroller Software Interface Standard

系统

Arm 为 Cortex-M 提供的一套软件接口标准，包含内核访问、DSP、RTOS 等组件。

比喻： Cortex-M 世界的通用插头标准。

在章节中学习 →

对称多处理

Symmetric Multiprocessing · SMP

系统

多个同构 CPU 核心共享内存并由一个操作系统统一调度；FreeRTOS 11.x 起提供 SMP 支持。

比喻：多个能力相同的厨师共用一套厨房。

在章节中学习 →

非对称多处理

Asymmetric Multiprocessing · AMP

系统

不同核心运行独立固件或操作系统，通过共享内存/IPC 协作。

比喻：两个独立厨房，通过传菜窗口合作。

在章节中学习 →

跟踪

Tracing

调试

记录任务切换、中断、API 调用等事件的时间线，用于分析真实运行时序。

比喻：给整个餐厅装监控，回放谁在什么时候做了什么。

在章节中学习 →

运行时统计

Run-Time Statistics

调试

统计各任务占用 CPU 的时间与比例，帮助发现忙等、优先级失衡等问题。

比喻：每个员工的工作时长报表。

在章节中学习 →

硬件错误异常
