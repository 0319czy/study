LED 多任务闪烁

第一个能“看见”的 RTOS 工程

场景描述

开发板上有一颗状态 LED 和一颗心跳 LED。要求心跳灯每 500 ms 翻转一次，状态灯每 100 ms 翻转一次，同时串口每 1 s 打印一次系统节拍。用裸机主循环也能做，但用两个独立任务能直观看到“并发”与“阻塞让出 CPU”。

完成后你会
  • 学会创建两个独立任务并给它们不同优先级
  • 理解 vTaskDelay 会让任务进入阻塞态，而不是空转
  • 观察低优先级任务在高优先级任务阻塞后获得 CPU
硬件与工程
  • 任意带 LED 的 Cortex-M 开发板
  • FreeRTOS 工程（厂商 SDK 或官方移植）

实现步骤

  1. 1

    1. 定义两个任务入口

    任务函数必须永不返回。用 vTaskDelay 阻塞，让出 CPU 给另一个任务；不要写 while 空转。

  2. 2

    2. 在 main 中创建任务

    先初始化硬件，再创建任务，最后启动调度器。栈深度单位在多数 Cortex-M port 中是“字”，256 字约 1 KB；实际用高水位校正。

    如果 LED 完全不亮，先确认调度器是否启动、任务是否创建成功，再检查 GPIO 时钟与引脚配置。
  3. 3

    3. 用串口任务观察节拍

    再创建一个低优先级打印任务。它会与 LED 任务竞争 CPU，但因为 LED 任务大部分时间在阻塞，打印任务仍能定期运行。

    xTaskDelayUntil 以“上一次唤醒时刻”为基准，能避免 vTaskDelay 带来的累计漂移。
  4. 4

    4. 做三个对照实验

    把心跳任务的 vTaskDelay 改成空循环，观察状态灯是否变慢；再把两个任务优先级对调，观察执行顺序是否改变。结论比背 API 更重要。

    忙等还会让 CPU 利用率接近 100%，低功耗设计基本失效。

常见坑

  • 任务函数里写 return，导致未定义行为
  • 栈给得太小，printf 一调用就溢出
  • 在中断里调用 vTaskDelay 等阻塞 API
  • 把 vTaskDelay 当成精确定时，忽略 tick 粒度与调度延迟

继续扩展

  • 用 xTaskDelayUntil 让两个 LED 保持严格周期
  • 把优先级改为相同，观察时间片轮转
  • 加入按键任务，按下时临时提高状态灯闪烁频率
