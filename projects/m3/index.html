M3 网关:把串口帧变成可查询的记录

设备端把温湿度打包成 AA 55 帧,Linux 网关负责读懂它、校验它、按接收时刻落盘, 并让查询在数据量变大后仍然快。M0 解决“读到一个数”,M1/M2 解决“可靠地传”,M3 解决“收到之后怎么存、怎么查”。

01目标

M3 的验收不是“串口有输出”,而是一条可复现的数据链路: tty 设备读字节 → 按 AA 55 找帧 → 校验 LEN/CMD/XOR → 去除坏帧 → 给合法记录打接收时间戳 → 写入 CSV 或 SQLite → 用 CLI 或本地 HTTP 查询。每一环都要能解释失败时会发生什么。

项内容
能力 在 Linux 用户态用 termios 配置 115200 8N1 读串口;实现帧同步、长度/命令/异或校验与 500 ms 半帧超时;把合法记录落盘并提供时间/温度查询。
可检查结果 能画出帧结构并手算一帧 XOR;回放 11 帧得到 7 成功 / 4 错误 / 5 条记录 / 2 个杂散字节;导出 5 行 CSV;按温度 ≥ 27 °C 过滤得到 2 条记录与正确均值/极值;写出 systemd 守护、日志轮转与数据保留策略。
证据标识 principle 原理与示例 · simulated 页面回放数据 · compiled gcc 13.3.0 编译并自测 · hardware-pending 真实串口与传感器未验证
  • 能解释为什么帧内没有时间戳字段,以及时间戳应该在哪一层、用哪个时钟打。
  • 能区分“帧格式错误”“XOR 错误”“半帧超时”“帧同步丢失”,并知道每种情况该丢多少字节。
  • 能说清 CSV 与 SQLite 在写入、查询、损坏恢复上的取舍,而不是“哪个高级用哪个”。
  • 能给出网关进程守护、日志、保留期的最小运维方案,并指出它的失效模式。
本页边界:回放器里的 11 帧是按协议构造的样例,不是传感器实测;C 程序只验证了编译与离线解析, 没有连接 /dev/ttyUSB0。真实硬件的 UART 电气层、波特率误差与传感器精度,需要你按 04 的步骤自行验证。

02前置知识

这一页假设你已经在 M0 见过温湿度读数,在 Linux 用户态课里写过 read 与 termios。下面三块是直接前置。

termios 与 tty

串口是 /dev/ttyUSB0(USB 转串口)或 /dev/ttyACM0(CDC)。打开用 O_RDWR | O_NOCTTY, 用 cfmakeraw 关行规程,CS8、清 PARENB/CSTOPB、B115200, VMIN=0 配合 VTIME=5 得到 500 ms 读超时。

UART 与字节序

线路上先发起始位,数据位 LSB 先出,最后停止位;这是位序。协议里的“温度 int16 LE”是字节序: 低字节在前。两者不是一回事,混起来会把 26.50 °C 读成别的数。

复习:MCU 与外设 →

M0 的单位与定点

协议把温度乘以 100 后放进 int16,湿度乘以 100 后放进 uint16,避免浮点传输。 解析时先还原整数,再除以 100;负温度要用有符号解释,不能按 uint16 读。

协议契约速查(与 M1/M2 一致)

字段长度含义与约束
AA 552帧头,固定。只有失步后才需要在字节流里搜索它。
LEN1DATA 字节数。本页上限 32;坏 LEN 不能无限吞数据。
SEQ10–255 回绕。用于发现丢帧,不参与业务主键。
CMD10x01 传感器数据;0x02 心跳。
DATALEN0x01:温度 int16 LE ×100,湿度 uint16 LE ×100(LEN=4);0x02:空(LEN=0)。
XOR1AA ^ 55 ^ LEN ^ SEQ ^ CMD ^ DATA[0] ^ … ^ DATA[LEN-1],含帧头 AA 55。
超时—帧间/半帧 500 ms;超过仍不完整则丢弃半帧并重新同步。
帧长与定点换算principle
整帧长度 = 2(帧头) + 1(LEN) + 1(SEQ) + 1(CMD) + LEN(DATA) + 1(XOR)
         = 6 + LEN

传感器帧(LEN=4,共 10 字节):
    温度 = int16_le(DATA[0], DATA[1]) / 100.0      # 有符号,-5.25 °C 合法
    湿度 = uint16_le(DATA[2], DATA[3]) / 100.0    # 无符号,0–655.35 %

XOR = AA ^ 55 ^ LEN ^ SEQ ^ CMD ^ DATA[0] ^ ... ^ DATA[LEN-1]
    例:AA ^ 55 ^ 04 ^ 01 ^ 01 ^ 5A ^ 0A ^ D4 ^ 12 = 0x6D

与 M1/M2 使用同一契约:本页不另立帧格式,只实现网关侧。若你的设备端改了字段顺序、XOR 范围或超时, 必须同时改两端并更新本页的解析器,否则“能收到字节”不等于“能解析”。

3.3 解析规则:每种错误丢多少字节

情况处理默认样例中的位置
XOR 不匹配整帧丢弃,错误计数 +1;不把 DATA 写入存储。SEQ=04,期望 0x9A,实际 0x64。
CMD 未知按 LEN 消费整帧后丢弃;记录未知命令,便于发现版本不匹配。SEQ=05,CMD=0x03。
LEN 与 CMD 不符丢弃;仍然按 LEN 前进,避免把后续字节当 DATA。SEQ=06,CMD=0x01 但 LEN=3。
截断(半帧)500 ms 内等不到剩余字节:丢弃半帧,重新搜帧头。最后 8 字节,应为 10 字节。
杂散字节不是 AA 55 的字节逐个跳过并计数;不构成“帧”。帧 10 前的 00 FF,共 2 字节。
LEN 超限视为坏帧,只丢帧头后重同步,防止坏 LEN 吞掉整段。本页未放,代码中有上限 32。
SEQ 跳变当前帧仍入库;另记“丢帧”指标,不把 SEQ 当唯一键。0x08 → 0x0A,跳过 0x09。

3.4 存 CSV 还是 SQLite

维度CSV 追加SQLite
写入顺序追加一行,实现最简单;崩溃可能留下半行。事务/WAL,崩溃恢复更稳;需要处理 busy/locked。
查询全表扫描;grep/awk 适合临时查,不适合百万行范围查询。B 树索引,时间范围与温度阈值查询快;可用 SQL 聚合。
并发多进程追加要自己加锁,容易交错。读并发好;写并发受锁限制,可用 WAL。
损坏恢复半行/截断需要人工判断;可用逐行校验。PRAGMA integrity_check;WAL 可回放。
部署无依赖,直接给同事/Excel 打开。需要 libsqlite3;单文件数据库,备份方便。
本页选择教学先用 CSV:导出与人工核对直观;查询器在内存中模拟索引。数据量增长、需要按时间/阈值反复查询时迁移;03.6 给 CLI 与 HTTP 示例。
本页的“查询”是对 5 条内存记录做过滤,不是 SQLite 的真实执行计划。它演示语义(边界是否含等号、空阈值如何处理), 性能结论要看 06 的索引与 EXPLAIN QUERY PLAN,不能拿 5 条记录的体验推断百万行。

3.5 时间戳、守护、日志与保留

时间戳

帧内没有时间字段,时间戳只能由网关在 read 返回时打。用 CLOCK_REALTIME 记墙钟, 用 CLOCK_MONOTONIC 判断 500 ms 超时,避免 NTP 回拨把超时判断弄乱。

存储用 UTC(带 Z)或带偏移的 ISO 8601;显示时再转本地时区。批量补写要用“接收时刻”,不是“处理时刻”。

进程守护

用 systemd 管进程:Restart=always、RestartSec=2、固定 User/Group、 WorkingDirectory 指向数据目录。不要用 nohup 当守护方案。

启动前确认串口设备路径稳定:优先 /dev/serial/by-id/,不要硬编码 ttyUSB0。

日志

日志记录“启动、设备打开、错误帧计数、写盘错误、重连”,不要为每一帧写一行(量太大)。 错误行带 SEQ 与帧 hex,方便复现。

用 logrotate 按天轮转、压缩、保留 14 天;或直接写 journald,用 journalctl -u 查。

数据保留

按天分文件(data/2026-11-27.csv)或按时间删 SQLite 行。先归档再删除,保留期写进运维文档。

删除大量行后 VACUUM 成本高,安排在低峰;更稳的是按天分表/分文件,直接丢旧分区。

本地只读 HTTP 服务(标准库,约 25 行) 
#!/usr/bin/env python3
# m3_api.py — 只读查询接口;生产请加鉴权、限流与分页
import json
import sqlite3
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import urlparse, parse_qs

DB = "/var/lib/m3/sensor.db"

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        q = parse_qs(urlparse(self.path).query)
        tmin = float(q.get("tmin", ["-999"])[0])
        limit = min(int(q.get("limit", ["100"])[0]), 1000)
        con = sqlite3.connect(DB)
        rows = con.execute(
            "SELECT ts, seq, temp_c, humidity_pct FROM readings "
            "WHERE temp_c >= ? ORDER BY ts DESC LIMIT ?",
            (tmin, limit),
        ).fetchall()
        items = [
            {"timestamp": r[0], "seq": r[1], "temp_c": r[2], "humidity_pct": r[3]}
            for r in rows
        ]
        body = json.dumps({"items": items}, ensure_ascii=False).encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

HTTPServer(("127.0.0.1", 8081), Handler).serve_forever()

实验 4:termios 骨架与 gcc 验证

下面是网关骨架的核心:打开 tty、配置 115200 8N1、VTIME=5 得到 500 ms 读超时。完整程序还包含帧解析器、 CSV 输出和与页面相同的 97 字节自测数据。它能在本机编译并运行离线自测,但没有连接真实串口。

m3_gateway.c · serial_open() 核心片段 compiledhardware-pending 
/* 配置串口为 115200 8N1 raw,VTIME=5 即 500 ms 读超时。
 * 返回 fd;失败返回 -1 并已 perror。 */
static int serial_open(const char *dev)
{
    int fd = open(dev, O_RDWR | O_NOCTTY);
    if (fd < 0) {
        perror("open");
        return -1;
    }

    struct termios tio;
    if (tcgetattr(fd, &tio) < 0) {
        perror("tcgetattr");
        close(fd);
        return -1;
    }

    cfmakeraw(&tio);                              /* 关行缓冲/回显/CR-LF 转换 */
    tio.c_cflag &= ~(PARENB | CSTOPB | CSIZE | CRTSCTS);
    tio.c_cflag |= CS8 | CLOCAL | CREAD;          /* 8N1,忽略 Modem 线,启用接收 */
    tio.c_iflag &= ~(IXON | IXOFF | IXANY);       /* 关软件流控 */
    tio.c_cc[VMIN] = 0;                           /* 0 字节 + VTIME:定时读 */
    tio.c_cc[VTIME] = 5;                          /* 5 × 100 ms = 500 ms 超时 */
    cfsetispeed(&tio, B115200);
    cfsetospeed(&tio, B115200);

    if (tcsetattr(fd, TCSANOW, &tio) < 0) {
        perror("tcsetattr");
        close(fd);
        return -1;
    }
    tcflush(fd, TCIOFLUSH);
    return fd;
}

完整 m3_gateway.c(可复制;约 250 行) 
/* m3_gateway.c — Linux 网关骨架:termios 115200 8N1 读串口 + AA55 帧解析 + CSV 输出
 *
 * 编译: gcc -Wall -Wextra -O2 -o m3_gateway m3_gateway.c
 * 自测: ./m3_gateway --self-test
 * 真机: ./m3_gateway /dev/ttyUSB0 > sensor.csv   # 需要 USB-UART 与 M3 设备
 *
 * 协议: AA 55 | LEN | SEQ | CMD | DATA[LEN] | XOR
 *       XOR = AA ^ 55 ^ LEN ^ SEQ ^ CMD ^ DATA[0..LEN-1](含帧头 AA 55)
 *       CMD=0x01 温度 int16LE ×100 + 湿度 uint16LE ×100(LEN=4)
 *       CMD=0x02 心跳(LEN=0);帧间超时 500 ms
 *
 * 证据边界: 本程序在本机 gcc 13.3.0 编译通过,并用 --self-test 验证解析器与页面回放结果一致。
 *           真实串口、真实 UART 电气层与传感器精度未验证(hardware-pending)。
 */
#define _POSIX_C_SOURCE 200809L
#define _DEFAULT_SOURCE          /* cfmakeraw / CRTSCTS 需要 */

#include <errno.h>
#include <fcntl.h>
#include <stdint.h>
#include <stdio.h>
#include <string.h>
#include <termios.h>
#include <time.h>
#include <unistd.h>

#define FRAME_MAX 32          /* LEN 的合理上限,防止坏 LEN 吞掉整段数据 */
#define FRAME_MIN 6           /* AA 55 LEN SEQ CMD XOR */
#define IO_TIMEOUT 500        /* 毫秒,与协议契约一致 */

struct stats {
    unsigned frames;          /* 检出的帧头数(含错误帧) */
    unsigned ok;              /* 校验通过的帧(含心跳) */
    unsigned sensors;         /* 入册的传感器记录 */
    unsigned errors;          /* XOR/长度/CMD/截断错误 */
    unsigned stray;           /* 帧头之外被跳过的字节 */
    unsigned timeouts;        /* 半帧超时被丢弃的次数 */
};

/* 配置串口为 115200 8N1 raw,VTIME=5 即 500 ms 读超时。
 * 返回 fd;失败返回 -1 并已 perror。 */
static int serial_open(const char *dev)
{
    int fd = open(dev, O_RDWR | O_NOCTTY);
    if (fd < 0) {
        perror("open");
        return -1;
    }

    struct termios tio;
    if (tcgetattr(fd, &tio) < 0) {
        perror("tcgetattr");
        close(fd);
        return -1;
    }

    cfmakeraw(&tio);                              /* 关行缓冲/回显/CR-LF 转换 */
    tio.c_cflag &= ~(PARENB | CSTOPB | CSIZE | CRTSCTS);
    tio.c_cflag |= CS8 | CLOCAL | CREAD;          /* 8N1,忽略 Modem 线,启用接收 */
    tio.c_iflag &= ~(IXON | IXOFF | IXANY);       /* 关软件流控 */
    tio.c_cc[VMIN] = 0;                           /* 0 字节 + VTIME:定时读 */
    tio.c_cc[VTIME] = 5;                          /* 5 × 100 ms = 500 ms 超时 */
    cfsetispeed(&tio, B115200);
    cfsetospeed(&tio, B115200);

    if (tcsetattr(fd, TCSANOW, &tio) < 0) {
        perror("tcsetattr");
        close(fd);
        return -1;
    }
    tcflush(fd, TCIOFLUSH);
    return fd;
}

/* 解析一段字节流,返回已消费的字节数。
 * 未消费的尾部留给下一次 read 拼接(半帧):未凑齐的帧不在这里计数,
 * 由调用方在最终化或 500 ms 超时时记一次错误并丢弃。
 * csv != NULL 时把校验通过的传感器帧写成 CSV 行。 */
static size_t parse_stream(const uint8_t *buf, size_t n, struct stats *st, FILE *csv)
{
    size_t pos = 0;

    while (pos < n) {
        if (!(buf[pos] == 0xAA && pos + 1 < n && buf[pos + 1] == 0x55)) {
            pos++;
            st->stray++;
            continue;
        }
        if (n - pos < FRAME_MIN) {
            /* 连最小帧都凑不齐:保留在缓冲区,等下一次 read;
             * 由调用方在最终化或 500 ms 超时时计数并丢弃,避免每轮重复报错。 */
            return pos;
        }

        unsigned len = buf[pos + 2];
        size_t total = (size_t)FRAME_MIN + len;

        if (len > FRAME_MAX) {
            printf("[----] bad LEN=%u (> %d), resync\n", len, FRAME_MAX);
            st->errors++;
            pos += 2;                             /* 只丢帧头,避免吞掉后续好帧 */
            continue;
        }
        if (pos + total > n) {
            /* 半帧:保留到下一次 read,不在这里计数;超时后由主循环处理。 */
            return pos;
        }

        unsigned seq = buf[pos + 3];
        unsigned cmd = buf[pos + 4];
        const uint8_t *data = buf + pos + 5;
        unsigned got = buf[pos + total - 1];
        unsigned calc = 0xAA ^ 0x55 ^ len ^ seq ^ cmd;
        for (unsigned i = 0; i < len; i++) {
            calc ^= data[i];
        }
        calc &= 0xFFu;
        st->frames++;

        if (calc != got) {
            printf("[%02u] seq=%02X cmd=0x%02X temp=-- hum=-- ERR: xor want 0x%02X got 0x%02X\n",
                   st->frames, seq, cmd, calc, got);
            st->errors++;
        } else if (cmd == 0x01 && len != 4) {
            printf("[%02u] seq=%02X cmd=0x%02X temp=-- hum=-- ERR: LEN=%u for sensor\n",
                   st->frames, seq, cmd, len);
            st->errors++;
        } else if (cmd == 0x02 && len != 0) {
            printf("[%02u] seq=%02X cmd=0x%02X temp=-- hum=-- ERR: LEN=%u for heartbeat\n",
                   st->frames, seq, cmd, len);
            st->errors++;
        } else if (cmd == 0x01) {
            uint16_t traw = (uint16_t)(data[0] | (data[1] << 8));
            uint16_t hraw = (uint16_t)(data[2] | (data[3] << 8));
            int32_t temp = (traw & 0x8000u) ? (int32_t)traw - 65536 : (int32_t)traw;
            st->ok++;
            st->sensors++;
            printf("[%02u] seq=%02X cmd=0x%02X temp=%.2f hum=%.2f OK\n",
                   st->frames, seq, cmd, temp / 100.0, hraw / 100.0);

            if (csv != NULL) {
                time_t now = time(NULL);
                struct tm tmv;
                localtime_r(&now, &tmv);
                fprintf(csv, "%04d-%02d-%02dT%02d:%02d:%02d,seq=%u,%.2f,%.2f\n",
                        tmv.tm_year + 1900, tmv.tm_mon + 1, tmv.tm_mday,
                        tmv.tm_hour, tmv.tm_min, tmv.tm_sec,
                        seq, temp / 100.0, hraw / 100.0);
            }
        } else if (cmd == 0x02) {
            st->ok++;
            printf("[%02u] seq=%02X cmd=0x%02X temp=-- hum=-- OK(heartbeat)\n",
                   st->frames, seq, cmd);
        } else {
            printf("[%02u] seq=%02X cmd=0x%02X temp=-- hum=-- ERR: unknown cmd\n",
                   st->frames, seq, cmd);
            st->errors++;
        }
        pos += total;
    }
    return pos;
}

/* 自测:与页面默认回放完全相同的 97 字节(11 帧,其中 4 帧故意写错)。
 * 输出应与页面“帧流回放”的统计一致:frames=11 ok=7 sensors=5 errors=4 stray=2。 */
static int self_test(void)
{
    static const uint8_t stream[] = {
        0xAA, 0x55, 0x00, 0x00, 0x02, 0xFD, 0xAA, 0x55, 0x04, 0x01, 0x01, 0x5A,
        0x0A, 0xD4, 0x12, 0x6D, 0xAA, 0x55, 0x04, 0x02, 0x01, 0xF3, 0xFD, 0x82,
        0x19, 0x6D, 0xAA, 0x55, 0x00, 0x03, 0x02, 0xFE, 0xAA, 0x55, 0x04, 0x04,
        0x01, 0x91, 0x0A, 0xEC, 0x13, 0x64, 0xAA, 0x55, 0x00, 0x05, 0x03, 0xF9,
        0xAA, 0x55, 0x03, 0x06, 0x01, 0x5A, 0x0A, 0xD4, 0x7F, 0xAA, 0x55, 0x04,
        0x07, 0x01, 0x91, 0x0A, 0xEC, 0x13, 0x99, 0xAA, 0x55, 0x04, 0x08, 0x01,
        0xB8, 0x0B, 0x70, 0x17, 0x26, 0x00, 0xFF, 0xAA, 0x55, 0x04, 0x0A, 0x01,
        0x98, 0x08, 0xA0, 0x0F, 0xCF, 0xAA, 0x55, 0x04, 0x0B, 0x01, 0x88, 0x08,
        0xA4,
    };
    struct stats st = {0};
    size_t used = parse_stream(stream, sizeof stream, &st, NULL);
    if (used < sizeof stream && sizeof stream - used >= FRAME_MIN) {
        /* 自测是“最终化”场景:剩下的半帧不会再补齐,补记一次截断错误。 */
        unsigned total = FRAME_MIN + stream[used + 2];
        st.frames++;
        st.errors++;
        printf("[%02u] seq=%02X cmd=0x%02X temp=-- hum=-- ERR: truncated need %u have %zu\n",
               st.frames, stream[used + 3], stream[used + 4], total, sizeof stream - used);
    }
    printf("consumed=%zu buffered=%zu frames=%u ok=%u sensors=%u errors=%u stray=%u\n",
           used, sizeof stream - used, st.frames, st.ok, st.sensors, st.errors, st.stray);
    return st.frames == 11 && st.ok == 7 && st.sensors == 5 &&
           st.errors == 4 && st.stray == 2 ? 0 : 1;
}

int main(int argc, char **argv)
{
    if (argc == 2 && strcmp(argv[1], "--self-test") == 0) {
        return self_test();
    }
    if (argc != 2) {
        fprintf(stderr, "usage: %s --self-test | /dev/ttyUSB0\n", argv[0]);
        return 2;
    }

    int fd = serial_open(argv[1]);
    if (fd < 0) {
        return 1;
    }

    struct stats st = {0};
    uint8_t buf[512];
    size_t used = 0;

    /* 主循环:read 到多少解析多少,半帧留在缓冲区;read 返回 0 表示 500 ms 超时。 */
    for (;;) {
        ssize_t r = read(fd, buf + used, sizeof buf - used);
        if (r > 0) {
            used += (size_t)r;
            size_t consumed = parse_stream(buf, used, &st, stdout);
            if (consumed > 0 && consumed < used) {
                memmove(buf, buf + consumed, used - consumed);
            }
            used -= consumed;
            if (used >= sizeof buf) {
                fprintf(stderr, "buffer full without frame sync, reset\n");
                used = 0;
            }
        } else if (r == 0) {
            if (used > 0) {
                /* 500 ms 内没补齐:半帧记一次错误并丢弃,而不是每轮 read 重复计数。 */
                st.timeouts++;
                st.frames++;
                st.errors++;
                fprintf(stderr, "timeout %d ms with %zu bytes buffered, dropped\n",
                        IO_TIMEOUT, used);
                used = 0;
            }
        } else if (errno == EINTR) {
            continue;
        } else {
            perror("read");
            break;
        }
    }

    fprintf(stderr, "frames=%u ok=%u sensors=%u errors=%u stray=%u timeouts=%u\n",
            st.frames, st.ok, st.sensors, st.errors, st.stray, st.timeouts);
    close(fd);
    return 0;
}

06故障排查

每条按“现象 → 检查步骤 → 预期结果 → 下一分支”组织。先复现、再定位;不要一上来就改协议或加 sudo。

1. 收到乱码或 XOR 错:帧头找到了,数据却对不上
现象
能读到字节,但解析表大量 XOR 错;或温度/湿度明显不合理(如 -300 °C、6000 %RH);或帧头 AA 55 都很难出现。
检查步骤
先用 stty -F 设备 -a 核对 speed 115200 与 cs8 -parenb -cstopb;确认设备端与网关端都按 8N1、无流控;用固定测试帧(如默认样例)从设备端原样发送;检查解析器的 XOR 范围是否与设备端一致(是否误漏 AA 55);检查 int16 是否按有符号解释、字节序是否为小端。
预期结果
stty 显示 115200 8N1;固定测试帧的 XOR 与页面/自测一致;温度在 -40–80 °C、湿度在 0–100 %RH 的合理范围内。
下一分支
若字节本身乱:先统一波特率/8N1,再查晶振误差、TX/RX 接反、地线与电平。若字节正确但 XOR 错:只改协议实现并同时更新两端,不要“在网关端猜一个容错阈值”。

2. 时间戳漂移:记录时间比实际晚、跳变或重复
现象
连续记录的间隔忽大忽小;NTP 校时后出现时间倒退;队列积压时整批记录的时间戳都偏晚;跨时区导出后时间对不上。
检查步骤
确认时间戳是 read 返回时打的,还是写盘时打的;检查是否用 CLOCK_REALTIME 做超时判断;检查系统 NTP/chrony 状态(timedatectl);检查存储是 UTC 还是本地时间、是否带偏移;检查批量补写是否用了“处理时刻”。
预期结果
时间戳单调递增(允许 NTP 微调,但要有告警);500 ms 超时不受校时影响;数据库中的时间带明确时区;导出后能还原到同一时刻。
下一分支
墙钟用 CLOCK_REALTIME,超时/周期用 CLOCK_MONOTONIC;接收时刻入队,写盘沿用入队时间;存 UTC 或带偏移;对“记录间隔 > 2×采样周期”加告警;不要把设备端没有的时间字段凭空补出来。
3. 写盘失败:进程还在跑,数据却停了
现象
日志出现 No space left on device、Read-only file system、Permission denied;CSV 最后一行不完整;SQLite 报 database is locked;重启后缺一段数据。
检查步骤
df -h 与 df -i 看空间和 inode;mount | grep ' / ' 看是否只读;ls -ld 数据目录 与 id 看权限;dmesg | tail 看文件系统/磁盘错误;SQLite 用 PRAGMA journal_mode 与 PRAGMA integrity_check 检查;确认写 CSV 时是否 fflush + fsync。
预期结果
数据目录可写且空间充足;CSV 每行完整(半行可被下一行覆盖或标记);SQLite 能通过完整性检查;写失败会进入错误日志并触发重试/告警,而不是静默丢数据。
下一分支
空间:清理/扩容/缩短保留期;只读:查挂载与磁盘健康,不要反复重启掩盖;权限:用专用用户与组,不要 chmod 777;CSV 半行:先写临时文件再原子改名,或改为 SQLite 事务;SQLite 锁:WAL、缩短事务、避免多写者。
4. 查询延迟:数据变多后,筛选从“瞬间”变成“几十秒”
现象
按时间范围 + 温度阈值查询越来越慢;CSV 方案要扫全文件;SQLite 查询出现全表扫描;网页/接口超时。
检查步骤

预期结果

现象

07小测

5 题,单选。点“提交答案”后页面内判分并显示解析;可点“重做”清零。题目只检查本页的概念与判断,不考记忆无关数字。

1. 帧 AA 55 04 01 01 5A 0A D4 12 92 解析出的温度与湿度是?
正确答案:A。温度 5A 0A 小端为 0x0A5A = 2650,除以 100 得 26.50 °C;湿度 D4 12 为 0x12D4 = 4820,除以 100 得 48.20 %RH。温度用 int16(可为负),湿度用 uint16(无负值)。
2. 本协议的 XOR 覆盖哪些字节?
正确答案:B。契约固定为 AA ^ 55 ^ LEN ^ SEQ ^ CMD ^ DATA…,含帧头 AA 55。两端必须完全一致;若一端漏算帧头,等价于结果再异或 0xFF,所有帧都会“校验错”。
3. 已找到帧头,LEN=4,但缓冲区只有 8 字节(还差 2 字节)。正确做法是?
正确答案:A。一次 read 不保证等于一帧;要维护跨 read 的缓冲。补齐前不能校验(缺字节);用 0 补齐会制造假帧;马上丢帧头会丢掉可能只差 1–2 字节的好帧。超过 500 ms 仍不完整才丢弃半帧。
4. “500 ms 超时”在本页语境下最准确的理解是?
正确答案:A。VTIME=5 只是让 read 最多等 500 ms;协议超时需要自己用单调时钟判断“半帧是否超时”。设备可能间歇上报,不能把“500 ms 没帧”直接判掉线;超时后应丢半帧、重同步,而不是重启进程。
5. 数据涨到百万行,按“时间范围 + 温度阈值”查询变慢,最有效的第一步是?
正确答案:A。查询慢的根因通常是扫描行数,不是串口吞吐。建 (ts, temp_c) 索引、避免在列上套函数、分页,并用执行计划确认;提高波特率只影响采集侧,不会让历史查询变快。
