HOW TO LEARN

四步循环，而不是“收藏夹吃灰”

01

先画地图，再写代码

能复述“用户态→系统调用→VFS→驱动→总线→设备→硬件”，再开始抄第一个模块。

02

每个实验都回答观察问题

动画不是装饰。先预测下一步，再播放验证；答不出观察问题，就回到概念页。

03

用 dmesg 建立证据链

“加载成功”不是结论。看 probe、节点、sysfs、返回码与错误路径，留下可复现日志。

04

在目标内核与板卡上验证

代码是骨架。用目标 build 目录编译，按板级 dts/原理图替换资源，最后做卸载与压力测试。

COMMON MISCONCEPTIONS

五个常见误区

insmod 成功 = 设备可用
加载、init、注册、probe、节点出现是不同阶段，要分别验证。
用户指针可以直接解引用
必须 copy_to_user/copy_from_user；中断上下文也不能访问用户地址。
自旋锁比互斥锁“更快”
选择取决于能否睡眠与临界区长度；选错会死锁或放大延迟。
有 ACK 就说明数据正确
I2C ACK 只说明响应；寄存器、命令与时序仍要验证。
旧教程的 API 永远可用
内核内部 API 不保证稳定；以目标版本头文件/绑定文档为准。
VERSION & SOURCES

版本边界与资料使用

本站的版本策略

默认基线为 Linux 6.x / ARM64。旧内核差异用版本对照卡标注；没有把任何 API 写成“永远正确”。

当前已收录 21 张版本卡，覆盖 class_create、proc_ops、gpiod、ioctl、DMA、mmap 等高频差异。

推荐查证方式

  • 目标内核源码的 include/ 与 drivers/
  • Documentation/devicetree/bindings/ 中的绑定文档
  • Documentation/ABI/ 与稳定接口说明
  • SoC 手册、板级原理图与设备手册

本站不是什么

  • 不是真实内核/开发板环境
  • 不是“万能驱动模板”
  • 不替代官方文档与硬件手册
  • 不把动画或测验当成掌握证明

代码、dmesg、设备号、波形均为教学示意；请在你自己的内核版本与硬件上验证。
