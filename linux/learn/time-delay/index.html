内核时间与延迟

jiffies 与 HZ 是内核的节拍器；定时器、hrtimer 与延时函数决定你是“睡一会”还是“原地等”。

jiffiesHZtimer_listhrtimermsleepusleep_rangendelay

学习目标

  • 换算 jiffies、HZ 与毫秒，理解节拍精度边界
  • 区分 msleep、usleep_range、ndelay 与忙等
  • 知道定时器回调运行在什么上下文、不能做什么
ONE SENTENCE

内核用 jiffies/HZ 计时，用定时器与延时函数安排“以后再做”或“先等一会儿”。

生活化比喻

HZ 是钟表每秒跳几下，jiffies 是秒针走过的格数

timer_list 像普通闹钟：到点提醒，但精度受节拍限制。hrtimer 像高精度秒表：用纳秒计时。msleep 是“睡一会儿，把 CPU 让给别人”；ndelay 是“原地数数，哪儿也不去”。

为什么重要 / 用在哪里

  • 按键消抖、传感器轮询、超时、周期性工作都需要时间管理；延时不等于“随便 sleep 一下”。
  • 定时器回调运行在软中断上下文，不能睡眠；在错误上下文用错延时函数会直接 BUG。
  • HZ 决定节拍精度，jiffies 回绕是实际代码必须处理的边界。
  • 忙等会占住 CPU，睡眠会影响实时性；选择取决于上下文与精度要求。

核心概念

HZ / jiffies

HZ 与 jiffies

HZ 是内核每秒的时钟节拍数，jiffies 是自启动以来的节拍计数。HZ 越高，普通定时器精度通常越高，但开销也更大。

time_after / time_before

回绕比较

jiffies 是无符号长整型，会回绕。不要直接写 `jiffies + timeout > jiffies`；使用 time_after/time_before 等宏处理回绕。

timer_list

timer_list

传统内核定时器，基于 jiffies 节拍。回调运行在软中断上下文，不能睡眠；模块卸载前要用 del_timer_sync 确保回调结束。

high-resolution timer

hrtimer

高精度定时器，使用 ktime_t 纳秒时间。适合需要更细粒度的场景；回调上下文与模式有关，默认不能假设可以睡眠。

msleep / usleep_range

睡眠延时

让当前进程睡眠并让出 CPU，适合进程上下文。usleep_range 比 usleep 更推荐，能给调度器一定范围以减少唤醒抖动。

ndelay / udelay / mdelay

忙等延时

原地循环等待，不睡眠，适合极短且不能睡眠的上下文。时间长会浪费 CPU，不能滥用。

关键 API 与代码

代码是学习示意，以 Linux 6.x / ARM64 为默认基线。每个 API 都列出参数与返回值；不要只抄代码， 先确认它运行在什么上下文、失败时怎么回滚。

timer_list：到点执行回调

API 逐个解释
timer_setup初始化阶段
void timer_setup(struct timer_list *timer, void (*callback)(struct timer_list *), unsigned int flags);

参数：timer：定时器结构；callback：到期回调；flags：通常为 0

返回：无返回值。

注意：Linux 4.15+ 推荐写法；旧内核可能使用 init_timer/字段赋值。

mod_timer任何上下文，但不能在回调里对同一 timer 乱重入
int mod_timer(struct timer_list *timer, unsigned long expires);

参数：timer：定时器；expires：目标 jiffies

返回：返回定时器此前是否处于 pending 状态（具体语义以头文件为准）。

注意：目标时间用 jiffies + msecs_to_jiffies(ms) 计算。

del_timer_sync进程上下文；可能睡眠
int del_timer_sync(struct timer_list *timer);

参数：timer：要删除的定时器

返回：返回是否删除了 pending 定时器。

注意：卸载路径必须用它等待回调结束，避免 use-after-free。

延时函数：睡眠还是忙等

API 逐个解释
msleep进程上下文
void msleep(unsigned int msecs);

参数：msecs：毫秒数

返回：无返回值；不可被信号打断。

注意：不能在中断上下文调用；不能保证精确到毫秒。

usleep_range进程上下文
void usleep_range(unsigned long min, unsigned long max);

参数：min/max：微秒范围

返回：无返回值。

注意：比 usleep 更推荐，给调度器一定范围可减少无谓唤醒。

ndelay任何上下文；忙等
void ndelay(unsigned long nsecs);

参数：nsecs：纳秒数

返回：无返回值。

注意：只适合极短延时；长延时请改用睡眠或定时器。

6.x 是默认基线，旧版只做定位提示。发行版可能回移植补丁，迁移时请直接看目标内核头文件。

版本对照内核时间 / 定时器

timer_setup 与旧定时器 API

6.x 基线

Linux 4.15+ 推荐 timer_setup(&timer, callback, flags)

旧版对照

旧代码常见 init_timer() 再填写 timer.function / timer.data

影响：旧写法在新内核上可能编译失败或字段不可用；定时器回调运行在软中断上下文。

边界：回调不能睡眠；模块卸载前必须 del_timer_sync 并确认回调不再运行。

常见错误与排查

01

定时器回调里打印 BUG: sleeping function called from invalid context。

常见原因
在 timer_list 回调（软中断上下文）中调用了 msleep、mutex_lock、I2C 传输等可能睡眠的函数。
排查 / 修复
回调只做短小工作；需要睡眠的善后交给 workqueue/threaded IRQ。
02

定时器偶尔提前/延后触发，或超时判断失效。

常见原因
直接比较 jiffies 而没有处理回绕；或把 HZ 当成固定 1000。
排查 / 修复
用 time_after/time_before；用 msecs_to_jiffies 换算；不要硬编码 HZ。
03

卸载模块后系统崩溃，日志指向已释放的 timer。

常见原因
卸载前没有 del_timer_sync，回调在模块卸载后仍在运行。
排查 / 修复
在 remove/exit 路径先停止新工作，再 del_timer_sync，最后释放私有数据。

    HZ 是每秒节拍数，jiffies 是节拍计数；换算用 msecs_to_jiffies，回绕比较用 time_after。
