调试与日志

printk 等级、dynamic debug、ftrace、perf、Oops 与 KASAN：把“黑盒崩溃”变成可定位的证据链。

printkdynamic debugftraceperfOopsKASANdmesg

学习目标

  • 读懂 printk 等级与 dmesg 时间戳
  • 用 dynamic debug 按文件/函数开关日志
  • 从 Oops 的 RIP、Call Trace 定位第一现场
ONE SENTENCE

调试不是“加一句打印”，而是建立证据链：日志、动态调试、ftrace、perf、Oops 与内存检查各回答不同问题。

生活化比喻

调试像医院检查：体温计、监护仪、CT、尸检各有用途

printk 是体温计，能看大概；dynamic debug 是可开关的监护仪；ftrace 记录函数调用轨迹；perf 看性能热点；Oops 是事故现场报告；KASAN/lockdep 是专门的病理检查。

为什么重要 / 用在哪里

  • 内核问题往往没有漂亮堆栈；必须靠日志、轨迹与现场信息缩小范围。
  • 在热路径乱打印会改变时序、拖慢系统，甚至掩盖问题。
  • dynamic debug 和 ftrace 可以在不改代码/少改代码的情况下获得证据。
  • Oops 的第一现场是 RIP 与 Call Trace，不是最后一行日志。

核心概念

printk log level

printk 等级

KERN_ERR/WARNING/INFO/DEBUG 等控制日志级别；pr_info/pr_err 与 dev_* 是常用封装。生产代码应避免在热路径大量打印。

dynamic debug

动态调试

为 pr_debug/dev_dbg 提供运行时开关，按文件、函数、行号选择开启；需要内核配置支持。

ftrace

ftrace

内核函数跟踪框架，可看函数调用、调度、中断等事件；tracefs 通常在 /sys/kernel/tracing。

perf

perf

采样性能分析工具，用于找 CPU 热点、调用链与事件计数；适合“哪里慢”，不直接回答“为什么错”。

Oops / panic

Oops 分析

Oops 给出 RIP、Call Trace、寄存器与错误码。先看第一现场与调用栈，再结合源码和反汇编定位。

KASAN / KCSAN / lockdep

内存/并发检查器

KASAN 查越界/use-after-free，KCSAN 查数据竞争，lockdep 查锁顺序与上下文错误。它们需要内核配置支持。

关键 API 与代码

代码是学习示意，以 Linux 6.x / ARM64 为默认基线。每个 API 都列出参数与返回值；不要只抄代码， 先确认它运行在什么上下文、失败时怎么回滚。

驱动日志：pr_fmt 与 dev_*

API 逐个解释
pr_fmt源文件顶部
#define pr_fmt(fmt) "led_demo: " fmt

参数：fmt：后续 pr_* 的格式串前缀

返回：宏；编译期拼接。

注意：必须在包含 printk 相关头文件之前定义，否则可能不生效。

dev_info / dev_err任何上下文；高频调用有性能代价
dev_info(struct device *dev, const char *fmt, ...);

参数：dev：设备；fmt...：格式串与参数

返回：无返回值（底层返回 printk 结果，但通常忽略）。

注意：日志等级要与严重性匹配；不要把正常流程刷成 error。

dynamic debug 与 ftrace 命令

API 逐个解释
dynamic_debug/control用户态调试
echo 'file <path> +p' > /sys/kernel/debug/dynamic_debug/control

参数：file：匹配源文件；+p：开启打印；-p 关闭

返回：无返回值；写入控制文件。

注意：需要 CONFIG_DYNAMIC_DEBUG；路径与实际编译文件名要匹配。

tracefs用户态调试
cat /sys/kernel/tracing/trace

参数：无参数

返回：输出当前 trace 缓冲。

注意：不同系统可能在 /sys/kernel/debug/tracing；先 mount 或查 /proc/mounts。

6.x 是默认基线，旧版只做定位提示。发行版可能回移植补丁，迁移时请直接看目标内核头文件。

6.x 基线

旧系统/脚本常写死 /sys/kernel/debug/tracing

影响：路径随发行版/挂载方式变化；脚本写死路径会“找不到 trace”。

边界：以 mount、/proc/mounts 与实际内核配置为准。

常见错误与排查

01

加了 pr_debug 但 dmesg 里看不到。

常见原因
pr_debug 默认不编译/不输出；dynamic debug 未开启，或日志级别被过滤。
排查 / 修复
确认 CONFIG_DYNAMIC_DEBUG；用 dynamic_debug/control 开启；临时用 pr_info 验证路径。
02

系统卡顿，日志刷屏。

常见原因
在热路径/中断中高频 printk；日志本身改变了时序。
排查 / 修复
使用动态调试/ratelimit；只在关键状态打印；把统计放到 debugfs/sysfs。
03

Oops 只看最后一行，找不到原因。

常见原因
没有看 RIP、Call Trace、寄存器与错误码；日志被后续输出覆盖。
排查 / 修复
保存完整 Oops；先看 RIP 附近与第一层 Call Trace；结合符号与反汇编；开启 KASAN/lockdep 复现。

TAKE IT WITH YOU

记住这三句话

  1. 01

    printk 看状态，dynamic debug 按需开启，ftrace 看轨迹，perf 看热点。

  2. 02

    Oops 先看 RIP 与 Call Trace；不要只盯最后一行日志。

  3. 03

    热路径/中断中少打印，必要时用 ratelimit、tracepoint 或统计接口。
