文件操作与 ioctl

把 open/read/write/release 串成一次完整调用，理解 copy_to_user/copy_from_user 的边界，以及 ioctl 命令号的编码规则。

file_operationscopy_to_usercopy_from_userioctl_IOR_IOW用户指针

学习目标

  • 解释用户缓冲区为什么不能在内核里直接解引用
  • 说清 _IO/_IOR/_IOW/_IOWR 与方向、长度、类型的关系
  • 能为一个 LED 设备设计最小的 read/write/ioctl 接口
ONE SENTENCE

文件操作是用户态与驱动之间的协议；ioctl 是同一套协议里专门传递设备控制命令的扩展通道。

生活化比喻

文件操作是窗口业务清单，ioctl 是特殊业务窗口

open 是取号，read/write 是递材料和取结果，release 是离场；ioctl 则像“调设备参数”的特殊窗口：普通窗口只收发字节，特殊窗口要按约定格式递一张参数表。

file_operations

特殊业务窗口
命令号
业务编号 + 参数表格式

为什么重要 / 用在哪里

  • 字符设备不只传字节，还要调亮度、设模式、读状态；ioctl 是最常见的控制接口。
  • ioctl 命令号不是随手写的数字，它要编码方向、类型、序号和参数大小，避免与其他驱动冲突。
  • 用户参数必须通过 copy_from_user/copy_to_user 访问；arg 本身是用户地址，不能直接解引用。
  • 32 位用户态跑在 64 位内核上时，参数布局可能不同，需要理解 compat_ioctl 的边界。

核心概念

file_operations

文件操作回调

open/read/write/release 是最小集合；ioctl、poll、mmap 按设备需要添加。回调签名由内核固定，不能自己改参数。

loff_t *ppos

偏移与 EOF

read/write 的 ppos 表示文件偏移。字符设备可以选择忽略它（每次从头读写），也可以像普通文件一样推进；要明确你的语义。

ioctl command encoding

ioctl 命令号

_IO/_IOR/_IOW/_IOWR 把方向、magic、序号和参数大小编码进一个整数。驱动和用户态应共享同一个头文件，避免手写魔法数。

unsigned long arg

用户参数

ioctl 的 arg 通常是一个用户地址或小整数。若它指向结构体，必须用 copy_from_user/copy_to_user；不要直接把 arg 转成内核指针。

0 / -errno

返回值约定

驱动 ioctl 成功返回 0，失败返回负 errno；用户态 ioctl 返回 -1 并设置 errno。未知命令通常返回 -ENOTTY。

compat_ioctl

兼容层

64 位内核可能运行 32 位用户程序，结构体布局/指针宽度不同。需要兼容时实现 compat_ioctl，或使用内核提供的 compat_ptr_ioctl 等辅助方式。

关键 API 与代码

代码是学习示意，以 Linux 6.x / ARM64 为默认基线。每个 API 都列出参数与返回值；不要只抄代码， 先确认它运行在什么上下文、失败时怎么回滚。

共享命令头文件：led_ioctl.h

API 逐个解释
_IOW / _IOR用户态与内核态共享头文件
#define LED_SET_BRIGHTNESS _IOW(LED_IOC_MAGIC, 1, struct led_config)

参数：magic：8 位类型标识；nr：命令序号；type：参数结构体类型

返回：编译期生成一个 ioctl 命令号；不是运行时函数。

注意：_IOW 表示用户态向驱动写参数，_IOR 表示从驱动读参数；方向要写对。

驱动侧：unlocked_ioctl 与用户参数

API 逐个解释
unlocked_ioctl进程上下文；unlocked 表示驱动自己负责并发保护
long (*unlocked_ioctl)(struct file *file, unsigned int cmd, unsigned long arg);

参数：file：打开的文件对象；cmd：ioctl 命令号；arg：用户地址或小整数

返回：成功返回 0；失败返回负 errno。用户态看到 -1 并设置 errno。

注意：不要直接解引用 arg；若 arg 指向结构体，用 copy_from_user/copy_to_user。

copy_from_user进程上下文
unsigned long copy_from_user(void *to, const void __user *from, unsigned long n);

参数：to：内核目标地址；from：用户源地址；n：字节数

返回：返回未复制的字节数；0 表示全部成功。

注意：失败通常返回 -EFAULT；不要用 memcpy 复制用户地址。

_IOC_TYPE内核/用户共享宏
_IOC_TYPE(cmd)

参数：cmd：ioctl 命令号

返回：取出命令中的类型/magic 字段。

注意：先校验 magic，可以快速过滤不属于本驱动的命令。

用户态：调用 ioctl

API 逐个解释
ioctl用户态
int ioctl(int fd, unsigned long request, ...);

参数：fd：设备描述符；request：命令号；第三个参数：通常是指向参数结构体的指针

返回：成功通常返回 0；失败返回 -1 并设置 errno。

注意：不要把内核的 unlocked_ioctl 返回值直接当用户态返回值；两者错误约定不同。

版本对照卡

6.x 是默认基线，旧版只做定位提示。发行版可能回移植补丁，迁移时请直接看目标内核头文件。

版本对照字符设备 / 控制命令

ioctl 回调与 BKL 时代

6.x 基线

现代 6.x 驱动实现 unlocked_ioctl，不再依赖大内核锁

旧版对照

更早的驱动可能实现 ioctl，并依赖历史上的大内核锁（BKL）语义

影响：unlocked 意味着并发保护由驱动自己负责；迁移旧代码时要重新检查锁与用户指针。

边界：这是历史背景说明；具体旧内核行为以对应版本源码为准。

版本对照调试接口 / procfs

procfs 的 proc_ops

6.x 基线

Linux 5.6+ 推荐 struct proc_ops

旧版对照

更早的内核常用 struct file_operations 注册 proc 文件

影响：字段名从 .read/.write 变为 .proc_read/.proc_write；混用会编译失败。

边界：procfs 适合小型调试信息，不应替代正式设备接口。

常见错误与排查

01

用户态 ioctl 返回 -1，errno 为 ENOTTY。

常见原因
命令号不匹配、magic 写错、驱动没有注册 unlocked_ioctl，或用户/内核头文件版本不一致。
排查 / 修复
用共享头文件生成命令；检查 _IOC_TYPE；用 strace -e ioctl 看实际命令号；确认 file_operations 注册。
02

ioctl 返回 EFAULT，或内核出现非法地址访问。

常见原因
把 arg 当内核指针直接解引用；用户态传入的地址不可读/不可写。
排查 / 修复
用 copy_from_user/copy_to_user；检查 arg 是否为 0；验证用户缓冲区长度与权限。
03

32 位程序在 64 位内核上 ioctl 行为异常。

常见原因
结构体布局/指针宽度不同，未提供 compat_ioctl 或兼容转换。
排查 / 修复
使用固定宽度字段；实现 compat_ioctl；或使用内核提供的 compat 辅助函数。
