SPI 驱动

SPI 是“主设备发时钟，从设备跟着移位”。掌握 spi_driver/spi_device、spi_transfer、模式与片选配置。

spi_driverspi_devicespi_transferCPOLCPHAspi-max-frequency

学习目标

  • 解释 CPOL/CPHA 与 SPI mode 0–3 的关系
  • 用 spi_sync/spi_write_then_read 完成一次寄存器读写
  • 在设备树中配置 reg、spi-max-frequency 与模式
ONE SENTENCE

SPI 由主设备发时钟、片选选中从设备，数据在 MOSI/MISO 上按位同时移位；驱动围绕 spi_device 与 spi_transfer 工作。

生活化比喻

SPI 像主设备摇铃、从设备跟着节拍传纸条

CS 是“点到你”，SCLK 是节拍，MOSI 是主设备发，MISO 是从设备回。CPOL 决定空闲时钟高低，CPHA 决定在第一个还是第二个边沿采样；两者组合成 mode 0–3。

为什么重要 / 用在哪里

  • 屏幕、Flash、传感器、ADC 常用 SPI；模式、片选、速率配错就会出现“有波形但数据全 0/全 FF”。
  • SPI 没有统一设备地址，靠片选选中设备；设备树 reg 常表示片选编号，不是 I2C 地址。
  • spi_transfer/spi_message 的返回值与缓冲生命周期需要正确理解，否则会读错数据。
  • SPI 传输可能睡眠，不能在硬中断上下文直接调用。

核心概念

spi_controller / spi_device

SPI 控制器与设备

控制器是主设备，spi_device 表示挂在某条 SPI 总线、某个片选上的从设备。驱动从 spi_device 获取 mode、速率、bits_per_word 等配置。

spi_driver

SPI 驱动

提供 probe/remove 与 of_match_table。注册后由 SPI 总线匹配 spi_device；probe 中通常设置 mode/速率并初始化设备。

spi_transfer / spi_message

传输结构

一个 spi_message 可以包含多个 spi_transfer；spi_sync 同步发送并等待完成。spi_write_then_read 是常用封装。

clock polarity / phase

CPOL / CPHA

CPOL 决定空闲时钟电平，CPHA 决定采样边沿。两者组合成 mode 0–3；主从必须一致。

CS / max_speed_hz

片选与速率

片选选中从设备；速率受从设备与走线限制。设备树常用 reg 表示片选号，spi-max-frequency 表示上限。

full-duplex shift

全双工移位

SPI 发送和接收同时进行；即使只想读，也常需要发送 dummy 字节来产生时钟。

关键 API 与代码

代码是学习示意，以 Linux 6.x / ARM64 为默认基线。每个 API 都列出参数与返回值；不要只抄代码， 先确认它运行在什么上下文、失败时怎么回滚。

spi_driver 骨架

API 逐个解释
spi_setup进程上下文
int spi_setup(struct spi_device *spi);

参数：spi：SPI 从设备

返回：成功返回 0；失败返回负 errno。

注意：在 probe 中设置好 mode/max_speed_hz/bits_per_word 后调用；失败不要继续传输。

spi_write_then_read进程上下文；可能睡眠
int spi_write_then_read(struct spi_device *spi, const void *txbuf, unsigned n_tx, void *rxbuf, unsigned n_rx);

参数：spi：从设备；txbuf/n_tx：发送缓冲与长度；rxbuf/n_rx：接收缓冲与长度

返回：成功返回 0；失败返回负 errno。

注意：常用于“先发命令再读数据”；不要在硬中断上下文调用。

spi_transfer / spi_message进程上下文
int spi_sync(struct spi_device *spi, struct spi_message *message);

参数：spi：从设备；message：包含一个或多个 spi_transfer

返回：成功返回 0；失败返回负 errno。

注意：传输缓冲在完成前必须保持有效；复杂时序可用多个 transfer 组合。

设备树：SPI 从设备与模式

API 逐个解释
reg（SPI）设备树属性
reg = <0>;

参数：片选编号（chip select index）

返回：无返回值；SPI 核心据此选择 CS。

注意：与 I2C 的 reg 含义不同；不要填从设备内部寄存器地址。

spi-max-frequency设备树属性
spi-max-frequency = <1000000>;

参数：最大时钟频率，单位 Hz

返回：无返回值；SPI 核心据此限制速率。

注意：实际速率还受控制器分频与走线影响；先降速验证，再逐步提高。

spi-cpol / spi-cpha设备树属性
spi-cpol; spi-cpha;

参数：无参数；作为布尔属性存在即生效

返回：无返回值。

注意：与 SPI_MODE_x 的对应关系要按绑定文档核对；主从模式必须一致。

版本对照卡

6.x 是默认基线，旧版只做定位提示。发行版可能回移植补丁，迁移时请直接看目标内核头文件。

版本对照设备树 / 驱动匹配

设备树匹配与 match data

6.x 基线

6.x：of_match_table 提供 compatible，驱动用 device_get_match_data 等 helper 取数据

旧版对照

旧代码常先 of_match_device() 再读取 match->data

影响：compatible 是设备树与驱动之间的字符串契约；改错一个字符就可能导致 probe 不执行。

边界：helper 的可用性与签名以目标内核头文件为准；不是所有平台都用设备树。

SPI 传输时序

切换 mode 0–3，观察 CPOL/CPHA 如何改变时钟空闲电平与采样边沿。片选、时钟、MOSI/MISO 必须与从设备手册一致。

可交互
SPI mode
CPOL=0（空闲低）CPHA=0（第一个边沿采样）传输：进行中

mode 0 与 mode 3 都在第二个边沿采样；区别是 CPOL 决定空闲时钟高低。主从必须使用同一个 mode。

1 / 8
步骤 1
拉低片选 CS

主设备拉低 CS，选中这条 SPI 总线上的从设备。CS 通常低有效。

观察问题：mode 0 和 mode 3 都在第二个边沿采样吗？CPOL 与 CPHA 分别控制什么？

结论提示：CPOL 控制空闲时钟电平，CPHA 控制采样边沿。mode 0/3 都在第二个边沿采样，但空闲电平不同；主从必须一致。

波形是教学示意，不按真实电气时序缩放；实际建立/保持时间、速率与片选以从设备手册和示波器为准。

常见错误与排查

01

SPI 有波形，但读回的数据全 0x00 或 0xFF。

常见原因
mode/CPOL/CPHA 不匹配、片选不对、速率过高、MOSI/MISO 接反，或命令字节错误。
排查 / 修复
先用逻辑分析仪看 CS/SCLK/MOSI/MISO；把速率降到 100 kHz；核对数据手册的 mode 与命令；确认片选编号。
02

probe 不执行或传输返回 -ENODEV。

常见原因
compatible 不匹配、SPI 控制器未启用、片选/reg 配置错误。
排查 / 修复
检查设备树与 of_match_table；确认 spi1 status；看 /sys/bus/spi/devices 与 dmesg。
03

在中断上下文调用 spi_sync 导致 BUG。

常见原因
SPI 传输可能睡眠，不能在硬中断/原子上下文调用。
排查 / 修复
把传输移到 workqueue 或 threaded IRQ；中断里只做调度。
