ONE SENTENCE

platform_driver 是 SoC 片上外设的常用驱动入口：总线按 name 或 compatible 匹配后，调用 probe 初始化设备。

生活化比喻

平台总线是招聘市场，device 是岗位，driver 是候选人

platform_device 描述“这里有一个片上外设”，platform_driver 提供“我能操作这类外设”。招聘市场（platform bus）按名字或 compatible 把双方配对，配对成功后候选人入职（probe），离职时交接（remove）。

为什么重要 / 用在哪里

  • SoC 内部的 GPIO 控制器、I2C 控制器、显示控制器、定时器等常以 platform 设备出现。
  • probe 是所有资源初始化的入口：寄存器映射、时钟、复位、中断、字符设备注册通常都在这里。
  • 资源获取失败、延迟 probe、remove 顺序错误，是板级驱动最常见的三类问题。
  • devm_* 能减少错误路径，但不能替代对生命周期和并发访问的思考。

核心概念

platform_device

platform_device

描述一个平台设备的资源：寄存器区间、中断、DMA、时钟等。它可以来自设备树、ACPI 或板级代码。

platform_driver

platform_driver

提供 probe/remove 与匹配表。注册后由 platform bus 负责匹配；匹配成功才调用 probe。

name / of_match_table / id_table

匹配方式

传统 platform 设备可按 name 匹配；设备树设备通过 compatible 与 of_match_table 匹配。匹配失败或延迟时 probe 不执行。

probe return

probe 的返回值

返回 0 表示成功；返回负 errno 表示失败。资源暂时未就绪时可返回 -EPROBE_DEFER，让内核稍后重试。

devm_*

devm 资源管理

devm 前缀的分配/映射/注册会绑定到 device 生命周期，probe 失败或 remove 时自动释放。它仍要求正确顺序与错误处理。

remove

remove 与卸载

remove 要停止新工作、注销对外接口、释放资源。不同 6.x 小版本的 remove 返回值存在演进，签名以目标头文件为准。

关键 API 与代码

代码是学习示意，以 Linux 6.x / ARM64 为默认基线。每个 API 都列出参数与返回值；不要只抄代码， 先确认它运行在什么上下文、失败时怎么回滚。

platform_driver 骨架

API 逐个解释
platform_get_resourceprobe/进程上下文
struct resource *platform_get_resource(struct platform_device *dev, unsigned int type, unsigned int num);

参数：dev：平台设备；type：IORESOURCE_MEM/IRQ 等；num：同类资源索引

返回：成功返回 resource 指针；失败返回 NULL。

注意：返回 NULL 不是 ERR_PTR；不要对它用 IS_ERR。

devm_ioremap_resourceprobe/进程上下文
void __iomem *devm_ioremap_resource(struct device *dev, const struct resource *res);

参数：dev：设备；res：IORESOURCE_MEM 资源

返回：成功返回映射地址；失败返回 ERR_PTR。

注意：使用 IS_ERR/PTR_ERR；映射随 device 生命周期自动释放，不要手动 iounmap 同一个地址。

platform_get_irqprobe/进程上下文
int platform_get_irq(struct platform_device *dev, unsigned int num);

参数：dev：平台设备；num：中断索引

返回：成功返回非负中断号；失败返回负 errno。

注意：0 是合法中断号，判断失败要用 irq < 0，不能写 if (!irq)。

probe 返回值platform bus 匹配后调用
int (*probe)(struct platform_device *pdev);

参数：pdev：匹配到的平台设备

返回：成功返回 0；失败返回负 errno；资源未就绪可返回 -EPROBE_DEFER。

注意：失败路径要按相反顺序清理已经完成的初始化。

常见错误与排查

01

驱动已加载，probe 没有执行。

常见原因
设备树 compatible 不匹配、platform_device 不存在、status disabled，或驱动注册失败。
排查 / 修复
检查 of_match_table 与 dts；看 /sys/bus/platform/devices 与 drivers；开启 dynamic debug 或加日志；确认 driver_register 成功。
02

probe 返回 -EPROBE_DEFER，设备一直不出现。

常见原因
依赖的时钟、稳压器、GPIO 控制器或总线尚未就绪。
排查 / 修复
确认依赖驱动已加载；检查设备树 phandle 与 provider；不要用无限延迟掩盖真实依赖错误。
03

remove 后系统崩溃，或资源被重复释放。

常见原因
remove/错误路径重复释放 devm 资源；中断/定时器仍在运行；注销顺序错误。
排查 / 修复
先停新工作（注销接口、停中断、删定时器），再让 devm 自动回收；不要手动释放 devm 管理的资源。
