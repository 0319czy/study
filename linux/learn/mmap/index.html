mmap 与内存映射

mmap 把设备内存或内核缓冲区映射进用户地址空间。理解 vm_area_struct、remap_pfn_range 与页对齐。

mmapvm_area_structremap_pfn_rangevma页对齐ioremap

学习目标

  • 说清 mmap 回调中 vma 代表什么
  • 用 remap_pfn_range 映射一段物理地址并处理长度/偏移
  • 识别缓存属性、权限与安全边界
ONE SENTENCE

mmap 把设备内存或内核缓冲区映射进用户虚拟地址空间，用户指针直接访问，不再经过每次 read/write 的拷贝。

生活化比喻

mmap 像把仓库的一扇门直接开在用户这边

read/write 是每次把货搬进搬出；mmap 则把页表指过去，让用户进程直接看到同一块内存。省掉拷贝，但同步、权限、缓存和生命周期都要驱动自己负责。

为什么重要 / 用在哪里

  • 摄像头、显示、采集卡等大块数据用 mmap 可以避免 read/write 的多次拷贝。
  • mmap 不是“自动共享内存”：页表、权限、缓存属性和生命周期都要驱动正确设置。
  • 映射错物理页、长度或偏移，可能让用户看到别的内存，甚至造成安全漏洞。
  • 映射后用户不再经过 read/write，驱动必须另外设计同步与通知机制。

核心概念

vm_area_struct / vma

虚拟内存区域

描述用户进程的一段虚拟地址范围、权限和偏移。mmap 回调收到 vma，负责把这段范围映射到设备/内核页。

vm_pgoff

页偏移

用户 mmap 的 offset 以页为单位放在 vm_pgoff。驱动通常要求 offset 页对齐，并把它换算成设备内的页偏移。

remap_pfn_range

remap_pfn_range

把一段物理页帧映射到用户 vma。适合已知 pfn 的设备/连续内存；pfn 必须来自正确的物理页。

dma_mmap_coherent

DMA 缓冲映射

把 dma_alloc_coherent 分配的缓冲映射给用户，处理 DMA 地址与 cache 属性。比手写 pfn 更安全，适合 DMA 场景。

cache attributes / vma flags

缓存与权限

映射的 cache 属性与权限必须与设备/内存类型匹配。用户可写映射要特别小心越界与信息泄露。

mmap lifetime

映射生命周期

映射建立后，用户可能长期持有指针。驱动卸载/释放缓冲前要确保没有映射仍在使用，通常需要引用计数或强制解除映射。

关键 API 与代码

代码是学习示意，以 Linux 6.x / ARM64 为默认基线。每个 API 都列出参数与返回值；不要只抄代码， 先确认它运行在什么上下文、失败时怎么回滚。

DMA 缓冲映射：dma_mmap_coherent

API 逐个解释
file_operations.mmap进程上下文
int (*mmap)(struct file *file, struct vm_area_struct *vma);

参数：file：打开的文件；vma：用户虚拟地址区域

返回：成功返回 0；失败返回负 errno。

注意：不要在 mmap 回调里睡眠太久；映射成功后用户访问不再经过 read/write。

dma_mmap_coherent进程上下文
int dma_mmap_coherent(struct device *dev, struct vm_area_struct *vma, void *cpu_addr, dma_addr_t dma_addr, size_t size);

参数：dev：设备；vma：用户区域；cpu_addr：CPU 指针；dma_addr：DMA 地址；size：映射大小

返回：成功返回 0；失败返回负 errno。

注意：适用于 dma_alloc_coherent 分配的缓冲；不要映射已经释放的缓冲。

通用页帧映射：remap_pfn_range

API 逐个解释
remap_pfn_range进程上下文
int remap_pfn_range(struct vm_area_struct *vma, unsigned long addr, unsigned long pfn, unsigned long size, pgprot_t prot);

参数：vma：用户区域；addr：用户起始地址；pfn：物理页帧号；size：字节数；prot：页保护/缓存属性

返回：成功返回 0；失败返回负 errno。

注意：pfn 不是虚拟地址；virt_to_phys 只适用于可直接映射的内核地址，设备 MMIO 要另行处理。

vm_pgoffmmap 回调
unsigned long vm_pgoff;

参数：用户 mmap offset >> PAGE_SHIFT

返回：无返回值；作为 vma 字段读取。

注意：不要把它当成字节偏移；需要按页换算。

步骤 1
用户调用 mmap

用户态请求把设备缓冲映射到自己的虚拟地址空间，指定长度与 offset。

观察问题：remap_pfn_range 映射成功后，用户写入还会经过驱动的 write 回调吗？

结论提示：不会。mmap 建立直接页映射，用户访问绕过 read/write；驱动必须自行设计同步、权限与生命周期。

pfn、偏移与长度为教学示意；真实映射要考虑页对齐、cache 属性、IOMMU 与安全边界。

常见错误与排查

01

用户 mmap 成功，但访问时 SIGBUS 或读到错误数据。

常见原因
映射长度超范围、pfn 错误、缓冲未分配/已释放，或 offset 换算错误。
排查 / 修复
检查 vma 长度、vm_pgoff、缓冲生命周期与 pfn 来源；用 /proc/self/maps 与 strace 验证。
02

用户看到旧数据或设备读到未刷新数据。

常见原因
cache 属性不匹配，或映射后没有同步协议。
排查 / 修复
使用 dma_mmap_coherent 或正确的 vma flags；定义 CPU/设备之间的同步与所有权规则。
03

卸载驱动后用户仍访问映射，系统崩溃。

常见原因
映射生命周期长于驱动/缓冲；卸载时没有处理仍存在的 vma。
排查 / 修复
用引用计数/打开计数阻止卸载；必要时主动解除映射；不要释放仍被映射的缓冲。
