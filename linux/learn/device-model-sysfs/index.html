设备模型与 sysfs

bus/device/driver 构成内核设备模型，kobject 与 attribute 把状态暴露到 /sys。理解 uevent 与“公告栏”的边界。

busdevicedriverkobjectattributeueventsysfs

学习目标

  • 画出 bus、device、driver 的匹配关系
  • 用 DEVICE_ATTR_RW 与 sysfs_emit 暴露一个只读/可写属性
  • 解释 sysfs 属性为什么不适合传大块数据
ONE SENTENCE

设备模型用 bus/device/driver 描述“谁和谁匹配”，sysfs 把这些内核对象映射成 /sys 下的目录与文本属性。

生活化比喻

bus 是招聘市场，device 是岗位，driver 是候选人

岗位挂在招聘市场（bus）上，候选人（driver）带着技能表来匹配；匹配成功后 probe 就是入职。sysfs 像公司公告栏：把设备、驱动、状态和可调参数挂出来，但公告栏只适合短文本，不适合搬大箱子。

为什么重要 / 用在哪里

  • 设备模型决定了 probe 何时被调用，也决定了 /sys 下为什么会出现某个目录。
  • sysfs 是最常见的调试与控制入口：看状态、调参数、触发测试，但接口设计必须小而安全。
  • kobject 的引用计数与 release 是设备生命周期的基础，写错会 use-after-free。
  • uevent 与 udev 串起了“设备出现”和“/dev 节点出现”，但两者不是同一步。

核心概念

bus / device / driver

总线、设备与驱动

bus 负责匹配；device 描述硬件实例；driver 提供操作函数。匹配成功后 bus 调用 driver 的 probe，失败则可能进入 deferred probe。

kobject

内核对象

设备模型的基础对象，提供引用计数、sysfs 表示与 uevent。驱动通常通过 device/driver 间接使用，不直接裸操作 kobject。

attribute

sysfs 属性

用 DEVICE_ATTR_RW 等宏定义 show/store 回调，再通过 device_create_file 挂到设备上。属性通常是短文本，读写应快速、可重入。

show

show 回调

把内核状态格式化成文本写入 buf。缓冲区通常只有一页，推荐 sysfs_emit；返回写入长度，失败返回负 errno。

store

store 回调

解析用户写入的文本并更新状态。成功返回 count（处理的字节数），失败返回负 errno；不要返回 0 表示成功。

uevent / udev

uevent 与 udev

内核通过 uevent 通知用户态设备变化；udev 根据规则创建 /dev 节点、设置权限。sysfs 目录出现不等于 /dev 节点一定已创建。

关键 API 与代码

代码是学习示意，以 Linux 6.x / ARM64 为默认基线。每个 API 都列出参数与返回值；不要只抄代码， 先确认它运行在什么上下文、失败时怎么回滚。

一个 brightness 属性：show / store

API 逐个解释
DEVICE_ATTR_RW编译期定义
static DEVICE_ATTR_RW(brightness);

参数：brightness：属性名，生成 dev_attr_brightness 与 show/store 入口

返回：宏展开为 struct device_attribute；无运行时返回值。

注意：要求存在 brightness_show / brightness_store 两个函数；权限通常由宏决定为 0644。

sysfs_emitshow 回调；Linux 5.10+ 推荐
int sysfs_emit(char *buf, const char *fmt, ...);

参数：buf：sysfs 提供的缓冲区；fmt...：格式串与参数

返回：返回写入的字符数；失败返回负 errno。

注意：sysfs 缓冲区通常只有一页；不要用 sprintf 写无界内容。

kstrtointstore 回调
int kstrtoint(const char *s, unsigned int base, int *res);

参数：s：输入字符串；base：进制，0 表示自动识别；res：解析结果

返回：成功返回 0；解析失败返回负 errno。

注意：解析后仍要做业务范围校验；不要把解析成功当成参数合法。

device_create_fileprobe/初始化路径
int device_create_file(struct device *dev, const struct device_attribute *attr);

参数：dev：设备；attr：属性

返回：成功返回 0；失败返回负 errno。

注意：失败时 probe 要回滚；remove 中对应 device_remove_file。

观察问题：为什么 store 成功时要返回 count，而不是 0？sysfs 为什么不适合传输几十 MB 数据？

结论提示：store 返回 count 才表示本次写入被完整处理；sysfs 属性通常只有一页缓冲区，适合小型状态/配置，不适合大块数据。

示例路径 /sys/class/led_demo/brightness 为教学假设；真实路径取决于设备类、设备层级与驱动注册方式。

常见错误与排查

01

/sys 下找不到属性文件。

常见原因
属性没有 device_create_file；DEVICE_ATTR 名称与引用不一致；probe 失败提前返回。
排查 / 修复
检查 device_create_file 返回值；确认属性名；查看 /sys/devices/... 与 dmesg；注意平台设备与 class device 的路径不同。
02

echo 写入成功但值没变，或 write 返回 0。

常见原因
store 成功时没有返回 count；解析后没有更新状态；范围校验直接失败但错误码不明确。
排查 / 修复
成功 return count；失败 return 负 errno；用 kstrtoint 并检查范围；用 cat 验证 show。
03

卸载设备后访问属性导致崩溃。

常见原因
remove 时先释放私有数据，再移除 sysfs 属性；或属性回调仍在并发执行。
排查 / 修复
先阻止新访问（注销/下线），再 device_remove_file，最后释放数据；必要时加锁与引用计数。
