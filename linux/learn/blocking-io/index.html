阻塞与非阻塞 IO

等待队列让进程“取号睡觉”，poll/select 让一个线程看多个 fd。理解 O_NONBLOCK、唤醒与异步通知。

等待队列wait_event_interruptiblepollselectO_NONBLOCKfasync

学习目标

  • 用 wait_event_interruptible 实现阻塞读
  • 写出 poll 回调并正确设置 POLLIN/POLLOUT
  • 解释“唤醒丢失”与“惊群”的常见来源
ONE SENTENCE

阻塞 IO 在数据没准备好时让进程睡眠，非阻塞 IO 立即返回 -EAGAIN；等待队列与 poll 负责“睡下”和“叫醒”。

生活化比喻

阻塞读是取号排队，poll 是同时盯多个窗口

没有号时，阻塞读让进程去休息区睡下，等叫号；非阻塞读则问一句“现在能办吗”，不能办就立刻走。poll/select 像一个前台同时盯多个窗口，哪个窗口有结果就通知你。

为什么重要 / 用在哪里

  • 字符设备、串口、传感器没有数据时，不能忙等烧 CPU；等待队列是标准做法。
  • 一个线程管理多个设备时，poll/select 比“每个 fd 一个线程”更轻量。
  • 阻塞/非阻塞语义、唤醒条件和返回码，直接决定用户态程序会不会卡死。
  • 丢失唤醒、惊群、持锁睡眠是并发 IO 中非常隐蔽的 bug。

核心概念

wait queue

等待队列

进程在条件不满足时加入等待队列并睡眠；条件满足时由中断/其他线程调用 wake_up 唤醒。

wait condition

等待条件

wait_event_interruptible 会在条件为假时睡眠，并在唤醒后重新检查。条件必须是可安全读取的共享状态，通常需要锁保护。

blocking / O_NONBLOCK

阻塞与非阻塞

阻塞模式让进程睡眠直到就绪；非阻塞模式立即返回 -EAGAIN。驱动必须同时支持两种语义，不能只实现一种。

poll / select

poll / select

用户态等待多个 fd 的就绪事件；驱动 poll 回调注册等待队列并返回当前就绪掩码。

lost wakeup

唤醒丢失

唤醒发生在进程真正睡下之前，导致它错过事件。正确做法是在循环中检查条件，并在锁保护下完成“检查—睡眠”的衔接。

fasync / SIGIO

异步通知

设备就绪时向用户进程发送信号，而不是让进程阻塞等待。适合事件驱动模型，但信号语义与并发处理更复杂。

阻塞读与中断唤醒

API 逐个解释
wait_event_interruptible进程上下文；会睡眠
int wait_event_interruptible(wait_queue_head_t wq, condition);

参数：wq：等待队列头；condition：就绪条件表达式

返回：条件满足返回 0；被信号打断返回 -ERESTARTSYS。

注意：不能在原子上下文调用；条件应在唤醒后重新求值。

wake_up_interruptible中断/进程上下文均可
void wake_up_interruptible(wait_queue_head_t *wq);

参数：wq：等待队列头

返回：无返回值。

注意：唤醒后进程会重新检查条件；不要在未改变条件时虚假唤醒。

poll 回调：注册等待并报告就绪

API 逐个解释
poll_waitpoll 回调，不能睡眠
void poll_wait(struct file *filp, wait_queue_head_t *wait_address, poll_table *p);

参数：filp：文件对象；wait_address：等待队列头；p：内核传入的 poll_table

返回：无返回值。

注意：忘记 poll_wait 会导致事件变化时用户态永远不被唤醒。

__poll_t / EPOLLINpoll 回调
__poll_t mask = EPOLLIN | EPOLLRDNORM;

参数：EPOLLIN：可读；EPOLLOUT：可写；其他事件按需

返回：返回当前就绪事件掩码。

注意：内核侧用 __poll_t/EPOLL*，用户态 pollfd 用 POLLIN 等；不要混用类型。

版本对照阻塞 IO / poll

poll 回调与 __poll_t

6.x 基线

6.x：poll 回调返回 __poll_t，使用 EPOLLIN/EPOLLOUT 等掩码

旧版对照

旧代码可能使用 POLLIN/POLLOUT 或 unsigned int 返回

影响：返回掩码要与用户态 poll/select 的事件对应；忘记 poll_wait 会导致永远不就绪。

边界：具体类型/宏以目标内核头文件为准；不要混用用户态 pollfd 与内核 poll_table。

常见错误与排查

01

用户态 read 永久卡住，中断来了也不醒。

常见原因
没有正确 wake_up、等待队列不是同一个、条件没有更新，或 poll_wait 缺失。
排查 / 修复
确认等待队列头唯一；在改变条件后唤醒；用 /proc 或日志确认中断确实到达；检查 poll 回调。
02

非阻塞 read 返回 0 而不是 -EAGAIN，用户态误判 EOF。

常见原因
驱动没有检查 O_NONBLOCK，或把“暂无数据”当成 EOF。
排查 / 修复
无数据且非阻塞时返回 -EAGAIN；只有真正结束时才返回 0。
03

高并发下偶发丢事件/惊群。

常见原因
检查条件与睡眠之间没有锁保护；wake_up 唤醒所有等待者；条件被多个消费者竞争。
排查 / 修复
用锁保护“检查—入队”；根据语义选择 wake_up_interruptible 或 wake_up_interruptible_all，并让消费者在唤醒后重新检查。
