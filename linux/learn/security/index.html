安全与稳定性

内核里的一个空指针就是整机重启。围绕越界、竞态、引用计数、内存泄漏与卸载安全建立防线。

空指针越界竞态引用计数内存泄漏卸载安全

学习目标

  • 识别用户输入、长度与整数溢出三类高风险点
  • 用引用计数与锁保护对象生命周期
  • 设计可回滚的 probe 失败路径与安全的 remove
ONE SENTENCE

内核安全的第一原则是：不信任用户输入，不泄漏内核内存，不在对象仍被引用时释放它。

生活化比喻

驱动像银行柜台：先验身份，再办业务，最后核对账目

用户参数是客户递进来的材料，必须验证；共享对象像账户，要有引用计数；卸载像关店，必须确认没有客户还在办理业务。任何一步省掉，都可能变成越界、UAF 或竞态。

为什么重要 / 用在哪里

  • 内核漏洞往往不是“复杂算法错”，而是长度、边界、生命周期和并发这类基础问题。
  • 驱动直接接触用户输入与硬件，攻击面比普通应用更大。
  • 一个 UAF 或越界写可能让整机崩溃，甚至被利用提权。
  • “测试时没崩”不能证明安全；需要代码审查、KASAN/KCSAN、lockdep 与压力测试。

核心概念

untrusted input

用户输入边界

ioctl 参数、sysfs 文本、read/write 长度都不可信。先校验长度、范围、空指针与溢出，再使用。

integer overflow

整数溢出

长度相乘/相加可能溢出，导致分配变小而拷贝变大。使用 check_mul_overflow/check_add_overflow 或明确的边界检查。

reference counting

引用计数

对象被多个执行流/文件持有时，用 kref/refcount 管理生命周期；最后一个引用释放时才销毁。

use-after-free

UAF

对象释放后仍被访问。常见于并发释放、卸载未等待、回调仍挂起。KASAN 能帮助发现。

information leak

信息泄漏

把未初始化的内核内存拷贝给用户，可能泄漏地址/密钥。拷贝前初始化或只拷贝有效字段。

safe unload

卸载安全

卸载前停止新访问、注销接口、等待进行中的操作、释放资源；顺序错误会留下悬空指针。

关键 API 与代码

代码是学习示意，以 Linux 6.x / ARM64 为默认基线。每个 API 都列出参数与返回值；不要只抄代码， 先确认它运行在什么上下文、失败时怎么回滚。

引用计数：最后一个引用才释放

API 逐个解释
kref_get进程/中断上下文；需确保对象仍然有效
void kref_get(struct kref *kref);

参数：kref：引用计数对象

返回：无返回值。

注意：不能在对象已经释放后再 get；获取路径必须有锁或已有引用保护。

kref_put进程/中断上下文；release 的上下文取决于调用者
int kref_put(struct kref *kref, void (*release)(struct kref *kref));

参数：kref：引用计数对象；release：最后一个引用时的释放回调

返回：返回 1 表示本次调用触发了 release；否则 0。

注意：release 回调不能睡眠，除非能保证在进程上下文；不要把复杂清理放在可能的中断上下文。

版本对照安全 / 用户拷贝

hardened usercopy 与越界检查

6.x 基线

6.x 可能启用 hardened usercopy，对用户拷贝范围做额外检查

旧版对照

旧内核/配置的检查较弱，越界拷贝可能更隐蔽

影响：即使有检查，驱动仍必须自己验证长度、对象边界与生命周期；不能依赖“内核会拦住”。

边界：是否启用取决于内核配置与发行版；不要把安全寄托在单一检查上。

常见错误与排查

01

用户传入超大长度后内核崩溃或内存被破坏。

常见原因
长度未校验、整数溢出、分配大小与拷贝长度不一致。
排查 / 修复
使用 check_*_overflow；限制最大长度；copy_*_user 使用实际分配大小；失败返回 -EINVAL/-EFAULT。
02

卸载模块后仍收到回调/中断，系统崩溃。

常见原因
卸载前没有停中断/取消工作/等待引用归零；对象释放后回调仍运行。
排查 / 修复
先注销接口、停硬件、free_irq/cancel_work_sync，再释放对象；用引用计数阻止过早释放。
03

copy_to_user 把未初始化字节返回给用户。

常见原因
结构体有 padding 或未初始化字段，直接整体拷贝。
排查 / 修复
拷贝前 memset 或只拷贝有效字段；检查结构体布局与 padding。

TAKE IT WITH YOU

记住这三句话

  1. 01

    用户输入不可信：长度、范围、溢出、空指针都要校验。

  2. 02

    对象生命周期用引用计数与锁保护；卸载前停止新访问并等待回调结束。

  3. 03

    不要向用户泄漏未初始化内核内存；KASAN/KCSAN/lockdep 是辅助证据。
