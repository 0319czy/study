DMA

DMA 是“搬用工”，让外设与内存直接搬数据。理解一致性/流式映射、scatter-gather 与中断完成的配合。

DMAdma_alloc_coherentdma_map_singlescatter-gatherIOMMUcache

学习目标

  • 区分 dma_alloc_coherent 与 dma_map_single 的使用场景
  • 解释 cache 一致性、DMA 地址与 CPU 虚拟地址的差异
  • 画出“准备缓冲 → 启动 DMA → 中断 → 回收”的闭环
ONE SENTENCE

DMA 让外设与内存直接搬运数据，CPU 只负责准备缓冲、启动传输和处理完成通知。

生活化比喻

DMA 是搬用工，CPU 只需要交代地址和数量

CPU 不再一箱一箱自己搬，而是告诉搬用工“从设备搬到内存这个地址，长度多少”；搬完后用中断通知 CPU。代价是地址转换、cache 一致性和完成顺序都要由驱动负责。

为什么重要 / 用在哪里

  • 高速采集、串口、网络、存储都依赖 DMA；不会 DMA 映射，吞吐上不去或数据直接错。
  • CPU 地址与设备 DMA 地址不是一回事；IOMMU、缓存与地址宽度会让“看起来对”的代码失败。
  • 一致性与流式映射的生命周期不同；用错会导致 cache 不一致、泄漏或 use-after-free。
  • DMA 完成通常靠中断；上半部/下半部的分工在这里同样关键。

核心概念

dma_addr_t

DMA 地址

设备能访问的地址，不一定等于 CPU 的虚拟地址或物理地址。通过 DMA API 获取，不要自己把指针强转后塞给设备。

coherent DMA

一致性映射

dma_alloc_coherent 分配一块 CPU 与设备都能一致访问的缓冲，适合长期存在、频繁双向访问的环形队列/描述符。

streaming DMA

流式映射

dma_map_single/dma_map_sg 把已有缓冲临时映射给设备；传输前后要按方向做 sync/unmap，适合一次性或分片传输。

DMA_TO_DEVICE / DMA_FROM_DEVICE

方向

方向影响 cache 维护与同步。写错方向可能导致 CPU 读到旧数据或设备读到未刷新的数据。

scatter-gather DMA

scatter-gather

用描述符表把多个不连续缓冲串成一次 DMA，减少拷贝。网卡、存储控制器常用；需要正确映射每个片段。

I/O Memory Management Unit

IOMMU

为设备提供地址转换与隔离。DMA API 会考虑 IOMMU；直接使用物理地址可能绕过转换而失败。

一致性 DMA 缓冲

API 逐个解释
dma_alloc_coherent进程上下文；可能睡眠
void *dma_alloc_coherent(struct device *dev, size_t size, dma_addr_t *dma_handle, gfp_t flag);

参数：dev：设备；size：字节数；dma_handle：输出 DMA 地址；flag：GFP_KERNEL 等

返回：成功返回 CPU 可访问的指针，并写入 DMA 地址；失败返回 NULL。

注意：释放用 dma_free_coherent(dev, size, cpu_addr, dma_handle)，四个参数都要对应。

dma_free_coherent进程上下文
void dma_free_coherent(struct device *dev, size_t size, void *cpu_addr, dma_addr_t dma_handle);

参数：dev：设备；size：分配大小；cpu_addr：CPU 指针；dma_handle：DMA 地址

返回：无返回值。

注意：不能在设备仍可能 DMA 写入时释放；先停止 DMA 并确认完成。

流式 DMA：映射、同步、解除

API 逐个解释
dma_map_single通常进程上下文
dma_addr_t dma_map_single(struct device *dev, void *ptr, size_t size, enum dma_data_direction dir);

参数：dev：设备；ptr：CPU 缓冲地址；size：字节数；dir：DMA_TO_DEVICE/DMA_FROM_DEVICE 等

返回：成功返回 DMA 地址；失败返回错误值，需用 dma_mapping_error 判断。

注意：方向必须与真实数据流一致；映射后 CPU 不应随意改缓冲，直到 sync/unmap。

dma_mapping_errormap 之后立即检查
int dma_mapping_error(struct device *dev, dma_addr_t dma_addr);

参数：dev：设备；dma_addr：map 返回的地址

返回：映射失败返回非 0；成功返回 0。

注意：不要直接判断地址是否为 NULL；不同架构的错误表示可能不同。

dma_sync_single_for_cpuDMA 完成后、CPU 读取前
void dma_sync_single_for_cpu(struct device *dev, dma_addr_t addr, size_t size, enum dma_data_direction dir);

参数：dev：设备；addr：DMA 地址；size：长度；dir：方向

返回：无返回值。

注意：用于流式映射的 cache 同步；一致性映射通常不需要这一步。

版本对照卡

6.x 是默认基线，旧版只做定位提示。发行版可能回移植补丁，迁移时请直接看目标内核头文件。

版本对照DMA / 内存

通用 DMA API 与总线专用 API

6.x 基线

现代驱动优先使用通用 dma_* API（dma_alloc_coherent/dma_map_single）

旧版对照

旧代码可能使用 pci_* 或架构专用 DMA 映射 helper

影响：通用 API 处理 IOMMU/地址转换/一致性；直接使用物理地址容易在 IOMMU 或高地址场景出错。

边界：一致性与流式映射的选择取决于缓冲生命周期和设备能力；具体以 DMA-API 文档为准。

步骤 1
准备缓冲

驱动分配/准备内存缓冲；缓冲区在 DMA 完成前不能被释放或随意改写。

观察问题：DMA 完成后，CPU 能立刻安全读取缓冲区吗？一致性映射和流式映射分别需要做什么？

结论提示：一致性映射由 DMA API 保证一致性；流式映射需要按方向 sync，并在使用后 unmap。释放前必须确认设备不再写。

地址、长度与中断为教学示意；真实 DMA 还要考虑 IOMMU、cache、地址宽度与设备能力。

常见错误与排查

01

DMA 读回的数据偶尔是旧值或全 0。

常见原因
方向写错、缺少 sync、缓冲被 CPU 提前改写，或设备实际没有完成就被读取。
排查 / 修复
确认 DMA_FROM_DEVICE/TO_DEVICE；完成中断后再 sync_for_cpu；用示波器/逻辑分析仪确认传输完成。
02

系统偶发崩溃，地址与已释放缓冲有关。

常见原因
设备仍在 DMA 写入时释放缓冲，或 unmap 后继续把地址交给设备。
排查 / 修复
先停止 DMA、等待完成/取消，再 unmap 与释放；使用完成量/中断确认闭环。
03

在小内存板子上正常，在大内存/IOMMU 平台失败。

常见原因
直接使用物理地址或假设地址宽度；没有通过 DMA API 做 IOMMU 转换。
排查 / 修复
一律使用 dma_* API；检查 dma_mask/coherent mask；不要自己把 virt_to_phys 结果塞给设备。

记住这三句话

  1. 01

    CPU 虚拟地址不等于 DMA 地址；映射与释放必须成对。

  2. 02

    一致性映射适合长期缓冲；流式映射适合临时传输，注意方向、sync 与 unmap。

  3. 03

    DMA 完成通常靠中断；释放缓冲前必须确认设备不会再写。
