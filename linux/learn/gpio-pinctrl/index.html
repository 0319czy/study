ONE SENTENCE

GPIO 是“通用开关”，pinctrl 决定引脚到底做 GPIO 还是复用成 I2C/SPI；新驱动优先使用 gpiod 描述符 API。

生活化比喻

GPIO 是通用插座，pinctrl 是配电箱的接线方式

一个引脚可以当普通开关、I2C 时钟、SPI 片选，不能同时全占。pinctrl 决定“这个引脚这组配置下接到哪个功能”，GPIO 只负责读电平或输出高低。设备树负责说明插座怎么接。

为什么重要 / 用在哪里

  • LED、按键、复位、片选、电源使能都常用 GPIO；用错 API 或极性会表现为“代码跑了但硬件没反应”。
  • pinctrl 复用是板级驱动高频坑：引脚没切到正确功能，GPIO/I2C/SPI 都不会工作。
  • gpiod 描述符 API 带设备树绑定和极性语义，比旧整数 GPIO 更安全、更可移植。
  • GPIO 中断与 GPIO 输出要区分上下文；某些 GPIO 控制器操作可能睡眠。

核心概念

gpio_desc

GPIO 描述符

gpiod 用描述符表示一个 GPIO，而不是全局整数编号。描述符绑定 device 与设备树属性，能携带方向、极性和归属信息。

gpiod_get / gpiod_put

获取与释放

devm_gpiod_get 获取并绑定 device 生命周期；非 devm 版本需要 gpiod_put。获取时通常指定初始方向，例如 GPIOD_OUT_LOW。

gpiod_direction_output / gpiod_set_value

方向与电平

先确定输入/输出，再读写电平。gpiod_set_value 受 active-low 语义影响；某些慢速 GPIO 控制器需要用 cansleep 变体。

GPIO_ACTIVE_LOW / GPIO_ACTIVE_HIGH

极性

active-low 表示物理低电平代表逻辑 1。设备树或 machine data 描述极性，驱动按逻辑值操作，不要自己再取反一次。

pinmux / pinctrl state

pinctrl 复用

一个物理引脚可能复用为 GPIO、I2C、SPI、PWM 等。pinctrl 的 default/sleep 状态决定不同电源状态下引脚配置。

gpiod_to_irq

GPIO 中断

把 GPIO 描述符转成中断号，再 request_irq/request_threaded_irq。触发方式通常来自设备树；不要在中断里做可能睡眠的 GPIO 总线访问。

关键 API 与代码

代码是学习示意，以 Linux 6.x / ARM64 为默认基线。每个 API 都列出参数与返回值；不要只抄代码， 先确认它运行在什么上下文、失败时怎么回滚。

gpiod：获取 LED 并输出

API 逐个解释
devm_gpiod_getprobe/进程上下文
struct gpio_desc *devm_gpiod_get(struct device *dev, const char *con_id, enum gpiod_flags flags);

参数：dev：设备；con_id：属性前缀，例如 "led" 对应 led-gpios；flags：GPIOD_IN/GPIOD_OUT_LOW 等

返回：成功返回 gpio_desc 指针；失败返回 ERR_PTR。

注意：用 IS_ERR/PTR_ERR；devm 版本随 device 生命周期释放，通常不需要 gpiod_put。

gpiod_set_value任何上下文（但慢速控制器可能需 cansleep 变体）
void gpiod_set_value(struct gpio_desc *desc, int value);

参数：desc：GPIO 描述符；value：逻辑值 0/1

返回：无返回值。

注意：不要自己处理 active-low；描述符已经携带极性语义。

gpiod_to_irqprobe/进程上下文
int gpiod_to_irq(const struct gpio_desc *desc);

参数：desc：GPIO 描述符

返回：成功返回中断号；失败返回负 errno。

注意：得到中断号后仍需 request_irq/request_threaded_irq，并处理共享与触发方式。

设备树：GPIO 与 pinctrl 绑定（简化）

API 逐个解释
led-gpios设备树属性
led-gpios = <&gpio1 12 GPIO_ACTIVE_LOW>;

参数：gpio1：GPIO 控制器 phandle；12：控制器内偏移；GPIO_ACTIVE_LOW：极性

返回：无返回值；由 gpiod 消费。

注意：con_id "led" 对应属性前缀 led-gpios；名字不一致会获取失败。

pinctrl-0设备树属性
pinctrl-names = "default"; pinctrl-0 = <&led_pins>;

参数：led_pins：pinctrl 状态节点 phandle

返回：无返回值；设备 probe 时应用默认引脚状态。

注意：pins/function 的取值必须查 SoC pinctrl 绑定，不能照抄别的芯片。

常见错误与排查

01

devm_gpiod_get 返回 -ENOENT 或 GPIO 不受控。

常见原因
设备树属性名与 con_id 不匹配；GPIO 控制器未就绪；pinctrl 没切到 GPIO 功能。
排查 / 修复
检查 led-gpios 与前缀；确认 gpio 控制器 phandle；查 pinctrl 状态与 SoC 手册。
02

LED 亮灭逻辑反了。

常见原因
硬件是 active-low，但驱动又手动取反；或设备树漏了 GPIO_ACTIVE_LOW。
排查 / 修复
在设备树/描述符层描述极性，驱动只用逻辑值；不要双重取反。
03

旧 gpio_request 代码在新内核编译失败或运行异常。

常见原因
旧整数 GPIO API 在部分内核配置下不可用；或编号空间与设备树不一致。
排查 / 修复
迁移到 gpiod 描述符 API；用 devm_gpiod_get；重新核对设备树与极性。
