## 2. 已定方向(用户的决策,不要推翻)

1. 保留六站内容与深色视觉,新增适合长阅读的浅色主题。
2. 以**项目贯穿**;第一条完整路线 = **多传感器采集与监控系统**:
   传感器 → STM32 HAL → FreeRTOS → 串口 → Linux 网关 → 数据存储 → 网页仪表盘。
3. 课程顺序:工程基础 → MCU 与外设 → RTOS → 嵌入式 Linux → 驱动与硬件协同 → 联网与交付 → 方向进阶。
   优先补齐 **C 与工程工具、数字电路基础、Linux 用户态应用**;Linux 驱动课排在用户态之后;模电按项目穿插。
4. 一级导航:**学习工作台｜学习路线｜知识库｜实验室｜项目实战｜工具与资料**;
   六学科保留在"知识库";首页按"新用户/已开始学习"两种状态。
5. 每节课统一结构:**目标 → 前置知识 → 原理与图示 → 操作实验 → 结果检查 → 故障排查 → 小测 → 下一步**;
   优先建设三项服务:**环境准备、排障(现象-检查步骤-预期结果-下一分支)、学习档案**(阅读/测验/实验/项目成果分别记录,"打开页面不算掌握")。
6. 代码与实验加**证据标识**:原理示意 / 已编译验证 / 已在指定硬件验证,并注明适用版本;课程优先对照官方资料(STM32、Buildroot 等)。
7. 技术路线渐进整合:先统一导航/跨站搜索/课程标识/总路线;再统一进度/收藏/错题/主题并迁移旧记录;内容与实验逐步共用组件;**不一次性重写六站**。
8. 核心课程游客可学;跨设备同步成熟后再提供可选账号;内容继续静态;账号/同步/提交按需加轻量后端。
9. 四批建设,第一批导航/总路线/搜索;第二批打通采集监控项目;第三批统一学习档案;第四批方向进阶(ROS/PCB/边缘 AI)。
10. 第一阶段暂缓:论坛、商城、付费课程、证书、远程硬件实验室、大型在线编译平台。

1. **不要重写六站**;不要改动现有路由语义与学习记录键(迁移只能在统一档案层做)。

4. 每次改子站产物后必须重跑 `node scripts/finalize.mjs`(否则深链恢复脚本丢失)。
5. 内容/实验以**可复现**为准:证据标识必须真实(原理示意 ≠ 已验证);写明适用版本。

7. 深色 + 浅色双主题都要过对比度检查;主要版面优先课程/代码/图示/实验。
