CASE STUDIES / 四个实战案例

实战案例

把流程串起来：先定义任务和标签，再谈预处理、算法、指标与泄漏风险。四个案例都是本地教学模拟，不对接真实数据集或后端服务。

学习目标

能说清每个案例「输入什么、输出什么、怎么衡量好坏」。

能指出至少一处目标泄漏或评估泄漏，并解释它为什么让分数虚高。

能手算或读出一个指标，并说清它在这个任务里代表什么代价。

回归

房价预测

House Price Prediction

给一套房子的若干可观测特征，估计一个连续的价格数值。输出是数而不是类别，所以这是回归任务，评价方式也随任务改变。

输入特征

  • 面积（平方米，连续数值）
  • 房龄（年，连续数值）
  • 卧室数（小整数）
  • 到市中心的通勤时间（分钟）
  • 学区评分（1–10，仅作讨论用指标）

目标 / 标签

成交价（连续数值）。本页只讨论单位、量纲与误差，不映射任何真实货币行情。

数据来源说明

讨论用设定：假设手上有 60 条本地合成的房屋记录。页面不下载、也不内置真实成交数据集，字段与数值是为讲清流程而设定的，不能当作任何城市的真实房价。

预处理

  1. 先划分训练集 / 验证集 / 测试集，再计算任何统计量。
  2. 缺失值用训练集的中位数填充，并记录填充比例；缺失本身也可能携带信息。
  3. 对面积、通勤时间等连续特征做标准化；它不会改变线性模型的预测，但有利于正则化和梯度下降。
  4. 把类别字段（如装修等级）做独热编码，避免把高基数编号直接当数值。
  5. 检查目标分布与极端值，再决定是否对价格取对数——这是建模假设，不是自动正确。

算法选择与理由

  • 线性回归：先建立可解释的基线，系数方向可以核对，误差也容易向别人解释。
  • 决策树 / 梯度提升：能捕捉非线性与特征交互，但需要更多数据与调参，也更容易过拟合。
  • 选择理由：先用简单模型确认数据里有没有稳定信号，再决定是否值得上复杂模型，不要一上来就堆模型。

评估指标

  • MSE：对大误差惩罚重，单位是价格的平方，不直观。
  • MAE：与价格同单位，更容易向非技术读者解释。
  • R²：相对「始终预测均值」的提升比例；它可以为负，负值表示比均值基线还差。

数据泄漏风险

  • 使用成交之后才知道的信息，例如最终税费、交割日期、贷款审批结果。
  • 在划分数据之前做标准化或插值，把验证集 / 测试集的分布信息带进训练。
  • 把「是否已成交」或「挂牌已撤销原因」当作特征，可能直接泄露目标。
  • 用测试集反复调参，再把同一测试集的分数当最终成绩——这是评估泄漏，同样会高估。

关联实验只演示一个简化机制（linear-fit），不等于本案例的完整模型，也不使用案例中描述的合成数据。

INTERACTIVE EXPERIMENT

线性回归拟合

ŷ = -0.300x + 0.800

步骤 0：按所有点的平均梯度更新斜率和截距；当前 MSE = 0.1147

观察问题：学习率小的时候，拟合线需要多少步才稳定？

结论提示：预测线最小化平均平方误差；点到线的竖直距离才是这里的残差。

观察练习：下面哪个特征最可能造成目标泄漏（预测时拿不到、或包含结果信息）？

范围限制：这是流程练习，不是可用的估价系统：只有本地合成的讨论数据，没有真实市场价格、政策变化与区域差异。线性关系只是起点，真实房价常含强非线性与交互；关联实验也只演示 18 个合成点上的直线拟合，不能外推为真实预测能力。

记住这三句话

  1. 先定义任务和标签，再选算法；「分类 / 回归 / 聚类」不是装饰，而是评价方式的起点。
  2. 数据来源和划分方式决定结论能走多远；本地合成数据只能练流程，不能当真实效果。
  3. 任何高分都要先问：有没有用到预测时拿不到的信息？
