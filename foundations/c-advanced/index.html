3. 原理与图示

C 的内存布局:栈(函数局部变量、向下增长)、堆(malloc/free)、全局/静态区、只读段。数组作为函数参数时退化为指针,sizeof 只在定义处有效。

结构体对齐:成员按最大对齐数补齐,sizeof(struct) 可能大于成员之和;调整成员顺序可减小体积。

const 修饰的是"只读视图",不保证底层不被改;volatile 告诉编译器"每次都要真正读写",用于硬件寄存器与中断共享变量。

struct reading { uint32_t seq; int16_t temp; uint8_t hum; };  /* 4+2+1+1 补齐 = 8 */

4. 操作实验

  1. 把下面三段程序分别保存为 oob.c、dangling.c、uninit.c。
  2. 用 gcc -g -fsanitize=address -o /tmp/x oob.c 编译并运行,记录 ASan 报告的"错误类型 + 文件:行号"。
  3. 用 gdb /tmp/x 的 bt 查看调用栈;修复后重新编译运行,确认报告消失。
  4. 把三次对比写进错题本或 /archive/ 的笔记。
/* oob.c */
#include <stdlib.h>
int main(void) { int *p = malloc(4 * sizeof(int)); p[4] = 1; free(p); return 0; }
/* dangling.c */
int main(void) { int *p = malloc(sizeof(int)); free(p); return *p; }
/* uninit.c */
#include <stdio.h>
int main(void) { int x; return x > 0 ? 0 : 1; }

5. 结果检查

检查项预期
越界写ASan 报 heap-buffer-overflow,含文件:行号
悬垂指针ASan 报 heap-use-after-free
未初始化读valgrind 或 -Wuninitialized 提示(ASan 不覆盖)
修复后三次运行均无错误报告;gdb bt 只在出错时使用

6. 故障排查

现象检查步骤预期结果下一分支
段错误但无 ASan 报告是否忘了 -g/-fsanitize=address?是否直接运行了旧二进制?重新编译并确认文件时间用 gdb bt 或 core 文件
结构体 sizeof 与预期不符对齐规则与成员顺序按最大对齐数补齐重排成员或加 packing(慎用)
优化后行为改变未定义行为被优化利用-O0 与 -O2 对比先修 UB,再谈优化

证据边界:示例命令在本机 gcc 13.3.0 可复现;真实硬件相关问题请结合具体板卡验证。
