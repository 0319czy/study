ROS 基础

ROS Basics · Workspace / Package / Node

一句话解释一句话解释：ROS 不是操作系统，而是一套让机器人里的许多小程序「说同一种语言」的软件框架——它规定程序怎么组织、怎么找彼此、怎么传数据。

🧩生活化比喻 · 工地与工人

把机器人项目想成一片工地：工作空间是整个工地，包是每个工种的工具箱，节点是干活的工人，话题是工地上的广播频道，参数是贴在墙上的施工参数表，launch 文件就是一张「一键开工」的调度单。

  • 工人（节点）之间不直接喊话，而是通过广播频道（话题）交流，所以谁换了人都不影响其他人
  • 工具箱（包）里装同一件事的工具：驱动、算法、界面分开装，方便复用
  • 调度单（launch）写清楚今天开哪几个工、各自参数是多少，一条命令全部开工

🎯为什么重要 / 用在哪里

几乎所有机器人软件工程都建立在这几个概念上：不会建包就不会写代码，不懂节点就查不到问题，不懂 launch 就只能一个个手动启动程序。

  • 工程协作：一个机器人项目常常几十上百个包，靠统一的目录与依赖声明才能协作
  • 可复用：同一个激光驱动包，可以被你的小车、别人的机械臂直接复用
  • 可调试：出问题时先看「哪个节点没起来、哪个话题没数据」，这是 ROS 排障的起点
  • 面试高频：工作空间结构、launch 与 node 的关系、colcon 做了什么，几乎是必问

#工作空间：工地怎么划区

ROS 2 的工作空间是一个约定俗成的目录结构。你只写 src 里的代码，build / install / log 都是 colcon 自动生成的，不要手改。

  • src/：你的源码，每个子目录是一个包
  • build/：编译中间文件，可以随时删掉重编
  • install/：编译产物，source 这里的 setup.bash 才能 ros2 run 到你的包
  • log/：每次构建的日志，构建失败时先看最新的那份
$ mkdir -p ~/ros2_ws/src && cd ~/ros2_ws
  • mkdir -p创建目录，-p 表示父目录不存在也一起建（已存在不报错）
  • ~/ros2_ws/src工作空间根目录下的源码目录，名字习惯用 ws 结尾
$ colcon build --symlink-install
  • colcon build在当前目录（工作空间根）编译所有包
  • --symlink-install用符号链接代替复制，改 Python 代码不用重新 build；C++ 代码仍需重编
$ source install/setup.bash
  • source在当前 shell 里执行脚本，让环境变量生效（不要用 sh 执行，会开子进程）
  • install/setup.bash把你的包加入 ROS 的查找路径（AMENT_PREFIX_PATH 等）
每个新开的终端都要 source 一次，或者把它写进 ~/.bashrc——这也是「明明编译成功却 ros2 run 找不到包」最常见的原因。

#包：一个工具箱要有说明书

一个包必须包含 package.xml（说明书：叫什么、依赖谁、谁维护），再按语言不同带 CMakeLists.txt（C++）或 setup.py（Python）。

包名只能用小写字母、数字和下划线，且必须与文件夹名一致，否则构建会报错。

#包的构建规则：CMakeLists 做三件事

C++ 包的 CMakeLists.txt 看起来吓人，其实核心只有三件事：找依赖 → 编译可执行文件 → 安装到 install 目录。少了第三步，ros2 run 就会说找不到可执行文件。

#节点：每个工人只管一件事

节点是一个正在运行的进程。好的节点职责单一：激光驱动只管发激光数据，路径规划只管算路径。这样某一块崩了，换掉它不影响别人。

一个可执行文件可以用 run 启动，也可以带参数、改节点名、重映射话题名——这些都不需要改代码。

$ ros2 run turtlesim turtlesim_node
  • turtlesim包名（package）
  • turtlesim_node可执行文件名（executable），不是节点名
$ ros2 node list
  • node list列出当前所有在线的节点名，这是排障第一步
$ ros2 node info /turtlesim
  • /turtlesim节点名（带斜杠）；如果启动时用 __node:= 改名，这里就换成新名字
  • info查看该节点发布了哪些话题、订阅了哪些、提供了哪些服务
节点名可以重复吗？可以，但会造成两个节点争抢同一个名字，话题/service 名冲突，调试非常痛苦。启动时用 `__node:=新名字` 改名更安全。

#消息与接口：说同一种语言

消息是节点之间传输的数据结构，定义在 .msg 文件里。ROS 2 把消息、服务、动作统称为「接口」（interface）。

标准消息库 std_msgs / sensor_msgs / geometry_msgs 覆盖了绝大多数常见需求，自己定义消息只在标准类型不够用时才做。

$ ros2 interface show std_msgs/msg/String
  • std_msgs/msg/String包名/msg/消息名；服务用 srv，动作用 action
  • show打印这个接口的字段定义，写代码前先确认字段名
$ ros2 topic echo /turtle1/pose --once
  • /turtle1/pose要打印的话题名
  • --once只打印一条就退出，避免刷屏

#参数与 Launch：把配置和启动分离

参数让同一份代码适应不同机器人：最大速度、话题名、控制频率都不该写死在代码里。

launch 文件把「启动哪些节点 + 参数 + 重映射」写成一份可版本管理的脚本，一条命令拉起整个系统。

$ ros2 param list /turtlesim
  • /turtlesim目标节点名
  • list列出该节点声明过的参数（没声明过的参数不会出现）
$ ros2 param set /turtlesim background_r 200
  • set运行时修改参数（只在本次运行有效，重启后丢失）
  • background_r参数名
  • 200参数值；类型不匹配会报错，例如把整数写成 200.0
$ ros2 launch my_first_pkg demo.launch.py
  • ros2 launch启动 launch 文件（不是 ros2 run）
  • my_first_pkg包名
  • demo.launch.pylaunch 文件名，必须在包的 launch 目录里并在安装规则中声明

Launch 启动流程

看一条 ros2 launch 命令如何按顺序拉起多个节点、注入参数、建立通信。

第 1/5 步
解说ros2 launch 读取 launch 文件（Python 或 XML），这是整个启动流程的入口。
  • 节点
  • 话题（广播）
  • 参数（配置）
  • 规划路径

观察问题

  1. launch 是先启动节点再传参数，还是先解析参数再启动？
  2. 节点 A 先起来、节点 B 后起来时，A 发的消息会不会丢？
  3. 为什么 launch 比手敲一堆 ros2 run 更适合工程？

结论提示

launch 是一份「启动计划」：解析文件 → 创建节点（可并行）→ 注入参数/重映射 → 各自开始跑。因为它把启动顺序与配置写成了代码，所以能进版本库、能复现、能一键启动整套系统。

学习示意：真实 launch 还支持事件处理、条件判断、命名空间与包含（IncludeLaunchDescription）。

参数配置：运行时改行为

同一份节点代码，通过参数改变行为；观察参数如何被读取、生效、并影响输出。

第 1/5 步
解说节点启动时先向 ROS 声明参数：名字、类型、默认值。没声明过的参数名是不允许设置的。
  • 节点
  • 参数（配置）
  • 机器人

观察问题

  1. 参数是在节点启动时读一次，还是每次使用都重新读？
  2. 运行时改参数，节点会立刻生效还是需要重启？
  3. 为什么参数要在代码里「声明」？

结论提示

参数让配置与代码分离：代码声明参数名与默认值，launch 或命令行在运行时覆盖。节点在启动时读取并缓存，运行时修改只有在节点回调里重新取值时才生效——这也是很多「改了参数没反应」的原因。

学习示意：真实节点用 declare_parameter / get_parameter / add_on_set_parameters_callback 完成同样的流程。

排障

常见错误与排查

先看现象，再想原因，最后按步骤验证

  • 🚨现象：colcon build 成功，但 ros2 run 报 Package not found

    原因：没有 source install/setup.bash，或者在工作空间以外的终端里执行。

    1. 确认当前终端执行过 source install/setup.bash
    2. echo $AMENT_PREFIX_PATH 检查你的工作空间路径是否在里面
    3. 换到工作空间根目录重新 build 并 source，再试一次

  • 🚨现象：ros2 run pkg exe 报 No executable found

    原因：CMakeLists 里漏了 install(TARGETS ...)，或 Python 的 setup.py 没登记 console_scripts。

    1. 打开 CMakeLists.txt 检查 install(TARGETS 名字 DESTINATION lib/${PROJECT_NAME})
    2. Python 包检查 setup.py 的 entry_points 是否包含该命令
    3. 重新 colcon build 后 ls install/pkg/lib/pkg/ 看可执行文件在不在

  • 🚨现象：package.xml 写法看起来没问题，build 却报 name 不匹配

    原因：包文件夹名与 package.xml 里的 <name> 不一致，或包名含大写字母/中划线。

    1. 把目录名改成与 <name> 完全一致
    2. 包名只用小写字母、数字、下划线
    3. 改名后删掉 build/ 与 install/ 重新构建，避免旧缓存干扰

  • 🚨现象：ros2 param set 报 Parameter not declared

    原因：节点代码没有声明该参数（ROS 2 默认不允许设置未声明的参数）。

    1. 在节点里用 declare_parameter / declare_parameter("x", 默认值) 声明
    2. 确认参数名完全一致（大小写、下划线）
    3. 用 ros2 param list /节点名 看节点到底声明了哪些参数
