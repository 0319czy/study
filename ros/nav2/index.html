导航 Nav2

Nav2 · Costmap / Planner / Controller / Behavior Tree

一句话解释一句话解释：Nav2 是 ROS 2 的导航系统——你给一个目标点，它负责「我现在在哪、该怎么走、每一步踩哪里、卡住了怎么办」。

学习目标

学完这页你应该能做到

  • ✓能画出 Nav2 的导航流水线，说清每个模块负责什么
  • ✓能解释代价地图的分层与膨胀层的意义
  • ✓能区分全局规划与局部控制的职责
  • ✓能说明行为树在导航里的作用（而不是死板的流程图）
  • ✓能通过一条命令启动导航并用动作下发目标点

🧩生活化比喻 · 开车用高德导航

高德先按地图规划一条长路线（全局规划），开车时又不断看眼前有没有车、行人（局部避障），走错了会自动重新规划（恢复行为）。Nav2 就是机器人版的高德，只不过它用的是代价地图和行为树。

  • 地图 + 定位 = 我在哪（AMCL）
  • 全局规划 = 从这到那的大方向
  • 局部控制 = 下一步具体往哪打方向
  • 行为树 = 堵死了怎么办、卡住了怎么办

🎯为什么重要 / 用在哪里

移动机器人最核心的功能就是「自主到达」。Nav2 是 ROS 2 生态里唯一成熟的通用导航栈，几乎所有移动机器人项目都基于它。

  • 服务机器人：送餐、巡检、清洁的路径执行
  • 仓储 AGV：地图内点到点运输
  • 自动驾驶原型：Nav2 的规划与控制思想可迁移
  • 面试：代价地图、膨胀半径、全局/局部规划区别是高频考点

术语

核心概念

中英对照 + 一句话解释

代价地图Costmap
把环境表示成「通行代价」的栅格图：障碍代价高、越靠近障碍越贵。
膨胀层Inflation Layer
在障碍周围按半径扩散代价，让路径远离墙壁，给机器人留安全余量。
AMCLAdaptive Monte Carlo Localization
粒子滤波定位：用激光与地图匹配，估计机器人在 map 中的位姿。
全局规划器Global Planner
在全局代价地图上算一条从起点到目标的路径，例如 NavFn、Smac。
局部控制器Local Controller
按全局路径生成速度指令并实时避障，例如 DWB、Regulated Pure Pursuit。
行为树Behavior Tree
用树形结构组织「先做什么、失败后做什么」，比状态机更易扩展。
生命周期节点Lifecycle Node
有 configure/activate/deactivate 状态的节点，便于受控启停。

#导航流水线：谁在干什么

Nav2 不是一个节点，而是一组节点协作。理解这张「流水线图」，调参时才知道该改哪个文件。

Nav2 主要模块
模块职责输入 / 输出
map_server加载并发布静态地图（/map）yaml → /map
amcl激光 + 地图 → 机器人位姿，发布 map→odom/scan + /map → TF
planner_server全局路径规划目标点 → /plan
controller_server跟随路径并避障/plan + 局部代价地图 → /cmd_vel
bt_navigator用行为树调度整个导航流程NavigateToPose 动作 → 各模块
behavior_server恢复行为：清代价地图、原地转、后退触发条件 → 动作
velocity_smoother速度平滑与限幅，保护底盘/cmd_vel → /cmd_vel_smoothed

#代价地图：不是「能不能走」，而是「多贵」

代价地图给每个格子一个 0~255 的通行代价。障碍物本身是致命代价（不可通行），障碍附近代价逐渐降低——这就是膨胀层，它让规划器倾向于走「宽敞的中间」。

  • static layer：来自静态地图的墙
  • obstacle layer：来自激光/点云的实时障碍
  • inflation layer：按 robot_radius 向外扩散代价
  • voxel layer：3D 点云投影（用于三维障碍）
  • 膨胀半径太小 → 贴着墙走，容易擦碰；太大 → 狭窄通道过不去
常见误区：以为「地图上没障碍就能走」。实际还要看膨胀层、机器人半径、以及局部代价地图的实时障碍。走廊过不去，多半是膨胀半径设大了。

#全局规划 vs 局部控制

两层规划的分工
维度全局规划（Global Planner）局部控制（Local Controller）
看什么地图全局代价地图（整张图）局部代价地图（机器人周围几米）
输出一条路径 /plan速度指令 /cmd_vel
更新频率低（几 Hz，目标变化时才重算）高（10~50 Hz）
主要解决的问题走哪条路最省/最安全此刻怎么走、怎么躲开突然出现的人
失败时重新规划暂停、减速、触发恢复行为

#行为树：卡住了怎么办，写进树里

传统状态机写导航逻辑容易变成一团乱麻；行为树把「成功/失败」的传播规则标准化，节点可以复用、可以组合。Nav2 的默认树大致是：计算路径 → 跟随路径，失败就重试规划，再失败就执行恢复行为。

#跑起来：一条命令 + 一个目标

$ ros2 launch nav2_bringup bringup_launch.py map:=/home/user/my_map.yaml use_sim_time:=true
  • map:=...指定地图文件；不写会尝试用默认参数，通常必须给
  • use_sim_time:=true仿真或回放时为 true，真机为 false
  • bringup_launch.py一次性启动 map_server、amcl、planner、controller、bt_navigator 等全套节点
$ ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose 「目标位姿：x、y 用米，朝向用四元数或 yaw」
  • /navigate_to_poseNav2 的导航动作名
  • nav2_msgs/action/NavigateToPose动作类型
  • 目标位姿在 map 坐标系下给出，RViz2 里也可以用 2D Goal Pose 工具直接点
$ ros2 lifecycle get /controller_server
  • lifecycle get查看生命周期节点当前状态；不是 active 就不会接收指令
  • /controller_server目标生命周期节点
导航卡住时按这个顺序查：定位（amcl 粒子是否收敛）→ 代价地图（RViz 看障碍与膨胀）→ 规划（有没有路径）→ 控制（有没有 /cmd_vel）→ 底盘（是否真的动）。

第 1/5 步
解说加载静态地图并生成代价地图：障碍是致命代价，障碍周围按膨胀半径扩散出「贵」的区域。
  • 地图 / 栅格
  • 障碍物
  • 规划路径
  • 机器人
  • 传感器数据

观察问题

  1. 膨胀层让全局路径离墙更远了吗？
  2. 突然出现的障碍会触发什么（重规划还是局部绕行）？
  3. 卡住时行为树先做什么，后做什么？

结论提示

Nav2 是两层规划 + 一套调度：全局规划决定大方向，局部控制负责眼前的安全，行为树负责失败后的处理。调参顺序应该是「定位 → 代价地图 → 速度 → 行为树」。

学习示意：真实 Nav2 用分层代价地图与插件化规划器，栅格与路径在这里被简化。

排障

常见错误与排查

先看现象，再想原因，最后按步骤验证

  • 🚨现象：导航启动后机器人完全不动，也没有路径

    原因：地图没加载成功，或 amcl 没收敛（定位失败），或生命周期节点没激活。

    1. RViz2 看 /map 有没有显示
    2. 用 2D Pose Estimate 给一个初始位姿，等粒子收敛
    3. ros2 lifecycle get 检查各节点是否 active

  • 🚨现象：规划出的路径贴着墙，实际执行时擦碰

    原因：膨胀半径太小，或 robot_radius 设置小于真实尺寸。

    1. 增大 inflation_radius 并调 cost_scaling_factor
    2. 按真实外接圆设置 robot_radius
    3. 检查障碍层是否真的看到墙（RViz 看代价地图）

  • 🚨现象：走廊过不去，一直报 no valid control

    原因：膨胀半径过大，把窄通道完全填满；或代价地图分辨率太粗。

    1. 减小 inflation_radius（但要保证安全）
    2. 提高代价地图分辨率（resolution 调小）
    3. 考虑用可通行区域约束，而不是硬调膨胀

  • 🚨现象：机器人原地打转、反复重规划

    原因：定位漂移导致目标点位置错误，或局部规划器陷入局部极小。

    1. 检查 amcl 粒子分布是否发散
    2. 降低最大速度，增加前视距离
    3. 查看 bt_navigator 日志，看触发了哪种恢复行为

收尾

记住这三句话

    导航 = 定位 + 代价地图 + 全局/局部规划 + 行为树调度。
