工具链

Toolchain · ros2 CLI / RViz2 / rqt / rosbag2 / doctor

一句话解释一句话解释：ROS 工具链就是机器人的「听诊器 + 录像机 + 仪表盘」——用它们看数据、录数据、画数据，把看不见的通信过程变成看得见的画面。

学习目标

学完这页你应该能做到

  • ✓能用 ros2 命令行在 5 分钟内摸清一个陌生系统的结构
  • ✓能在 RViz2 里正确设置 Fixed Frame 并显示传感器数据
  • ✓会用 rqt_graph / rqt_plot / rqt_console 定位问题
  • ✓能录制、回放 rosbag2 数据包并配合仿真时间
  • ✓会用 ros2 doctor 做系统体检，用 launch 参数调试启动失败

🧩生活化比喻 · 医院查体四件套

一条 ROS 命令像听诊器（听单个器官），RViz2 像 CT 机（看整体影像），rqt 像一排仪表盘（实时曲线与日志），rosbag2 像录像机（把过程录下来反复看）。

  • 听诊器（CLI）：快速确认「这个节点、这个话题活着吗」
  • CT 机（RViz2）：把激光、点云、TF、路径画成三维画面
  • 仪表盘（rqt）：曲线、节点图、日志聚合、相机画面
  • 录像机（rosbag2）：现场数据带回家，复现同一个 bug

🎯为什么重要 / 用在哪里

工具链决定你排障的速度。同一个 bug，会用工具的人 10 分钟定位，不会的人改一整天代码。

  • 接手陌生系统：node list、topic list、rqt_graph 三分钟画出通信结构
  • 复现问题：现场录 bag，回家离线回放，不用一直占着机器人
  • 性能检查：ros2 topic hz 看频率，rqt_plot 看数值抖动
  • 录包做数据集：感知与导航调参的标准流程

#ros2 命令行的三个层次

记住这个分层就不容易乱：第一层「系统里有什么」（list），第二层「某个东西长什么样」（info、show），第三层「和它互动」（echo、pub、call、send_goal）。

  • 有什么：node list、topic list -t、service list -t、action list -t、param list
  • 什么样：node info、topic info -v、interface show、param get
  • 互动：topic echo、pub、hz、service call、action send_goal、param set
$ ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist
  • topic pub手动往话题发一条消息，用来测试下游节点是否正常；消息内容用 YAML 写在最后并加引号
  • --once只发一次；不写会持续按频率发送，Ctrl+C 停止
  • /turtle1/cmd_vel目标话题名
  • geometry_msgs/msg/Twist消息类型，必须与话题现有类型一致
$ ros2 node info /turtle1
  • info查看节点发布了什么、订阅了什么、提供哪些服务与动作
  • /turtle1节点名

#RViz2：先设 Fixed Frame，再谈显示

RViz2 里最常被忽略的一步是 Fixed Frame（固定坐标系）。所有显示数据都要变换到这个世界坐标系下才能画出来；如果 TF 里没有这个坐标系，画面就会报错说 Fixed Frame 不存在。

  • Fixed Frame 常用 map（导航）或 base_link、odom（调试单机）
  • LaserScan 显示：把 Topic 设为 /scan，Size 调大一点才看得清
  • TF 显示：勾选 Frames 就能看到坐标轴与连接关系
  • Path、Map、PointCloud2 是导航与感知最常用的三种显示
  • 保存配置：File 菜单里的 Save Config As，下次不用重新点一遍
$ rviz2 -d my_config.rviz
  • -d启动时加载配置文件（.rviz），团队共享显示配置的标准做法
  • my_config.rviz配置文件路径
RViz2 只能看，不能动机器人。想拖动机器人模型、下发导航目标，需要配合插件，例如 Nav2 的 2D Goal Pose 与 MoveIt2 的 MotionPlanning 面板。

#rqt：四个够用的插件

rqt 是一堆小工具的集合，不需要全学，先掌握四个：看结构、看数值、看日志、看图像。

$ rqt_graph
  • 无参数打开节点与话题的连接图，能直观看出命名空间与连接关系
$ ros2 run rqt_plot rqt_plot /turtle1/pose/x:y
  • /turtle1/pose/x:y要画的消息字段，用冒号分隔即可同图显示多个字段
  • rqt_plotROS 2 里 rqt 插件用 ros2 run 调用，和 ROS 1 的 rosrun 不同
常用 rqt 插件
插件作用什么时候用
rqt_graph画出节点与话题的连接图接手新系统、确认谁在发谁在收
rqt_plot把消息字段画成实时曲线看速度抖动、PID 响应、传感器噪声
rqt_console集中查看所有节点日志并按级别过滤多节点同时报错时定位源头
rqt_image_view显示相机或深度图确认图像话题是否有画面

#rosbag2：把现场录下来

bag 是 ROS 的黑匣子：把话题数据按时间戳存盘，之后可以离线回放，甚至用 --clock 让节点以为时间在流动。

$ ros2 bag record -a -o my_bag
  • -aall，录制所有话题；体积可能很大，现场建议先 topic list 选出关键话题
  • -o my_bag输出目录名，会生成 my_bag 目录而不是单个文件
$ ros2 bag info my_bag
  • info看包里有哪些话题、时长、消息条数、存储格式
  • my_bagbag 目录路径
$ ros2 bag play my_bag --clock
  • play回放 bag
  • --clock发布 /clock 仿真时间，配合节点 use_sim_time 为 true 才能正确对齐
$ ros2 bag play my_bag -r 0.5 -l
  • -r 0.5以 0.5 倍速回放，方便观察细节或降低 CPU 压力
  • -lloop，循环回放，调试可视化时很方便
回放时若节点没有设 use_sim_time 为 true，会出现数据时间戳是过去的、节点却用当前时间的诡异问题，TF 查询尤其容易报错。

#ros2 doctor 与 launch 调试

ros2 doctor 是体检工具，能快速判断是环境问题还是代码问题。launch 出问题时，先看它到底生成了什么、参数传到哪了。

$ ros2 doctor --report
  • doctor检查 ROS 环境、网络、依赖
  • --report输出完整报告，排查明明装了包却找不到时非常有用
$ ros2 launch my_pkg demo.launch.py --show-args
  • --show-args只打印这个 launch 文件支持哪些参数，不真正启动
$ ros2 launch my_pkg demo.launch.py --print
  • --print打印 launch 最终展开后的节点与参数清单，确认参数有没有真的传进去
$ ros2 launch my_pkg demo.launch.py --log-level debug
  • --log-level debug把 launch 自身日志调到 debug，能看到每个节点的启动细节

排障

常见错误与排查

先看现象，再想原因，最后按步骤验证

  • 🚨现象：RViz2 报错说 Fixed Frame 不存在

    原因：TF 树里没有 map 坐标系，或者 TF 还没发布。

    1. 用 ros2 run tf2_tools view_frames 生成 TF 树，确认 map 是否存在
    2. 没跑导航时把 Fixed Frame 改成 base_link 或 odom
    3. 检查 map 到 odom 的定位节点（amcl）是否启动

  • 🚨现象：ros2 bag play 之后 RViz2 什么都不动

    原因：节点没设 use_sim_time 为 true，或者回放时没加 --clock。

    1. 回放时加 --clock，确认 ros2 topic echo /clock 有数据
    2. 给节点或 launch 设置参数 use_sim_time 为 true
    3. 确认 bag 里确实录到了相关话题（ros2 bag info 查看）

  • 🚨现象：rqt_plot 曲线是空白

    原因：字段路径写错（大小写或层级不对），或话题本身没有数据。

    1. ros2 topic echo /话题 --once 看清字段名
    2. 用 话题名/字段名 的形式，嵌套字段逐层写
    3. 确认话题频率不是 0（ros2 topic hz）

  • 🚨现象：ros2 launch 一闪而过并报参数不存在

    原因：launch 文件没有声明该参数，或者参数名与传入的不一致。

    1. 用 --show-args 查看该 launch 支持的参数
    2. 检查 launch 里是否用 DeclareLaunchArgument 声明了它
    3. 用 --print 看最终展开的节点参数
