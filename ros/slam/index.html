SLAM 建图

SLAM · Simultaneous Localization and Mapping

一句话解释一句话解释：SLAM 是「边走边画地图」——机器人在陌生环境里边移动边记录，一边估算自己在哪，一边把周围的墙和障碍画成地图。

SLAM激光雷达里程计栅格地图回环

学习目标

学完这页你应该能做到

  • ✓能解释为什么「定位」和「建图」必须同时做（鸡生蛋问题）
  • ✓能读懂 LaserScan 与 OccupancyGrid 的关键字段
  • ✓能跑通一次建图流程并保存地图文件
  • ✓能说出里程计漂移与回环检测的关系
  • ✓知道 slam_toolbox 与 cartographer 的定位差异

🧩生活化比喻 · 摸黑画迷宫

你被蒙上眼睛放进一个陌生房间，只允许用手电筒照一下前方。你要一边走一边在地上画房间轮廓——可问题是：你连自己走了多远都不确定（脚底打滑），画出来的图就会越来越歪。SLAM 要解决的就是：用听到看到的墙壁去纠正「我走了多远」这个估计。

  • 激光雷达 = 手电筒（测到墙的距离）
  • 里程计 = 你数步数（会累积误差）
  • 地图 = 地上逐渐画满的格子
  • 回环 = 走回原点发现画歪了，整体对齐回来

🎯为什么重要 / 用在哪里

导航必须先有地图。SLAM 是从零到一的第一步：没有地图，Nav2 无从规划；地图不准，导航到处撞墙。

  • 第一次进入新环境的建图：家里、仓库、实验室
  • 地图精度直接决定定位与规划质量
  • 回环检测能显著改善大场景地图的一致性
  • 视觉 SLAM 还能做纯相机建图（无激光雷达时）

核心概念

中英对照 + 一句话解释

SLAMSimultaneous Localization and Mapping
同时定位与建图：一边估计自身位姿，一边构建环境地图。
激光扫描LaserScan
一圈角度上的距离数组，是 2D 建图最常用的输入。
里程计Odometry
由轮子编码器推算的位移，短时间平滑、长时间会累积漂移。
栅格地图OccupancyGrid
把空间切成小格子，每格记录「被占据的概率」。
回环检测Loop Closure
识别出「我回到了来过的地方」，据此消除累积误差。
建图与定位分离Mapping / Localization
建图用 slam_toolbox 等，已有地图后交给 AMCL 做定位。

#鸡生蛋问题：为什么要同时做两件事

要准确建图，你需要知道自己在哪；要知道自己在哪，你需要一张地图。SLAM 用概率方法把两个未知量放在一起估计：既算「地图最可能长什么样」，也算「我此刻最可能在哪」。

  • 只有里程计：走 10 米后可能已经偏了 30 厘米，画出来的地图会歪
  • 只有激光：没有位姿，激光点堆在一起无法形成地图
  • SLAM：用激光匹配来修正里程计误差，用修正后的位姿去堆叠激光点

#看懂 LaserScan：一圈距离数字

激光雷达数据不是图像，而是一个角度范围上的距离数组。理解它的字段，才能理解建图算法在做什么。

sensor_msgs/msg/LaserScan 关键字段
字段含义典型值
angle_min / angle_max扫描的起始与结束角度（弧度）-3.14159 / 3.14159（360°）
angle_increment相邻两点之间的角度间隔0.0175（约 1°）
range_min / range_max有效测距范围0.12 / 8.0 米
ranges距离数组，长度 = (max-min)/increment每项单位米
frame_id该数据的坐标系名laser_link
scan_time扫描一圈的耗时0.1 秒（10Hz）
LaserScan 里也可能出现 inf（无限远，表示没打到东西）或 NaN，算法需要专门处理，否则会把「没东西」当成「很近的障碍」。

#概率栅格与 log-odds：每个格子都有「把握」

栅格地图不是把格子简单涂黑或涂白，而是维护「被占据的概率」。为了数值稳定与计算方便，通常存对数几率（log-odds），观测到障碍就加一个正数，观测到空闲就减一个数。

#跑一次建图：四步流程

以 2D 激光建图为例，流程是「起驱动 → 起 SLAM → 遥控走一圈 → 存地图」。

$ ros2 launch slam_toolbox online_async_launch.py use_sim_time:=true
  • online_async_launch.py在线异步建图模式：一边收激光一边增量更新地图
  • use_sim_time:=true仿真或回放时必须打开；真机可以不写
$ ros2 run teleop_twist_keyboard teleop_twist_keyboard
  • teleop_twist_keyboard键盘遥控节点，发布 /cmd_vel；建图时要匀速慢走，转弯别太快
$ ros2 run nav2_map_server map_saver_cli -f my_map
  • map_saver_cli把 /map 话题保存成文件（.pgm + .yaml）
  • -f my_map输出文件名前缀；会在当前目录生成 my_map.pgm 与 my_map.yaml
建图时最容易犯的错是「走太快、转太急」：激光匹配跟不上，地图就会扭曲。慢走、多转弯、回到起点形成回环，地图质量会好很多。

#回环检测：走回原点时的「啊，我来过」

走了 20 米回到起点，里程计说你偏了 1 米，但激光发现墙的位置和起点时匹配——这就是回环。算法据此把整段轨迹拉回去，地图瞬间对齐。

  • 没有回环：地图会像手绘长卷一样逐渐歪掉（尤其大场景）
  • 有回环：整张图误差被分散，一致性大幅提升
  • 误回环很危险：走错地方也会被当成回环，导致地图撕裂
  • 视觉 SLAM 常用词袋模型（BoW）做回环候选检索

结论提示

SLAM 的本质是「用观测不断修正位姿估计，再把观测累积成地图」。栅格概率让地图能表达不确定；回环检测负责消除长期累积误差。

学习示意：真实 SLAM 还会做位姿图优化、子图（submap）与回环约束，这里的漂移是夸张演示。

排障

常见错误与排查

先看现象，再想原因，最后按步骤验证

  • 🚨现象：地图越走越歪，墙出现重影

    原因：里程计漂移大且没有回环，或激光与里程计时间不同步。

    1. 降低行驶速度，增加转弯处的停留
    2. 尽量走回起点形成回环
    3. 检查 use_sim_time 与时间戳是否一致

  • 🚨现象：建图完全没有反应，/map 一直是空的

    原因：没有 /scan，或 /scan 的 frame_id 在 TF 里不存在。

    1. ros2 topic echo /scan --once 看数据是否存在
    2. 检查 laser_link 的静态 TF 是否发布
    3. ros2 run tf2_tools view_frames 确认坐标系连通

  • 🚨现象：保存的地图在 Nav2 里位置整体偏移

    原因：地图 yaml 里的 origin 与建图时的地图坐标系不一致。

    1. 检查保存时机器人是否在 map 坐标系原点附近
    2. 对比 RViz 中地图与实际环境的位置关系
    3. 必要时用图像工具重新对齐 origin 后手改 yaml

  • 🚨现象：建图过程中 CPU 飙高、地图更新越来越慢

    原因：场景过大、栅格太细、或同时开了多个建图节点。

    1. 增大 resolution（例如 0.1 米）
    2. 限制地图范围，或使用只保留局部地图的模式
    3. 确认没有重复启动 slam 节点（ros2 node list 检查）
