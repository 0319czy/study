URDF 建模

URDF · link / joint / xacro / robot_state_publisher

一句话解释一句话解释：URDF 是用 XML 写的机器人「结构说明书」——有哪些零件（link）、零件之间怎么连接（joint）、长什么样、多重，写清楚之后 RViz2 就能把你画的机器人显示出来。

🧩生活化比喻 · 乐高积木与连接件

link 是一块块积木（车身、轮子、机械臂连杆），joint 是把积木连起来的连接件。有的连接件是死的（fixed，焊住），有的是转轴（revolute/continuous），有的是滑轨（prismatic）。你给每块积木标上尺寸、外观和重量，机器人的「数字双胞胎」就成型了。

  • link：有名字的刚体零件，可以设置外观、碰撞体、质量
  • joint：父子 link 之间的相对位置与运动方式
  • origin：每个零件相对父节点的安装位置（平移 + 旋转）

🎯为什么重要 / 用在哪里

URDF 是「显示、仿真、规划、碰撞检测」的共同基础：RViz2 靠它画模型，Gazebo 靠它算碰撞，MoveIt2 靠它做运动规划。

  • 可视化：RViz2 显示机器人当前姿态
  • 仿真：模型直接导入 Gazebo，加传感器插件就能跑
  • 规划：机械臂的运动学与碰撞检测都基于 URDF（加 SRDF）
  • 协作：一份 URDF 就是团队共享的机器人结构定义

#link 与 joint：先有零件，再有连接

URDF 是一个 XML 树：最外层是 robot，里面平铺着所有 link 与 joint。joint 通过 parent / child 把 link 连成树形结构——注意，和 TF 一样，一个 link 只能有一个父 joint。

常用 joint 类型
类型运动方式典型用途必须写 limit 吗
fixed完全固定底盘到雷达、相机支架不需要
continuous绕轴无限旋转驱动轮、万向轮需要 effort / velocity
revolute绕轴转动但有角度范围机械臂关节、舵机需要 lower / upper / effort / velocity
prismatic沿轴直线滑动升降台、夹爪开合需要 lower / upper / effort / velocity
floating / planar六自由度 / 平面移动很少直接用在 URDF 里视类型而定

#三个容易混的标签：visual、collision、inertial

同一个 link 里可以同时有三种描述，它们服务不同目的，不能混用。

  • visual：给人看的，决定 RViz2 里长什么样（几何形状、颜色、贴图）
  • collision：给物理引擎和规划器用的碰撞体，通常比 visual 简单（用盒子近似复杂外形）
  • inertial：给动力学仿真用的质量与转动惯量，缺失时 Gazebo 会警告或行为异常
  • 三者都可以各自带 origin，用来调整相对零件坐标系的位置

#让它动起来：三个节点的配合

URDF 本身只是静态描述。要看到它并让它动，需要三个角色配合：robot_state_publisher 把 URDF + 关节角变成 TF，joint_state_publisher_gui 提供可拖动的滑块，RViz2 负责画图。

$ ros2 run robot_state_publisher robot_state_publisher diff_bot.urdf
  • robot_state_publisher读取 URDF，发布 robot_description 与各 link 的 TF
  • diff_bot.urdfURDF 文件路径；也可以由 launch 通过 robot_description 参数传入
$ ros2 run joint_state_publisher_gui joint_state_publisher_gui
  • joint_state_publisher_gui弹出滑块窗口，拖动即可发布 /joint_states，看关节动起来
$ rviz2 -d diff_bot.rviz
  • -d diff_bot.rviz加载已保存的显示配置；Fixed Frame 记得设成 base_link
顺序不重要，但三者都必须在同一 ROS_DOMAIN_ID 下。RViz2 里没有 robot_description 就看不到模型，通常说明 robot_state_publisher 没起来。

#xacro：别复制粘贴，写宏

两个轮子几乎一样，只有名字和位置不同。xacro 让你写一次宏，传参数生成多次，还能用变量统一管理尺寸。

$ ros2 launch my_pkg display.launch.py
  • display.launch.py常见做法：launch 里用 xacro 处理模型、启动 robot_state_publisher、打开 RViz2

  1. revolute 与 continuous 在运动范围上有什么区别？
  2. 关节角变化时，子 link 的位置是绕哪个点转的？
  3. fixed 关节在动画里为什么不动？

结论提示

关节运动是围绕 joint 的 origin（也就是父 link 上的安装点）进行的，轴方向由 axis 决定。理解这一点，才能明白为什么 URDF 里 origin 写错会导致轮子「绕着奇怪的点转」。

排障

常见错误与排查

先看现象，再想原因，最后按步骤验证

  • 🚨现象：RViz2 里机器人模型不显示，只有坐标轴

    原因：robot_description 没发布（robot_state_publisher 没起来），或 Fixed Frame 与模型坐标系不匹配。

    1. ros2 param get /robot_state_publisher robot_description 看参数是否存在
    2. 检查 RViz2 的 RobotModel 插件里 Description Topic 是否设为 robot_description
    3. 把 Fixed Frame 设成 base_link 再试

  • 🚨现象：模型显示正常，但拖 joint_state_publisher_gui 滑块不动

    原因：关节名不一致，或 joint 类型是 fixed（fixed 关节不接受运动）。

    1. 对比 URDF 里的 joint name 与 /joint_states 里的 name
    2. ros2 topic echo /joint_states 确认发布的内容
    3. 确认该关节不是 fixed 类型

  • 🚨现象：XML 解析报错：mismatched tag 或 Unexpected end of file

    原因：标签没闭合，或 XML 里出现了未转义的 & < 等字符。

    1. 用编辑器格式化 XML，检查配对标签
    2. 把注释里的特殊字符去掉或转义
    3. 用 xmllint 或 check_urdf 快速定位报错行

  • 🚨现象：Gazebo 里模型乱飞或抖动

    原因：inertial 参数不合理（质量为 0 或惯量过小），或 collision 与 visual 不匹配。

    1. 给每个 link 设置合理质量（例如 1~5 kg）
    2. 惯量用近似公式估算，不要全填 0
    3. 让 collision 尺寸不大于 visual，必要时简化碰撞体
