MoveIt2 机械臂

MoveIt2 · Motion Planning / Collision / Planning Group

一句话解释一句话解释：MoveIt2 是机械臂的「大脑」——你告诉它「把夹爪移到桌上那个杯子」，它负责算出每个关节该怎么转、会不会撞到东西，再把轨迹交给控制器执行。

学习目标

学完这页你应该能做到

  • ✓能说清 MoveIt2 在机械臂系统里承担什么职责（以及不承担什么）
  • ✓能解释规划组、SRDF 与 URDF 的分工
  • ✓能区分关节空间规划与笛卡尔空间规划的使用场景
  • ✓能说明碰撞检测与允许碰撞矩阵（ACM）的作用
  • ✓能看懂一个 MoveGroupInterface 的最小调用流程

🧩生活化比喻 · 搬柜子绕过家具

你要把柜子从客厅搬到卧室：先看路线（规划），检查走廊宽度够不够（碰撞检测），搬的过程中还得调整手的位置避免撞到灯（笛卡尔微调）。MoveIt2 就是这个「搬家规划师」，它只管算怎么搬，不负责真的使力——使力是电机驱动器的事。

  • 规划 = 算出一条关节轨迹
  • 碰撞检测 = 确保轨迹上任何一刻都不撞
  • 执行 = 把轨迹按时间发给控制器

🎯为什么重要 / 用在哪里

六轴、七轴机械臂有 6~7 个自由度，人脑无法直接算出「转到哪几个角度才到位」。MoveIt2 把逆运动学、规划、碰撞检测、轨迹执行打包成可配置框架，是 ROS 生态机械臂的事实标准。

  • 抓取：从相机拿到目标位姿，规划到预抓取点
  • 码垛/分拣：批量点到点轨迹
  • 科研：与视觉、强化学习结合做操作任务
  • 安全：先做碰撞检测再执行，避免撞坏工件与本体

核心概念

中英对照 + 一句话解释

规划组Planning Group
把若干关节/连杆组成一个可规划的单元，例如机械臂本体、夹爪。
SRDFSemantic Robot Description Format
在 URDF 之上补充「语义」：分组、允许碰撞、默认姿态、虚拟关节。
正/逆运动学FK / IK
FK：已知关节角算末端位姿；IK：已知末端位姿求关节角（可能有多个解或无解）。
运动规划器Motion Planner（OMPL 等）
在高维关节空间里搜索一条无碰撞路径的算法。
碰撞检测Collision Checking
用包围体或网格检查机器人各部分与场景是否相交。
允许碰撞矩阵ACM
声明哪些连杆之间本来就会接触（例如相邻连杆），避免误判为碰撞。
轨迹Trajectory
关节角随时间变化的序列，含速度与加速度约束。

#MoveIt2 的边界：它做什么、不做什么

新手最容易误解的一点是：MoveIt2 不是驱动器，它不发 PWM，也不直接控制电机。它算出一条轨迹，交给 ros2_control 的控制器去执行。

  • 它做：逆运动学求解、路径规划、碰撞检测、时间参数化、轨迹执行调度
  • 它不做：底层伺服控制、力控环、安全急停（由硬件与控制器负责）
  • 它的输入：目标位姿或关节目标 + 当前机器人状态 + 场景障碍物
  • 它的输出：一条关节轨迹（发给控制器）

#URDF + SRDF：结构描述与语义描述

URDF 只描述「长什么样、怎么连接」；SRDF 补充「哪些关节算一组、哪些连杆允许接触、默认姿态是什么」。MoveIt2 必须同时读这两个文件。

#关节空间 vs 笛卡尔空间

两种规划目标怎么选
维度关节空间（Joint Space）笛卡尔空间（Cartesian）
目标怎么写直接给每个关节的角度给末端在基座坐标系下的位姿（x,y,z + 姿态）
是否需要 IK不需要需要，可能多解或无解
典型用途回零、点到点快速移动直线插补、沿表面扫描、精确对位
优点稳定、几乎总能规划成功末端轨迹可控、精度高
风险末端轨迹不可控（可能绕奇怪的路径）奇异点附近可能无解或速度爆炸
抓取场景的通用做法：先用关节空间快速到「预抓取位姿」，最后一段用笛卡尔直线慢速接近，既快又不会撞。

#碰撞检测与允许碰撞矩阵

碰撞检测是规划能否成功的关键。它把机器人每个连杆与场景障碍物做几何相交测试，任何一刻相交就判定轨迹无效。

  • 相邻连杆（1 与 2、2 与 3）本来就连着，必须用 ACM 声明允许接触
  • 夹爪两指闭合时互相接触，也要允许
  • 场景障碍物可以是规划场景里的碰撞体（碰撞对象），不必是真实传感器
  • 碰撞检测越精细越慢，工程上常用包围盒或凸包近似

#最小调用流程（C++ / MoveGroupInterface）

$ ros2 launch moveit2_tutorials demo.launch.py
  • demo.launch.py官方教程的演示启动文件，会打开 RViz2 的 MotionPlanning 面板
  • 依赖需要安装 moveit2 与 moveit2_tutorials；包名在部分发行版里是 moveit_resources 与教程包分开的
$ ros2 action list | grep -i move
  • action list查看 MoveIt2 暴露的动作接口，例如 move_action、execute_trajectory
  • grep -i move只看与 move 相关的行，快速定位动作名
RViz2 的 MotionPlanning 面板是做实验最快的方式：拖动交互标记（Interactive Marker）到目标位置，点 Plan 看轨迹，再点 Execute 执行。

给一个末端目标，看规划器如何尝试多种关节解、避开障碍，再选中一条可执行轨迹。

第 1/5 步
解说给定目标：把末端（tool0）移动到这个位姿。注意目标是「末端」的要求，不是关节角。
  • 机械臂
  • TF 坐标
  • 规划路径
  • 障碍物

观察问题

  1. 同一个末端位置为什么可能有多个关节解？
  2. 有障碍时规划失败，是把目标判为不可达，还是换了条路径？
  3. 为什么规划出的路径不是直线？

结论提示

机械臂在高维关节空间里搜索路径，直线末端轨迹往往不是「关节空间的直线」。规划器优先保证无碰撞与可达，其次才是路径短。

学习示意：真实 MoveIt2 在 6~7 维关节空间里采样，并用 OMPL 等规划器搜索；这里用二维两连杆简化。

排障

常见错误与排查

先看现象，再想原因，最后按步骤验证

  • 🚨现象：plan 一直失败，报 no motion plan found

    原因：目标不可达（超出臂展）、有碰撞、或初始状态本身就在碰撞中。

    1. 先让机械臂回到 home 姿态，确认初始状态无碰撞
    2. 把目标位姿改近一点，验证可达性
    3. 检查 SRDF 的 disable_collisions 是否漏写相邻连杆

  • 🚨现象：规划成功但执行时抖动或超时

    原因：轨迹速度/加速度超限，或控制器配置与规划时间参数不一致。

    1. 设置 max_velocity_scaling_factor 与 max_acceleration_scaling_factor 降低速度
    2. 检查 ros2_control 控制器的更新频率配置
    3. 查看 execute 的反馈，确认是卡在哪一段

  • 🚨现象：机械臂撞到桌面，但规划说无碰撞

    原因：规划场景里没有桌面这个障碍物，碰撞检测看不到它。

    1. 在 PlanningScene 里加入桌面碰撞体
    2. 或用传感器点云更新规划场景（octomap）
    3. 确认场景坐标系与机器人基座一致

  • 🚨现象：IK 求解失败，末端到不了指定姿态

    原因：目标姿态超出关节限位，或接近奇异点。

    1. 放宽姿态约束，先只约束位置
    2. 换一个接近方向（approach direction）
    3. 查看关节限位与臂展，确认目标在可达球内
