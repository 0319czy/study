3. 原理与图示

Buildroot 流水线:配置 → 下载 → 工具链 → 内核/DTB → rootfs → 镜像。产物在 output/<board>/images/。

启动链:BootROM → SPL/U-Boot → 内核 → 挂载 rootfs → init。DTB 描述硬件,内核与 DTB 必须匹配。

rootfs 最小集:/init(或 systemd)、/dev、/proc、/sys、/etc;串口控制台需要 getty 与正确的 console 参数。

make stm32mp157c_dk2_defconfig
make linux-rebuild all
ls output/stm32mp1/images/   # zImage, stm32mp157c-dk2.dtb, rootfs.ext2

4. 操作实验

  1. 在 /directions/linux-build/ 的模拟器里选目标板与工具链,生成命令并检查架构/前缀一致性。
  2. 按命令清单执行(可在 QEMU 环境):Buildroot 配置 → 内核/DTB → rootfs → 镜像。
  3. 用 file/readelf 核对产物架构;用串口日志确认启动到 login。
  4. 记录:产物路径、镜像大小、启动日志关键行、耗时。
file output/stm32mp1/images/zImage
readelf -h output/stm32mp1/images/rootfs.ext2 2>/dev/null || true
# 串口:115200 8N1,看到 "Welcome to Buildroot" 即成功

5. 结果检查

检查项预期
产物zImage、dtb、rootfs.ext2 均存在,大小合理
架构file 显示 ARM/ARM64,与目标板一致
启动串口日志出现内核版本与 login
可复现从空目录按记录重跑一次成功

6. 故障排查

现象检查步骤预期结果下一分支
内核不启动串口参数/波特率、镜像地址、U-Boot 环境串口有 U-Boot 输出检查 bootcmd 与 loadaddr
rootfs 挂载失败root= 参数、文件系统类型、MMC 分区内核日志显示挂载成功改用 initramfs 验证
DTB 不匹配dtb 与板卡型号、内核版本设备树解析无报错换对应 dtb 或更新内核

证据边界:命令与产物路径为 principle;实板启动、镜像烧录需硬件验证(hardware-pending)。
