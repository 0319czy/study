中断与 NVICInterrupt & NVIC

中断是外设在需要你时敲一下 CPU 的门：CPU 立刻放下手上的活去处理，处理完再回来接着干。

1 个交互实验 3 道小测验默认 STM32F407 / STM32G474（Cortex‑M4F）

学习目标

  • ·能说清一次中断从"外设置挂起"到"ISR 返回"硬件替你做了哪几件事
  • ·会区分抢占优先级与子优先级，知道 PRIGROUP 在决定什么
  • ·能用 HAL 把 EXTI 按键中断从底层寄存器一路配到回调函数
  • ·写出短、不阻塞、标志清干净的 ISR，并把耗时处理搬到主循环

一句话解释

中断是外设在需要你时敲一下 CPU 的门：CPU 立刻放下手上的活去处理，处理完再回来接着干。

生活化比喻

中断像公司前台：门铃响了才处理，重要客人可以插队

CPU 就是正在写方案的你，门铃是外设发出的中断请求，前台是 NVIC：她记着"哪些门铃允许响"（使能）、"哪个客人更急"（优先级）。普通客人来了，她在便签上排好队，等你写完当前这段；老板来了，她直接敲门打断你（抢占）。你起身前会把笔、本子、手机按固定顺序放进抽屉（压栈 8 个字），回来再一件件拿出来（出栈）继续写——这就是中断现场的保护与恢复。

为什么重要 / 用在哪里

  • 01实时性的来源：轮询把 CPU 时间花在"问有没有事"上，中断只在"真有事"时才花时间，是按键、串口收数、定时采样、电机换相的基础。
  • 02所有外设都靠它收尾：UART 收完一个字节、ADC 转换完成、DMA 传完一半，最终都要落到一个 ISR 或 HAL 回调上。
  • 03排错绕不开 NVIC：程序"卡死""进不去回调""优先级反转"这类问题，八成是使能、优先级分组或标志没清。
  • 04进阶内容的前置：FreeRTOS 的任务切换本质是 PendSV + SysTick 中断，学不会中断就读不懂调度器。

是什么：从轮询到中断

先想清楚"谁在等谁"，中断的每个细节才有落点。

轮询（polling） 是 CPU 主动反复问外设："好了没？好了没？"——问的时候什么正事也干不了。中断（interrupt） 反过来：外设真有事情时主动向内核发请求，内核暂停当前指令流，跳到一段专门的代码（ISR，Interrupt Service Routine，中断服务函数）里处理，处理完回到被打断的地方继续执行。整个过程对主程序是"透明"的：它不知道自己被暂停过。

关键区别在触发方。轮询是软件驱动，延迟取决于循环转多快；中断是硬件驱动，延迟由"外设 → NVIC → 内核"这条硬件通路决定，通常是若干个时钟周期到几十个周期的量级（示意，具体以外设与主频为准）。这也是为什么按键、编码器、串口这类"随机又要求及时"的事件必须用中断。

中断不是"多线程"
Cortex‑M 没有操作系统级的线程概念：ISR 是抢占主程序的一次函数调用，跑完就还回去。所以 ISR 里没有"等待"，也不能假设主程序停在了哪一行；它和主程序共享同一片 SRAM，共享变量必须自己保证可见性（后面 volatile 那一节）。
中断源Interrupt Source
能发出中断请求的东西：外设（EXTI、USART、TIM…）或内核异常（SysTick、PendSV…）。
NVICNested Vectored Interrupt Controller
嵌套向量中断控制器，Cortex‑M 内核的一部分：负责使能、优先级比较、嵌套与向量分发。
EXTIExternal Interrupt/Event Controller
外部中断控制器，把某个引脚的电平跳变变成一条中断线请求。
ISRInterrupt Service Routine
中断服务函数，名字必须与启动文件里的向量表条目一致（如 EXTI0_IRQHandler）。
抢占Preemption
更高抢占优先级的中断可以打断正在执行的 ISR，形成嵌套。

核心机制：一次中断的六步

这条链路上，硬件做了什么、软件该做什么，必须分得清。

从中断请求发生到 ISR 返回，一共六步。前三步是硬件完成的，你写代码只需要保证"请求产生得对、使能给对了、标志清干净"。

  1. 外设置挂起：外设检测到事件（如 EXTI 采到下降沿），把对应的挂起标志置起来，向 NVIC 发出请求。
  2. NVIC 判定：查这条中断线是否使能（NVIC->ISER[]），再把自己的抢占优先级与当前执行优先级比较——够高就立即响应，不够就先排队。
  3. 压栈保存现场：内核自动把 8 个寄存器的值压入当前栈，同时把 LR 写成特殊的 EXC_RETURN 值。
  4. 取向量：按异常编号去向量表取入口地址（向量表基址由 SCB->VTOR 指定），跳到对应 ISR。
  5. 执行 ISR：你在里面读状态、清标志、把数据搬走或置个标志就出来。
  6. 异常返回：ISR 末尾执行 BX LR（编译器自动生成），LR 里的 EXC_RETURN 触发硬件出栈，恢复现场回到被打断处。

压栈的 8 个字固定是：xPSR、PC（返回地址）、LR、R12、R3、R2、R1、R0，共 32 字节。栈从高地址向低地址长，所以内存里从低到高看起来是 R0 在最低、xPSR 在最高。为什么偏偏是这 8 个：R0–R3 与 R12 是传参/临时寄存器（函数调用约定里本来就不保证保留），PC/xPSR/LR 决定"回到哪、以什么状态回"，硬件全包了，所以 ISR 可以写成一个普通的 C 函数。

EXC_RETURN 是一个"魔法返回值"，例如 0xFFFFFFF9 表示返回 Thread 模式、用主栈 MSP；0xFFFFFFFD 表示返回 Thread 模式、用进程栈 PSP（具体取值见 ARM 架构手册）。它保证了"进去时谁压的栈，出来时还回谁"——这也是裸机（全用 MSP）与 RTOS（任务用 PSP）能共用同一套中断机制的原因。

尾链（tail-chaining）与迟到（late arrival）
尾链：一个 ISR 返回时如果已有一条中断挂起且优先级足够，硬件跳过"出栈 8 字 + 再压栈 8 字"，直接进下一个 ISR，省掉十来个时钟周期（示意）。迟到：在压栈阶段（现场还没保存完）更高优先级的请求到了，硬件改为先执行更高优先级那个，返回后再补执行原来的——两个机制都是为了少做无用功，属于硬件行为，你不需要写代码，但看波形时要认得出来。
第 1 层

请求层：谁在敲门

先问：这个事件凭什么能变成一条中断请求？

  • ·引脚级：SYSCFG->EXTICR[] 选端口，EXTI->IMR 放开该线，EXTI->RTSR / EXTI->FTSR 选上升沿或下降沿。
  • ·外设级：USART/TIM/ADC 等在自己的控制寄存器里有中断使能位（HAL 的 HAL_UART_Receive_IT 之类就是替你打开它）。
  • ·挂起标志：事件发生时被置起来，不读不写就一直挂着，这是"反复进中断"的根源。
第 2 层

仲裁层：谁先被接待

先问：同时有多个请求，凭什么按这个顺序处理？

  • ·使能：NVIC->ISER[] 写 1 放行，NVIC->ICER[] 写 1 关掉；没使能的中断挂起也不会进 ISR。
  • ·优先级：NVIC->IP[] 每个中断一个字节，数值越小优先级越高。
  • ·分组：SCB->AIRCR 的 PRIGROUP 字段决定优先级里"几位管抢占、几位管子优先级"。
第 3 层

上下文层：现场怎么保住

先问：被打断的那段代码，回来还能接着跑吗？

  • ·硬件压栈 8 个字（xPSR/PC/LR/R12/R3–R0），出栈由 EXC_RETURN 驱动。
  • ·栈指针自动切换：Thread 模式用 MSP 或 PSP，Handler 模式固定用 MSP。
  • ·中断里再开中断就会嵌套，栈也跟着嵌套——栈太小会直接 HardFault。
第 4 层

处理层：软件该干什么

先问：ISR 里到底应该写几行代码？

  • ·第一件事：清中断标志（EXTI 是 EXTI->PR 写 1 清除，外设一般是读状态寄存器再写清除）。
  • ·第二件事：把数据取走（读 DR/读缓冲）或置一个标志，不做耗时运算。
  • ·耗时工作（滤波、打印、协议解析）交给主循环看标志处理，或用队列把数据递出去。

优先级：抢占与子优先级

这是本页最容易学错的一节：只有抢占优先级能"打断"。

Cortex‑M 的每个中断都有一个 8 位优先级寄存器，STM32 一般只实现其中高 4 位（也就是 16 个等级，具体实现位数以参考手册为准），数值越小优先级越高。真正的坑在于这 4 位不是全都用来决定"能不能打断"：SCB->AIRCR 的 PRIGROUP 字段把它切成两段——高位那段是抢占优先级（preemption priority），低位那段是子优先级（subpriority）。

  • 抢占优先级：决定"能不能打断正在执行的 ISR"。更高（数值更小）就可以抢，形成嵌套。
  • 子优先级：只在多个中断同时挂起时决定谁先执行；它永远不会打断已经在跑的 ISR。
  • 同级不抢占：抢占优先级相同的中断，后来的只能等前面的跑完；即便子优先级不同也一样。
  • 分组是全工程共享的：PRIGROUP 是全局设置，两个模块各自调一次不同分组，后调的会覆盖前面的理解，优先级表现就会莫名其妙。
记住这一条就够了
HAL_Init() 默认把分组设成 `NVIC_PRIORITYGROUP_4`（4 位抢占、0 位子优先级），这时你填的子优先级参数实际上不起作用。新手用 CubeMX 时若在 NVIC 页里改了分组，务必确认所有模块都按同一套理解写优先级，否则"高优先级居然被打断了"会非常难查。

编号怎么来的：Cortex‑M 用"异常编号"统一管理内核异常与外设中断。内核异常占编号 1–15（SysTick 是 15、SVC 是 11、PendSV 是 14），CMSIS 里用负数 IRQn 表示它们（SysTick_IRQn = -1、SVCall_IRQn = -5、PendSV_IRQn = -2）；外设中断从 16 起编号（EXTI0 异常编号 16，即 EXTI0_IRQn = 0）。编号见 ARM 架构手册与所用芯片参考手册的中断向量表，不同系列的外设顺序并不相同。

实战链路：从引脚到回调

以一个按键接 PA0、按下接 GND、下降沿触发为例，走完整条链路。

外部中断最典型的例子就是按键。它的链路是固定的五段：引脚电平 → SYSCFG 选端口 → EXTI 选边沿并放开屏蔽 → NVIC 使能并给优先级 → ISR/回调处理。少任何一段，现象都是"按键没反应"，所以排查时按这个顺序逐段确认最快。

  1. 开时钟：打开 GPIO 端口时钟，以及 SYSCFG 的时钟——EXTI 的"这个线归哪个端口"选择寄存器在 SYSCFG 里，忘开时钟就会选不中引脚。
  2. 配引脚：PA0 设为输入，启用内部上拉（按键另一端接地：松开为高、按下为低）。
  3. 选端口 + 选边沿：HAL 里用 GPIO_MODE_IT_FALLING 一次性完成；底层是写 SYSCFG->EXTICR[] 选定 PORTA，再置 EXTI->IMR 与 EXTI->FTSR。
  4. 配 NVIC：HAL_NVIC_SetPriority 给抢占/子优先级，HAL_NVIC_EnableIRQ 写 NVIC->ISER[] 放行。
  5. 写 ISR：函数名必须与启动文件向量表一致（EXTI0_IRQHandler），里面调用 HAL_GPIO_EXTI_IRQHandler。
  6. 清标志并处理：HAL 会清 EXTI->PR 再回调 HAL_GPIO_EXTI_Callback；回调里只置标志，真正动作放主循环。
使能同一个 EXTI0 中断的三种写法

三者操作的是同一批寄存器，差别只在"谁替你算地址、谁替你清标志"。

两个容易致命的细节
① 同一条 EXTI 线不能跨端口共用：EXTI0 只能接 PA0 / PB0 / PC0… 中的一个，两个都配会互相抢。② EXTI->PR 是写 1 清除，而有些外设的中断标志是"读状态寄存器再写清零"——清错了地方，表现就是"ISR 只进一次"或"进去出不来"。

ISR 编写规则与前后台分工

中断写得好不好，就看"ISR 有多短"和"共享数据有多稳"。

ISR 的目标只有一个：用最短时间结束战斗。它跑的时候主程序停着，同优先级或更低优先级的中断也进不来，所以任何阻塞、任何长循环都会直接变成系统延迟。常用的架构叫前后台系统（foreground/background）：ISR 当"前台"只负责接客，主循环当"后台"慢慢处理。

  • 必须清中断标志：不清就反复进同一个 ISR，主循环看起来像卡死；优先用 HAL 提供的 xxx_IRQHandler，它已按外设要求清标志。
  • 不要阻塞：HAL_Delay、等标志位、printf、Flash 擦写都不要放 ISR 里。HAL_Delay 依赖 SysTick 中断计数，在某些优先级配置下会死等。
  • 共享变量加 `volatile`：告诉编译器"这个值可能被别处改"，禁止把它缓存进寄存器或被优化掉。
  • 32 位以上或多字段数据要防撕裂：主循环读一半被 ISR 改掉会得到"半新半旧"的值；用临界区（短暂关中断）或双缓冲/队列解决。
  • 耗时处理搬走：ISR 里只置标志或把数据塞进环形队列，主循环 while(1) 里轮询处理，复杂算法、协议解析、UI 刷新都归主循环。
  • 别在 ISR 里打印/调用不可重入函数：调试输出最好改成"置个标志、主循环打印"，或用翻转引脚 + 示波器观察。
优先级反转：中断也会"堵车"
如果低优先级 ISR 里做了一件"高优先级 ISR 也要等的事"（比如都抢同一把软件锁或同一个缓冲），高优先级反而会被拖住。Cortex‑M 上没有优先级继承，解决办法是别在 ISR 里加锁，用无锁的单生产者单消费者队列，或者干脆只置标志。

把这页的链路记住：外设置位 → NVIC 比优先级 → 硬件压 8 字栈 → 取向量 → ISR 清标志置标志 → EXC_RETURN 出栈返回，中间还可能插进尾链与迟到。下一页进入 DMA：让数据搬运也变成"外设自己干活、只在中途和结束时打断你一次"。

常见错误与排查

错误现象怎么查 / 怎么改
ISR 里忘了清中断标志（或清错了寄存器）程序像卡死一样反复进同一个 ISR，主循环几乎不执行；单步调试会发现刚出 ISR 立刻又进去确认清的是"触发源对应的挂起位"：EXTI 是写 `EXTI->PR` 的对应位，外设一般要先读状态寄存器再写清除；优先调用 HAL 的 `xxx_IRQHandler`，别自己另写一套。
在 ISR 里调用 `HAL_Delay()` 做延时/消抖按键偶尔"失灵"、系统整体变卡；若当前 ISR 优先级高于 SysTick，`HAL_Delay` 会直接死等不出来ISR 里只记录时间戳并置标志，消抖与延时全部挪到主循环；确需等待就改状态机，别阻塞。
把子优先级当成"能打断别人"以为给中断设了更小的子优先级就能抢进高优先级 ISR，实测毫无反应；或者两个模块各自设了不同分组，优先级表现前后矛盾记住只有**抢占优先级**决定能否打断，子优先级只影响同时挂起时的排队；`SCB->AIRCR` 的 PRIGROUP 全工程只设一次（通常 `NVIC_PRIORITYGROUP_4`）。
ISR 与主循环共享的变量没加 `volatile`开 -O2 后主循环永远读不到 ISR 更新过的标志，程序"看起来没反应"，改成 -O0 又正常跨中断共享的变量一律 `volatile`；多字节数据再用临界区或队列保护，不要依赖编译器"碰巧没优化"。
只配了 EXTI 却没使能 NVIC（或 ISR 名字写错）引脚边沿确实产生了，EXTI 挂起位也置起来了，但回调永远不执行按链路逐段验证：先看 `EXTI->PR` 有没有置起，再看 `NVIC->ISER[]` 是否使能，最后核对 `EXTI0_IRQHandler` 名字与启动文件向量表是否完全一致。

第 3 题判断进阶

判断：在按键的 ISR（或 HAL_GPIO_EXTI_Callback）里直接调用 HAL_Delay(10) 做消抖是推荐做法，因为 ISR 优先级高、执行起来最快。

记住这三句话

  1. 01中断的完整链路是：外设置挂起 → NVIC 比优先级 → 硬件压 8 字栈 → 取向量 → 执行 ISR → EXC_RETURN 出栈返回，中间还有尾链与迟到两种硬件优化。
  2. 02PRIGROUP 决定几位给抢占、几位给子优先级；只有抢占优先级能打断正在执行的 ISR，子优先级只管同时挂起时的先后，HAL 默认是 4 位抢占。
  3. 03ISR 要短：清标志、取数据、置标志，别阻塞别延时；共享变量加 volatile，耗时处理交给主循环，靠"前台/后台"分工换取实时性。
