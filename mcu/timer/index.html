定时器 / PWMTimer & PWM

定时器就是一台“数时钟周期”的机器：数到设定值就翻输出或触发中断，PWM 则是用它输出占空比可调的方波。

1 个交互实验 3 道小测验默认 STM32F407 / STM32G474（Cortex‑M4F）

学习目标

  • ·说出时基三要素（时钟源 / PSC / ARR）与更新事件之间的关系
  • ·用 f = TIMclk / ((PSC+1)(ARR+1)) 和 CCR/(ARR+1) 手算频率与占空比
  • ·解释影子寄存器与预装载（ARPE）为什么能做到“无毛刺改占空比”
  • ·区分输出比较、输入捕获与单脉冲，知道各自典型的应用场景

一句话解释

定时器就是一台“数时钟周期”的机器：数到设定值就翻输出或触发中断，PWM 则是用它输出占空比可调的方波。

生活化比喻

定时器像一台“带打卡机的跑步机”

时钟是跑步机的节拍：每来一个脉冲，计数器就走一格。PSC 是“每几拍才记一次”，ARR 是“走满多少格就吹哨（更新事件）”，CCR 则是“走到第几格时把开关拨一下”。所以频率由“走满一圈要多久”决定，而 PWM 的高电平时间由“开关在第几格被拨动”决定。秒表的读数只是“走了多少格”，它本身并不知道一秒有多长——一切都是你配出来的。

为什么重要 / 用在哪里

  • 01几乎所有“时间”都来自定时器：PWM 调光与电机调速、串口超时、ADC 定时触发、输入捕获测频测距、RTOS 的时基，背后都是 TIM。
  • 02让 CPU 不再死等：用定时中断或硬件 PWM 代替 HAL_Delay 轮询翻转 GPIO，CPU 才能腾出手做别的事。
  • 03硬件 PWM 效率高、抖动小：软件翻转 GPIO 受中断延迟影响，频率一高就变形；硬件 PWM 由比较器直接驱动引脚，稳定得多。
  • 04调试高频问题就在这几个寄存器里：频率差一倍、占空比跳变、捕获值乱跳，原因基本都能落到 PSC / ARR / CCR 与预装载上。

定时器是什么：一台数数机器

定时器不“知道”秒，它只会数时钟周期；把“数多少个”配好，时间、频率、占空比就都能算出来。

定时器（Timer）本质是一个可编程计数器。STM32 的通用定时器（TIM2、TIM3、TIM4…）都围绕同一套时基：时钟源 → 预分频器（PSC）→ 计数器（CNT）→ 自动重装寄存器（ARR）→ 更新事件（UEV）。计数器每来一个计数时钟就加一（或减一），数到 ARR 就归零、同时产生一次更新事件；更新事件可以触发中断、刷新预装载寄存器，也可以作为 ADC、DMA 的触发源。

计数时钟TIMclk
定时器自己的工作时钟，来自 APB1 或 APB2 总线；注意它不一定等于总线时钟（见下面的注意框）。
预分频器PSC, Prescaler
把计数时钟先“放慢”：实际分频系数是 PSC+1，写入值 0 表示不分频。寄存器是 16 位。
计数器CNT, Counter
真正在跑的计数值；向上模式从 0 数到 ARR，向下模式从 ARR 数到 0，宽度随型号不同。
自动重装寄存器ARR, Auto-Reload Register
一圈的“格数”：计数器数到它（向下模式是数到 0）就重装并产生更新事件。一个周期的计数点是 ARR+1 个。
更新事件UEV, Update Event
计数器溢出/下溢时产生的事件：可置中断标志、把预装载值搬进影子寄存器、触发 ADC 或 DMA。
捕获/比较寄存器CCR, Capture/Compare Register
比较时决定“第几格触发”（PWM 占空比），捕获时用来锁存进入沿那一刻的 CNT 值。

更新事件既可以“默默”刷新预装载寄存器，也可以主动通知 CPU：使能 TIM2->DIER 的 UIE 后，每次计数到 ARR 都会把 TIM2->SR 的 UIF 置位；用 HAL 的 HAL_TIM_Base_Start_IT() 启动，中断回调就是 HAL_TIM_PeriodElapsedCallback()。这就是“用定时器做周期任务”的最小闭环。

时钟没开，后面全是白配
TIM2 挂在 APB1 上，第一步必须用 __HAL_RCC_TIM2_CLK_ENABLE() 打开时钟门控；引脚还得切到对应的复用功能。配置顺序永远是“开时钟 → 配时基 → 配通道 → 启动”，任何一步漏掉，示波器上都是一条直线。

频率与占空比怎么算

两个公式解决 90% 的配置问题：ARR 决定频率，CCR 决定占空比。

先算计数频率：TIMclk 经过 PSC 分频后，计数器每经过 (PSC+1) 个时钟才加一，所以计数频率 f_cnt = TIMclk / (PSC+1)。再算一个周期：计数器从 0 数到 ARR 一共数 ARR+1 个点（0 也算一个点，这是最容易漏掉的 +1），因此一个周期的时间是 (ARR+1) / f_cnt，取倒数就是输出频率。

TIMclk 不是 PCLK1
F4/G4 的规则：APB 预分频系数为 1 时，定时器时钟等于该 APB 时钟；分频系数不为 1 时，定时器时钟 = 2 × APB 时钟。例如 F407 的 PCLK1 = 42 MHz 时，TIM2 的计数时钟是 84 MHz。直接用 42 MHz 去算，频率正好差一倍——这是定时器最经典的“算错一倍”问题。

计数模式与影子寄存器

方向决定波形长什么样；影子寄存器决定“改参数时波形会不会抖”。

计数模式由 TIM2->CR1 的 DIR（方向）与 CMS（中央对齐模式选择）决定：向上计数从 0 数到 ARR，向下计数从 ARR 数到 0，中央对齐则先向上再向下、来回折返。模式不同，同一个 PSC / ARR 得到的频率和波形都不一样，换模式必须重算。

为什么电机喜欢中央对齐
中央对齐输出的 PWM 左右对称，一个周期内的高电平被“摊”在中间，相比边沿对齐能降低部分低频谐波与电流纹波（具体效果与开关频率、死区有关）。代价是同样 PSC/ARR 下更新事件的节奏不同，算频率与中断周期时要按手册核对，不能直接套向上模式的公式。

影子寄存器（Shadow Register）是理解“毛刺”的关键。PSC、ARR、CCR 这类参数寄存器大多带一个“影子副本”：你写进去的值先进预装载寄存器，真正被硬件使用的影子寄存器只在更新事件时一次性更新。这样新参数总是在一圈的边界生效，不会落在脉冲中间。

  • 开了 ARR 预装载（ARPE）：运行中改 ARR 调频，新周期在下一次更新事件才切换，不会出现“半个周期长、半个周期短”的异常波形。
  • 开了 CCR 预装载（OC1PE）：运行中改占空比，新比较值在下一次更新事件生效，高电平不会被中途截断或拉长。
  • 不开预装载：写 CCR 会立即参与比较，如果正好落在当前高电平期间，就可能出现一个宽度异常的脉冲——示波器上看到的就是毛刺，电机/灯会抖。
  • PSC 写进去也不是立刻生效：它同样缓冲在更新事件上；用 HAL 的 __HAL_TIM_SET_PRESCALER() 或直接写 TIM2->PSC 后，最好等待（或主动产生）一次更新事件再确认新频率。
一句话记住
ARR 定频率、CCR 定占空比；要在线改，就先开预装载（ARPE / OCxPE），让新值在更新事件生效。 看到“改参数有毛刺”，先查这两个使能位，而不是怀疑芯片。

输出比较、输入捕获与单脉冲

同一个比较器，往外驱动就是 PWM，往里锁存就是测频——方向不同而已。

输出比较（Output Compare）：硬件持续比较 CNT 与 CCR，相等时按配置改变输出引脚。PWM 只是输出比较的一种用法：CNT < CCR 时输出一种电平、CNT ≥ CCR 时输出另一种电平，于是占空比 = CCR/(ARR+1)。输出比较还有“匹配时置高 / 置低 / 翻转 / 冻结”等模式，可以用来产生精确的单次跳变或可调相位的方波。

  • PWM 模式 1：CNT < CCR 时有效电平（通常高），适合 LED、电机这类“高电平有效”的负载。
  • PWM 模式 2：与模式 1 相反，CNT < CCR 时输出无效电平，占空比按“低电平占比”理解，接反相驱动时常用。
  • 匹配翻转（Toggle）：CNT = CCR 时引脚翻转一次，配上一个周期一次比较，就能得到 50% 占空比的方波；配合更新中断还能做简易 DDS 波形。
  • 冻结（Frozen）：比较不改变输出，只产生比较中断，适合“到点提醒 CPU”而不动引脚。

输入捕获（Input Capture）：把引脚上的边沿（上升沿/下降沿）当作“事件”，硬件在事件发生的一瞬间把当前 CNT 值锁存进 CCR，再产生捕获中断。两个边沿之间的计数值差，就是这段时间里走过的计数点数——除以计数频率就是时间，取倒数就是频率。测频、测周期、测脉宽、红外解码、超声波回波测距，全是这个思路。

  1. 配时基：让一个 ARR 周期足够长，至少覆盖待测信号的最低频率（低频要加大 PSC，否则 CNT 会多次溢出）。
  2. 配通道：把通道设成输入捕获、选边沿极性（测频常用上升沿）、必要时加输入滤波抑制毛刺。
  3. 开捕获中断：用 HAL_TIM_IC_Start_IT() 启动，中断里读捕获值；连续两次捕获的差值就是周期对应的计数点数。
  4. 处理溢出：周期比一个 ARR 还长时，要累计更新事件次数再拼出完整时间，否则读到的只是“残差”。

单脉冲（One-Pulse）是输出比较的特殊用法：置位 TIM2->CR1 的 OPM 位后，定时器在下一个更新事件自动停止计数，只输出一个宽度由 CCR 决定的脉冲。它适合“给一个精确的触发脉冲就收工”的场景，比如驱动某些需要单次使能信号的器件、或作为外部器件的精确定时触发。

捕获最容易错的三件事
① 待测频率太低而 ARR 周期太短，CNT 溢出多次却没累计，读数完全不对；② 输入信号有毛刺，没开滤波导致一次边沿被当成好几次；③ 捕获回调里做了耗时操作，下一次边沿来时前一次还没处理完。先用“已知频率的信号源 + 示波器”验证捕获值，再上真实负载。

配置 PWM：六步与代码

顺序有因果：时钟与引脚不对，后面的寄存器和 HAL 调用全部白费。

  1. 开时钟：打开 TIM2 的 APB1 时钟与 GPIOA 的 AHB1 时钟；没开时钟，寄存器写了也不生效。
  2. 配引脚复用：把 PA0 设成复用推挽，并选到 TIM2_CH1 对应的复用号（F4 上 TIM2 是 AF1，以数据手册引脚表为准）。
  3. 配时基：按目标频率算好 PSC 与 ARR，选向上计数，并把 ARR 预装载（ARPE）打开，便于运行中调频。
  4. 配输出通道：选 PWM 模式 1、设初始 CCR（决定初始占空比）、高电平有效，并打开 CCR 预装载（OC1PE）。
  5. 启动：调用 HAL_TIM_PWM_Start()，它同时打开计数器和通道输出；只开计数器不使能通道，引脚不会有波形。
  6. 运行中调参：调占空比用 __HAL_TIM_SET_COMPARE()，调频率用 __HAL_TIM_SET_AUTORELOAD()；两个宏只是写 CCR / ARR，预装载已使能时改动在更新事件生效。
同一路 PWM 的三种写法：HAL / LL / 寄存器

三段做的是同一件事（PA0 上 TIM2_CH1 输出 1 kHz、50% 的 PWM）；省略了错误处理与时钟树配置。LL 函数名与参数以所用 LL 头文件版本为准，寄存器位定义见参考手册 TIM 章节。

  • ?只把 CCR 从 250 改成 750（ARR 不变），频率变了吗？

⚠ 示意值：本页出现的电压、电流、时间、频率、位宽等数值用于帮助理解量级，不代表任何具体芯片的出厂指标。

交互要点：调 PSC / ARR / CCR，实时看频率与占空比怎么变；单步观察 CNT 与 CCR 比较的时刻，理解“占空比就是高电平占一圈的比例”。

频率与分辨率是一对矛盾
同一个计数时钟下，频率越高，一个周期里的计数点越少，占空比能调的档位也越少。84 MHz 下做 20 kHz，一圈约 4200 个点，分辨率约 0.024%（示意）；而做 1 Hz 时一圈要 8400 万个点，16 位定时器（ARR 最大 65535）根本装不下，只能加大 PSC。选参数前先问：要频率精度，还是要占空比精度？

别靠“感觉调对了”：先量频率，再量占空比，最后看边沿。

查时钟门控、复用号、CC1E 与 HAL_TIM_PWM_Start 是否都做到
  • 示波器探头要接地：探头地夹接板上 GND，别只夹信号；长地线会引入振铃，让你误判“PWM 有毛刺”。
  • 先测空载，再带负载：LED、电机、MOS 栅极都会改变边沿形状；空载正常、带载变形时，问题在驱动级而不是定时器配置。
  • 用已知信号交叉验证：拿信号发生器或另一路已知 PWM 去喂输入捕获，先确认“测量链路”没问题，再测真实信号。
  • 别在中断里做重活：更新中断与捕获中断都应短小，耗时操作放到主循环；否则频率一高就丢事件。
定时器还是很多外设的“节拍源”
同一个 TIM 还能给 ADC 提供规则/注入触发、给 DMA 发请求、接编码器做测速。这些用法共用时基与更新事件：改了 PSC/ARR，触发频率也跟着变。做“定时器触发 ADC + DMA 搬运”时，先把 PWM/时基调稳，再接触发链路，出问题才容易定位。

到这里，定时器的主线就完整了：时钟 → PSC → CNT → ARR/更新事件 构成时基，CCR 比较负责输出，捕获负责测量。ADC 与 DMA 两页会把定时器串起来：用更新事件触发采样、让数据自己流进内存，CPU 只处理结果。

常见错误与排查

错误现象怎么查 / 怎么改
忘记开 TIM2 时钟或没配引脚复用HAL 函数全部返回 OK，示波器上却是一条直线；读 CNT 一直是 0按“开 TIM 时钟 → 开 GPIO 时钟 → 配复用号 → 配时基/通道 → Start”的顺序逐项核对，先确认 `TIM2->CR1` 的 CEN 已置位。
用 PCLK1 直接当定时器时钟算频率实际频率正好是设计值的一半（或两倍），怎么调 ARR 都对不上F4/G4 在 APB 预分频不为 1 时，定时器时钟 = 2 × APB 时钟；先看时钟树，再用示波器反推实际 TIMclk。
PSC / ARR 忘了 +1，把寄存器值当分频系数频率整体偏高一档，占空比也差一点点，且越小的值偏差越明显记住实际分频 = PSC+1、一个周期 = ARR+1 个计数点；手算完用示波器量一次周期验证。
运行中直接改 CCR/ARR 却没开预装载调光/调速时偶尔出现一个特别窄或特别宽的脉冲，电机抖动、LED 闪烁打开 ARPE 与 OCxPE（HAL 的 AutoReloadPreload 与 PWM 通道配置），让新值在更新事件生效；改 PSC 同样要等更新事件。
输入捕获不处理计数器溢出低频信号测出来频率乱跳，或总是偏大/偏小一个固定量让 ARR 周期覆盖最低待测频率；周期更长时累计更新事件次数再拼时间，并检查捕获中断有没有丢。

第 3 题判断入门

判断：PWM 模式 1、高电平有效，且 CCR1 预装载（OC1PE）已使能时，把 TIM2->CCR1 改成新值，新占空比会在下一个更新事件才生效，因此不会把当前脉冲从中间“截断”而产生毛刺。

记住这三句话

  1. 01时基三要素是时钟源、PSC、ARR 与更新事件：f = TIMclk / ((PSC+1)(ARR+1))，占空比 = CCR/(ARR+1)，两个 +1 都不能漏。
  2. 02ARR 定频率、CCR 定占空比；在线改参数要先开预装载（ARPE / OC1PE），让新值在更新事件生效，才能做到无毛刺。
  3. 03输出比较负责“往外驱动”（PWM），输入捕获负责“往里测量”（测频测周期），单脉冲则是只发一次精确脉冲的特殊用法。
