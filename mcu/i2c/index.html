I²CInter-Integrated Circuit

I²C 只用两根线（SCL 时钟 / SDA 数据），靠开漏加地址，让几十个器件共享一条总线。

1 个交互实验 3 道小测验默认 STM32F407 / STM32G474（Cortex‑M4F）

学习目标

  • ·画出 SCL/SDA 两根线的接法，并说清开漏 + 上拉为什么不是“可选优化”而是硬性要求
  • ·对照波形讲出 START、重复 START、STOP 的电平条件，以及第 9 个时钟上 ACK/NACK 由谁产生
  • ·看到 7 位地址与读/写位，能自己拼出地址字节，并解释 10 位地址为什么占两个字节
  • ·能按“写寄存器地址 → 重复 START → 读数据”的流程读懂一帧传感器读数，并知道用 HAL_I2C_Mem_Read 怎么实现

一句话解释

I²C 只用两根线（SCL 时钟 / SDA 数据），靠开漏加地址，让几十个器件共享一条总线。

生活化比喻

一根被弹簧拉高的绳子，谁都能往下拽

把 SDA 想成一根绷在弹簧上的绳子：每个器件手里只有一个“往下拽”的钩子（开漏的下管），没有人能主动往上推。大家都松手时，弹簧（上拉电阻）把绳子拉回高处，这就是逻辑 1；任何一个器件一拽，绳子就到低处，这就是逻辑 0。正因为“不能往上推”，两个器件同时动手也不会打架——这就是 I²C 敢让几十个器件挂在同一根线上的底气。

为什么重要 / 用在哪里

  • 01传感器世界的默认总线：温湿度、气压、加速度计、OLED、EEPROM、RTC 大量使用 I²C，学会一页就能对接一大类模块。
  • 02两根线的代价最低：引脚宝贵的封装里，I²C 用 2 个脚挂 100 多个地址，比 SPI 省片选、比 UART 省线。
  • 03它把“总线”的概念讲透了：线与、仲裁、ACK、时钟延展，这些机制在 CAN、USB 里会以别的形式再出现一遍。
  • 04调试里最容易翻车的地方：没上拉、地址错、总线被拉死，占了 I²C 故障的绝大多数——会查比会写代码更值钱。

两根线：SCL 与 SDA

先建立物理图像：谁驱动、谁释放、高电平从哪来。

I²C（Inter-Integrated Circuit，内部集成电路总线）由 Philips（现 NXP）提出，是同步、多主多从、半双工的串行总线：SCL 负责时钟，SDA 负责数据，两者都是开漏（open-drain）+ 上拉电阻。主机产生时钟并决定“什么时候开始说话”，从机靠地址被选中；同一时刻总线上只能有一个方向在传数据，所以说它是半双工。

SCLSerial Clock
时钟线，由主机（或正在延展时钟的从机）拉低；高电平由上拉提供。
SDASerial Data
数据线，双向；同一时刻由发送方驱动，接收方只读。
开漏open-drain
输出级只有下管：写 0 拉低，写 1 等于“放手”，高电平全靠外部上拉。
上拉pull-up
把总线在无人驱动时拉到高电平的电阻；它的阻值决定边沿快慢与功耗。

开漏的本质：器件写 1 时并不是“输出高电平”，而是把引脚放开（高阻），让上拉电阻把线拉到 VDD。所以总线的实际电平是“所有器件拉低动作的逻辑或”：只要有一个器件在拉低，线就是低；全体放手，线才是高。这叫线与（wired-AND）。

  • 必须开漏的理由一：线与，避免短路。 如果改用推挽，一个器件推高、另一个拉低，等于把 VDD 和 GND 通过两只导通的管子短接，电流会烧引脚。开漏下“拉低”是唯一主动动作，物理上不可能互相顶牛。
  • 必须开漏的理由二：多主仲裁只能这么实现。 仲裁要能发现“我发的是 1，线上却是 0”——只有“1 = 放手”时，这件事情才有意义，输的一方也能立刻放手而不损坏任何东西。
  • 必须开漏的理由三：电平转换。 上拉到哪个电压，高电平就是哪个电压。3.3 V 器件和 5 V 器件可以挂同一条总线（前提是器件手册允许），因为 3.3 V 器件从不去“推高”，不会和 5 V 上拉对顶。
一句话区分：协议 ≠ 电平标准
I²C 是协议，不是电平标准：它规定了“两根线怎么配合、帧长什么样、ACK 怎么回”，而“高电平要几伏、上升时间允许多大”由规范里的电气章节和你选的器件共同约束。同理，RS232/RS485 是电气标准，Modbus 是应用层协议（协议总览页有完整四层框架）。

2 根（SCL / SDA）+ 共地

拓扑

事务时序：START 到 STOP

这一节是 I²C 的语法：什么时候算开始、什么时候算一字节、谁在第 9 个时钟说话。

数据有效性规则先定下来：SCL 为高电平期间，SDA 必须保持稳定（接收方就在这个窗口采样）；SDA 只允许在 SCL 为低时改变。唯一例外就是 START 与 STOP——它们故意在 SCL 高时让 SDA 跳变，从而和普通数据位区分开。

以下三种总线状态是 I²C 规范的定义（不是“约定俗成”）：

  • START（启动）：SCL 保持高电平时，SDA 由高变低。总线从空闲进入占用，后面的第一个字节一定是地址。
  • 重复 START（Repeated START，写作 Sr）：一次事务中途不发 STOP，直接再制造一次“SCL 高时 SDA 高→低”，相当于“换个话题继续聊”。典型用途是把“写寄存器地址”和“读数据”接到一起，且不让别的潜在主机插进来。
  • STOP（停止）：SCL 保持高电平时，SDA 由低变高。总线回到空闲，任何主机都可以重新发起 START。

7 位地址怎么拼：地址帧是 8 位 = 7 位从机地址 + 1 位方向位。方向位 0 表示主机写（主机→从机），1 表示主机读（从机→主机）。所以手册里写“地址 0x48”通常指 7 位值，总线上实际出现的是 0x48<<1 | 0 = 0x90（写）或 0x91（读）。HAL 要的是已左移的 8 位形式，这是新手最常见的地址错误来源。

10 位地址一句话：为地址空间不足而扩展，第一个字节用 11110 作前缀带上 2 位高位地址与方向位，第二个字节补上剩下 8 位——也就是一次寻址要吃掉两个字节，且重复 START 后仍要再发一遍。日常接传感器基本用不到，见到 0x78 这类“看起来像 8 位地址”的值先确认它是不是已经左移过的 7 位地址。

ACK / NACK 发生在每个字节之后的第 9 个时钟：发送方发完 8 位后释放 SDA（开漏让它被上拉为高），接收方如果想“收到了”，就在这第 9 个时钟把 SDA 拉低，这就是 ACK；如果保持放手让 SDA 为高，就是 NACK。所以“谁拉低 SDA”永远是这个字节的接收方：地址字节阶段是从机，主机读数据阶段是主机自己。

  • NACK 含义一：从机不在。 地址阶段没人应答，通常意味着地址算错、器件没上电、没接上拉或总线被拉死。主机应放弃本次事务（发 STOP 或重新 START），HAL 会返回错误。
  • NACK 含义二：主机不想再收了。 读数据时，主机在最后一个字节回 NACK，是正常的结束信号，告诉从机“够了，我要发 STOP 了”。这不是出错。
  • 从机也可能回 NACK：写数据时若从机内部忙或缓冲区满，它可以不应答，主机据此决定重试或放弃。

单步走一遍 START → 地址 → ACK → 寄存器 → 重复 START → 数据 → STOP；试着改上拉强弱，看上升沿怎么变慢。

别把 START/STOP 当“电平标准”
START 和 STOP 是总线状态的迁移条件，判断依据是“SCL 高电平时 SDA 往哪个方向跳”。用逻辑分析仪抓波形时，I²C 解码器找的就是这两处跳变；如果一段数据里出现“SCL 高时 SDA 跳变”，解码器会认为这里有一个 START 或 STOP——这也是毛刺最容易造成误帧的地方。

延展、仲裁与电容上限

三个机制解释了 I²C 的能力边界：能等、能抢、但不能太长太快。

时钟延展（clock stretching）：从机来不及处理时，可以在 SCL 为低的阶段把 SCL 拉住不放，主机释放 SCL 后必须检测到 SCL 真正变高才继续。这是 I²C 里少见的“从机反控主机”，也是慢速传感器（如正在做一次转换的温度计）能与高速主机共存的原因。注意 HAL 里有个 NoStretchMode，把它设成“禁用延展”会让这类从机直接被判超时。

多主仲裁（arbitration）：两个主机同时发 START、同时发地址时，双方逐位比较 SDA：每个主机一边发一边读回总线电平。发 1（放手）却读到 0 的那一方，当场输掉仲裁，立刻停止驱动 SDA，转为监听（通常切到从机接收模式），赢家完全感知不到有人抢过。因为“0”会盖住“1”（线与），地址数值小的那一方自然胜出，而且整个过程不丢任何一位数据——这叫无损仲裁。

  • 仲裁的前提是开漏：只有“1 = 放手”时，输家才能毫无副作用地退出；推挽输出一旦对顶就是短路。
  • 仲裁比的是地址与数据位，不是“谁先发”——先发的一方只是先占线，位比较仍按位进行。
  • 单主系统也用得上：总线上只要存在第二个可能发起传输的器件（多主、或多核系统），就必须按仲裁规则设计。

总线电容是硬上限：I²C 规范对一条总线的总电容设了上限（具体数值以规范原文为准），它由器件引脚电容、PCB 走线、排线/杜邦线共同贡献。电容越大，同样的上拉电阻下上升沿越慢，高电平可能还没到就被采样，或者直接违反规范允许的上升时间——于是表现为“器件少时正常、一挂多就偶发 NACK”。长线、多器件、大上拉，三者只能取其二。

  • 上拉太小（R 小）：边沿快，但器件拉低时要灌入更大电流，功耗升高，还可能超出引脚的灌电流能力。
  • 上拉太大（R 大）：省电，但上升沿变慢，容易撞上规范允许的最大上升时间，速率与挂载数量都受限。
  • 没有唯一“正确阻值”：它被“最大上升时间”和“最大灌电流”两头夹住，还要算上总电容，必须按规范公式核算后再实测波形确认。
不要背数字，要会算
本页刻意不给“上拉应为 X kΩ、上升时间应为 Y ns”这类具体值：它们随总线电容、供电电压、器件灌电流能力而变，抄一个数字往往比不抄更危险。正确做法是拿规范里的电气表格 + 你板子的实测上升时间互相验证。

读传感器：写地址再读数据

把前面的时序拼起来，就是每天都在用的“读一个寄存器”。

绝大多数 I²C 传感器内部是一张寄存器表（谁是谁、地址多少，看器件手册的 register map）。主机想读温度，实际动作是：先告诉从机“我要访问哪个寄存器”，再让从机把这个寄存器的内容送回来。中间必须用重复 START 换方向，而不是 STOP 后再 START——否则中间可能被别的主机插队，且多一次总线释放。

  1. START：主机拉低 SDA 抢占总线。
  2. 发地址 + 写位（0）：等从机在第 9 个时钟回 ACK。
  3. 发寄存器地址：1 个字节（也有器件用 16 位寄存器地址，那就发 2 个字节），从机 ACK 后内部指针指向该寄存器。
  4. 重复 START：不发 STOP，直接再起一次，方向准备翻转。
  5. 发地址 + 读位（1）：从机 ACK，随后由从机驱动 SDA 逐位送出数据；主机每收一字节回 ACK，最后一字节回 NACK。
  6. STOP：主机释放总线，事务结束。
同一件事（读一个寄存器）的三种写法

三种写法操作的是同一组寄存器，区别只在“谁帮你串流程”。注意：F4 与 G4 的 I²C 实现不同（时序计算与状态位命名都不一样），本页寄存器写法用允许的 `I2C1->CR1/CR2/OAR1/CCR/TRISE/ISR/ICR/DR` 拼骨架，**真实位定义必须对照你手上系列的参考手册**。

`HAL_I2C_IsDeviceReady` 是排查神器：它只做“START + 地址 + 看有没有 ACK”，不读数据。写业务代码前先让它通过，能把“地址错 / 没上拉 / 没上电”三类问题和“寄存器读错”彻底分开。

配置顺序与上板排查

同样的代码在别人板子上能跑，在你板子上不行，通常差在这六步里的某一步。

  1. 确认引脚复用：查数据手册引脚表，确认 PB8/PB9 之类引脚确实能复用成 I2C1，且复用编号正确；换系列或换封装都要重查。
  2. 把引脚配成复用开漏：GPIO_MODE_AF_OD，速度别选最低档；上下拉先按“外部上拉已就位”处理。
  3. 评估上拉：数一下总线上器件与走线，按规范的最大上升时间与器件灌电流能力核算，先算再实测。
  4. 配外设参数：速率（100 kbit/s 标准模式 / 400 kbit/s 快速模式量级）、7 位或 10 位寻址、允许时钟延展。
  5. 探活：用 HAL_I2C_IsDeviceReady 以正确（已左移）的地址确认从机应答，再进入业务读写。
  6. 读一条已知值：读 WHO_AM_I 这类固定值寄存器比对，能立刻区分“通信不通”和“寄存器理解错”。
调试顺序：先量电平，再抓波形，最后怀疑代码
① 万用表量空闲时 SCL/SDA 是否都被拉到 VDD——不是高电平，先怀疑上拉和供电；② 示波器/逻辑分析仪看有没有 START、地址后第 9 个时钟是不是低（ACK）；③ 才去看代码里的地址是否左移、寄存器号是否抄对。这个顺序能把排查时间压到最短。

兜底手段：总线卡死时怎么救。如果从机在传输中途被复位（比如你的 MCU 比从机先上电、或调试时反复复位），从机可能一直拉着 SDA 等时钟，表现为 BUSY 永远置位、每次传输都超时。标准做法是：手动把 SCL 当作 GPIO 敲 9 个以上时钟脉冲，让从机把剩下的位移完，再补一个 STOP，然后重新初始化 I²C 外设。很多 HAL 版本也提供 HAL_I2C_DeInit + 重新 HAL_I2C_Init 的复位路径作为临时手段。

常见错误与排查

错误现象怎么查 / 怎么改
SDA/SCL 没接上拉，或只靠内部弱上拉什么数据都读不到，`HAL_I2C_Mem_Read` 返回 HAL_TIMEOUT 或 HAL_ERROR；用示波器看空闲电平可能只有 1 V 出头，上升沿“圆头”很慢先量空闲电平：开漏释放时两根线都应该是接近 VDD 的高电平。不是就补外部上拉（按总线电容与规范上升时间核算），并把引脚模式确认为复用开漏。
地址没左移，或把 8 位地址当 7 位地址用每次传输都在地址字节后的第 9 个时钟收到 NACK，`HAL_I2C_IsDeviceReady` 一直失败；换个地址写法（如 0x48 与 0x90）就通了HAL 的 DevAddress 要的是“7 位地址左移一位”。先用 `HAL_I2C_IsDeviceReady` 扫一遍 0x08–0x77，找到真正应答的 7 位地址再写进代码；注意有些模块丝印写的是已左移的值。
总线被拉死（SDA 一直为低，BUSY 不释放）上电后第一次传输就超时，之后所有操作都返回 HAL_BUSY；示波器上 SDA 恒定低电平，SCL 空闲高多半是从机在传输中途被复位，正拉着 SDA 等第 9 个时钟。把 SCL 临时切成 GPIO 手动发 9 个以上时钟脉冲 + 一个 STOP，再重新初始化外设；长期方案是让从机先于 MCU 完成上电，或加电源监控。
把 NACK 一律当成“通信故障”读最后一个字节时收到 NACK，代码里报错退出，结果永远读不到数据分清阶段：地址阶段的 NACK 才是“没人应答”；主机读数据时最后一字节回 NACK 是**正常的结束标志**。用 `HAL_I2C_Mem_Read` 时这件事由 HAL 自动完成，不要自己在回调里把它当错误。
禁用时钟延展，或超时设得过短平时能读，器件做转换时偶发 HAL_TIMEOUT/NACK；降低速率后症状减轻保持 `NoStretchMode` 为允许延展，并把 Timeout 按器件手册的最长转换时间留足余量；若从机确实不支持延展，就降低速率或拉长轮询间隔。

判断：主机读传感器时，最后一个字节由主机回 NACK，这说明从机出错或数据没收到。

记住这三句话

  1. 01两根线 + 开漏 + 上拉 = 一条“谁都能拉低、谁都不能推高”的线与总线；开漏不是省事，而是线与、多主仲裁、电平转换三件事的共同前提。
  2. 02START/重复 START/STOP 的本质是“SCL 高时 SDA 跳变”；每字节后的第 9 个时钟由接收方拉低 SDA 表示 ACK，NACK 可能意味着“没人在”也可能意味着“主机不想再收”。
  3. 03读传感器永远是“写寄存器地址 → 重复 START → 读数据”；上拉阻值由总线电容与上升时间决定，先算再实测，别抄数字。
