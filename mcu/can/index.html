CAN / CAN FDController Area Network

CAN 把一堆节点挂在两根差分线上，靠“ID 越小越优先”的逐位仲裁抢总线，抢输了的数据也不丢。

1 个交互实验 3 道小测验默认 STM32F407 / STM32G474（Cortex‑M4F）

学习目标

  • ·说清 CANH/CANL 的差分电平：显性位为什么是逻辑 0、隐性位为什么是逻辑 1，以及终端电阻为什么要两端各一个
  • ·对照帧格式表，从 SOF 到 EOF 逐段说出作用与长度，并讲清“显性覆盖隐性”为什么让仲裁无损、ID 越小优先级越高
  • ·把位时间拆成同步段 + 传播段 + 相位缓冲段 1、2，写出位时间与波特率的关系并说明采样点的位置
  • ·遇到“发不出去 / 收不到 / 一上总线就报错”时，能按终端电阻、位定时、ID 冲突、过滤器四项排查

一句话解释

CAN 把一堆节点挂在两根差分线上，靠“ID 越小越优先”的逐位仲裁抢总线，抢输了的数据也不丢。

生活化比喻

CAN 像一场“按优先级抢话”的电话会议

会议室里没有主持人，谁想说话就开口。两个人同时开口时，他们一个字一个字地比：谁说出的字优先级低（ID 大），谁就立刻闭嘴，让另一个人把这句完整讲完。关键点是——闭嘴的人并没有把话弄坏，他记得自己讲到哪，等下一个人说完、会议室安静了，他再从头讲一遍。所以“抢话失败”不等于“数据丢了”。

为什么重要 / 用在哪里

  • 01汽车与工业的现场总线标准：车身控制器、电机驱动器、电池管理、机器人关节，一根两芯线就能挂几十个节点，布线成本远低于点对点。
  • 02多主 + 无损仲裁是它最值钱的机制：没有主从轮询的开销，紧急消息（ID 小）天然先走，冲突不丢数据、不需要应用层重传。
  • 03差分传输抗干扰：两根线同进同退，电机、继电器、点火线圈的共模干扰会被差分接收器抵消，这是它能上车的原因。
  • 04它是理解“总线错误处理”的最佳样本：错误帧、错误计数器、主动/被动/总线关闭这一整套机制，是嵌入式可靠通信的通用思路。

两根线：差分、显性与隐性

CAN 的所有“神奇”都建立在一条差分总线的两个状态上。

CAN（Controller Area Network，控制器局域网）是一条多主、广播式的差分总线：总线上的节点没有地址，谁都能在总线空闲时开口；一帧数据发出去，所有节点都能收到，收不收取决于各自的过滤器（filter）。物理上是两根线 CANH 与 CANL，两端各接一个120 Ω 量级的终端电阻，中间可以挂很多节点——标准的线型（总线型）拓扑，不是星形也不是环。

显性位Dominant bit
逻辑 0。收发器主动把 CANH 拉高、CANL 拉低，两根线之间出现明显差分电压（量级约 1.5–3 V，具体看收发器手册）。总线上只要有一个节点发显性，整条线就是显性。
隐性位Recessive bit
逻辑 1。收发器“放手”，终端电阻把两根线拉回同一电位，差分电压接近 0 V（量级）。没有任何节点驱动时，总线就是隐性。
终端电阻Termination resistor
总线两端的 120 Ω 量级电阻，用来吸收信号反射、给隐性位提供泄放回路。两端各一个，并联后从线间量到的是 60 Ω 量级。
仲裁Arbitration
多个节点同时开口时，用“显性覆盖隐性”的逐位比较决定谁继续发，输的一方立即退出并稍后重发。

显性覆盖隐性是后面一切机制的物理基础：多个节点同时驱动时，只要有一个发 0，总线就是 0——相当于“低电平赢”。这条规则在电气层就已经决定了仲裁的结果，不需要软件参与。

线数与信号
CANH / CANL 两根差分线；两端收发器仍需公共参考地，地电位差大或强干扰场合改用隔离收发器
拓扑
线型总线，节点用短支线（stub）挂上去，支线越短越好
终端
总线物理两端各一个 120 Ω 量级电阻，中间节点不加
速率与长度
经典 CAN 上限 1 Mbit/s；速率越高可用的总线长度越短（1 Mbit/s 量级时几十米量级，示意）
节点数
受收发器驱动能力与总线负载限制，常见几十个节点量级
典型场景
汽车车身/动力总线、电机与电池管理、工业设备、机器人关节
为什么差分会比单端抗干扰
干扰通常以“共模”形式同时耦合到两根线上：CANH 和 CANL 一起升高、一起降低。接收器只看两者之差，共模部分被减掉了。这也是 CAN 能和电机、继电器共处一个机柜的原因——但前提是两根线绞在一起走，分开走线会让共模干扰变成差模干扰。

帧格式：SOF 到 EOF

记不住十几段没关系，先记住“谁开头、谁决定优先级、数据在哪、谁校验、谁应答、谁收尾”。

CAN 有数据帧、远程帧、错误帧、过载帧四种帧。日常通信 99% 是数据帧，下面这张表就是标准数据帧的骨架；扩展帧只是把 11 位 ID 换成 29 位 ID，多插了 SRR / IDE 两个控制位，其余段一一对应。

  • 位填充（bit stuffing）：发送端只要连续出现 5 个同极性位，就强行插入 1 个相反位；接收端按同样规则删掉。目的是保证总线有足够的跳变沿，接收方能持续重同步。
  • DLC 只表示长度，不表示内容：DLC=8 就是 8 字节，负载的含义（温度？转速？命令字？）由应用层约定，CAN 本身不关心。
  • ACK 是“有人收到”而不是“目标收到”：总线上任何节点校验通过都会拉低 ACK 槽，所以 ACK 只证明“至少有一个节点听到了”，不证明你的目标节点处理了它。
  • CRC 与 ACK 都由硬件完成：CPU 只负责往邮箱里塞数据和 ID，剩下的填充、CRC、应答、重发全是 bxCAN 自动做的。
一句话记住 FD 的三处变化
BRS 让数据段提速、DLC 扩展让一帧装到 64 字节、CRC 变长且改用固定填充位（因为数据段速率变了，动态填充算不准）。这三件事合起来，才是 CAN FD“更快更大”的全部秘密。

仲裁：ID 越小，越先说话

这是 CAN 最漂亮的设计：冲突不丢数据、不需要退避算法、不需要应用层重传。

总线空闲时，多个节点可以同时开始发送。它们都先发 SOF（显性），然后逐位送出仲裁段。每送一位，节点都会同时回读总线：如果自己发的是隐性（1），读回来却是显性（0），说明有别人在发 0——自己优先级低，立刻停止发送、退出仲裁，转为接收状态；如果发什么就读回什么，就继续往下发。最后只剩一个节点在发，它拿到的总线完全没被破坏。

  1. 同时开口：节点 A（ID 0x123）与节点 B（ID 0x2A0）在同一时刻检测到总线空闲，都发出 SOF，仲裁开始。
  2. 逐位比较：两个 ID 从最高位开始一位一位往总线上送，每一位都是“线与”的结果——有 0 就是 0。
  3. 分叉点出现：某一位 A 发 0、B 发 1，总线呈现 0。A 回读一致，继续；B 发 1 却读回 0，判定自己输了。
  4. 输者退出、胜者继续：B 立刻停止发送、切到接收；A 不受影响地把这一帧发完（数据段、CRC、EOF 全都正常）。
  5. 输者稍后重发：总线再次空闲时，B 的这帧还躺在发送邮箱里，由硬件自动重发——数据一位都没丢，这就是无损仲裁。

为什么“ID 数值小”就等于“优先级高”
因为数字小的 ID 在高位上更早出现 0，而 0 是显性、会覆盖别人的 1。0x123（二进制 001 0010 0011）与 0x2A0（010 1010 0000）从最高位比，第 2 位就分出胜负：前者是 0、后者是 1，于是 0x123 赢。结论：ID 数值越小，优先级越高，与 ID 的“含义”无关。

工程含义很直接：把最紧急的报文分配最小的 ID。急停、故障、电机过流这类帧给 0x0xx 量级的小 ID；状态上报、诊断这类慢帧给大 ID。反过来，如果两个节点用同一个 ID 发不同的数据，仲裁不会报错（它们会一直“一致”到数据段才可能分叉），结果就是数据被悄悄覆盖——这是设计错误，不是仲裁能救的。

位定时：把一个位切成四段

两个节点必须对“一位有多长、在哪一刻采样”达成一致，否则收到的全是位错误。

CAN 没有时钟线，靠双方各自的位定时（bit timing）对齐。做法是把一个位时间切成若干个时间份额 TQ（Time Quantum），TQ 由 CAN 外设时钟分频得到；再把整个位时间划成四段。接收方在每个位的采样点（sample point）读一次总线，采样点之前的部分用来容忍延迟，之后的部分用来容忍偏差。

  1. 确认 CAN 时钟：查清 CAN1 挂在哪条总线上、当前频率是多少（F407 上 CAN1 在 APB1），这是所有计算的输入。
  2. 选目标波特率与 TQ 数：先按整网约定定下波特率，再选一个合适的位时间 TQ 总数（常见 8–25 TQ 量级，示意），除出每个 TQ 的时间。
  3. 算 BRP：BRP = f_CAN / (波特率 × 位时间总 TQ 数)，取整并核对误差；除不尽就换 TQ 总数重算。
  4. 分配四段：Prop_Seg 按收发器与线缆延迟估（留余量），Phase_Seg1 / Phase_Seg2 用来凑出想要的采样点。
  5. 定 SJW：一般取 1 TQ 起步；晶振误差大或总线长时可以适当加大，但不得超过 min(Phase_Seg1, Phase_Seg2)。
  6. 写寄存器并进正常模式：置 MCR 的初始化请求 → 配置 BTR → 清初始化请求 → 等 MSR 确认，才能真正收发。
  7. 两节点必须一致：全网的波特率、采样点约定要统一；只改一个节点，它就会用错误帧把整条总线搅乱。
CAN FD 的位定时要配两套
经典 CAN 只有一套位定时；CAN FD 有仲裁段（标称速率）和数据段（BRS 之后的数据速率）两套位定时，各自都要满足采样点与容差要求。G474 这类带 FDCAN 的芯片对应的是 HAL_FDCAN_* 系列接口，寄存器布局与 F407 的 bxCAN 完全不同——本页的寄存器口径按 bxCAN 写，换芯片务必重查手册。

错误处理：错误帧与三种状态

CAN 把“出错”也做成了总线行为：谁出错谁被记账，记多了就自动闭嘴。

CAN 的可靠性不只靠 CRC，还靠每个节点都在监视总线。发送方会回读自己发出的每一位，接收方会检查填充规则、CRC、固定格式位。任何一方发现不对，就立刻发一个错误帧（error frame），把当前这帧“作废”，让全网一起丢弃它，然后由发送方重发。

每个节点内部有两个错误计数器：TEC（Transmit Error Counter，发送错误计数器） 与 REC（Receive Error Counter，接收错误计数器）。发现错误就加（发送侧加得多，接收侧加得少），成功收发就减。计数器决定节点处在哪个状态——这就是“错误主动 / 错误被动 / 总线关闭”的由来。

看到 TEC 一路涨到 255，先查物理层
TEC 快速上涨几乎总是三件事：终端电阻缺失或不匹配、两端波特率/位定时不一致、总线上没有第二个节点应答 ACK。真正的“软件 bug”很少能把 TEC 顶到总线关闭。反过来，如果 REC 一直涨而 TEC 正常，重点查接收侧的采样点、滤波器配置和线缆。
  • 错误帧不携带 ID：它是全网广播的“作废信号”，没有地址，所以不会有人“没收到”。
  • 错误计数器会自己回落：成功收发会让计数器减，短暂干扰能自愈；只有持续故障才会把节点推向总线关闭。
  • 总线关闭是保护而不是故障：一个坏节点如果继续狂发错误帧，会把整条总线拖垮；让它闭嘴，剩下的节点才能继续工作。

动手写：过滤器 + 发一帧

HAL 把 bxCAN 的初始化、过滤器、邮箱都包成了结构体，但“先配过滤器再 Start”的顺序不能颠倒。

这段代码解决三件事：把 CAN1 拉起来并配好位定时 → 加一组过滤器，只收 0x123 → 启动并把一帧 4 字节数据丢进邮箱。注意过滤器必须在 HAL_CAN_Start 之前配好，否则启动瞬间收到的帧会因为没有过滤器而全部被丢弃。

过滤器不是“地址筛选”，是硬件匹配
bxCAN 有若干组过滤器（bank），每组可以配成掩码模式（关心哪几位）或列表模式（精确匹配一串 ID），决定“哪些 ID 进 FIFO0 / FIFO1”。命中过滤器的帧才进 FIFO、才触发中断，其余的在硬件层就被扔掉，不占 CPU。这也是 CAN 能在高负载下仍保持低 CPU 占用的原因。
同一件事（把 CAN1 拉起来）的三种写法

STM32 的 LL 库**没有覆盖 CAN 外设**（LL 只做了 GPIO/RCC/TIM/USART/SPI/I2C 等），所以中间这栏只写得到“时钟与引脚”，bxCAN 本体只能落到寄存器写法——这不是省略，是这套芯片的现实。寄存器名与位定义以 RM0090 的 bxCAN 章节为准。

这一页讲的是“总线本身”。回到整站视角：UART / I²C / SPI 解决的是芯片与外设之间的短距离通信，CAN 解决的是多个节点之间的可靠广播；再往上还有 USB（主机-设备）与以太网（TCP/IP），它们的取舍逻辑完全不同——后续批次会展开。

常见错误与排查

错误现象怎么查 / 怎么改
终端电阻漏接：一个都没接，或只在板子上接了一个桌面上短距离、低波特率时看着能通，一上长线或提高波特率就大量错误帧，TEC 飞涨直到总线关闭；示波器上看波形有明显振铃/过冲断电后用万用表量 CANH 与 CANL 之间的直流电阻：两端各一个 120 Ω 量级电阻时，应量到 60 Ω 量级。量到 120 Ω 说明只接了一个，量到很大说明一个都没接。终端只在总线物理两端加，中间节点不要加。
两个节点的波特率 / 位定时不一致（BRP、TS1、TS2 算错或抄了别的板子的值）单个节点自测（回环模式）完全正常，一接上总线就满屏位错误、ACK 错误，两个节点谁也发不出去；用逻辑分析仪量到的位宽与对方对不上分别算出两边的位时间：BRP = f_CAN / (波特率 × 位总 TQ 数)，再核对采样点位置。确认两边的 CAN 外设时钟频率不同（比如一个 42 MHz、一个 36 MHz）时，不能直接抄同一组参数。用示波器量一位的实际宽度做交叉验证。
ID 冲突：两个节点用同一个 ID 发不同内容同一 ID 的报文时而来自另一个节点：接收端把两个来源当同一个信号，后到的把先到的覆盖掉；如果两者恰好在同一时刻发送且数据不同，还会在数据段分叉、触发位错误与反复重传，抓包表现为“这个 ID 偶尔整帧消失”维护一张全网 ID 分配表（ID、发送节点、周期、含义），抓包按 ID 分组统计来源与周期。仲裁只解决“谁先说”，不解决“谁该用哪个 ID”——同 ID 双发是设计错误，改 ID 或改发送职责。
过滤器没配好：掩码写错、过滤器组没激活、FIFO 分配错发送正常（TSR 显示成功），但 `HAL_CAN_GetRxMessage` 永远拿不到帧、接收中断不触发；或者反过来，收到一堆不关心的 ID 把 FIFO 冲爆先把掩码全部清零做“全通过”测试，确认硬件通路和中断没问题；再逐位收紧掩码。重点查三处：`FA1R` 有没有激活该组、`FFA1R` 的 FIFO 分配、以及标准 ID 在 32 位过滤器里有没有左对齐（`<< 5`）。
总线上只有自己一个节点，却在正常模式下等待发送成功`HAL_CAN_AddTxMessage` 返回成功，但邮箱一直不空、TEC 持续上涨并报 ACK 错误，最后总线关闭CAN 的 ACK 需要至少一个其他节点（或回环）来拉低 ACK 槽。单板调试请把模式改成 `CAN_MODE_LOOPBACK`，或接第二块板/一个 CAN 分析仪。这不是代码 bug，是拓扑缺了应答方。

两个节点在同一时刻检测到总线空闲，各自要发送一帧标准数据帧，ID 分别是 0x120 和 0x121，其余字段（DLC、数据）都不同。按 CAN 的仲裁规则，谁会先把这一帧发完？

第 3 题判断进阶

判断：一个节点进入总线关闭（Bus-Off）状态后，仍然可以继续正常收发，只是会比别人多发一些错误帧。

记住这三句话

  1. 01CAN 是差分多主总线：显性（0）覆盖隐性（1），终端电阻两端各一个 120 Ω 量级；总线空闲为隐性。
  2. 02仲裁逐位比较、ID 数值越小优先级越高，输的一方立即退出且数据不丢，由硬件在总线空闲后自动重发——这就是无损仲裁。
  3. 03位时间 = 同步段 + 传播段 + 相位缓冲段 1、2，波特率 = 1 / 位时间；出错靠错误帧与 TEC/REC 记账，涨过头就进入错误被动甚至总线关闭。
