板级总线与接口Board-level Buses

板级总线是芯片、模块与设备之间的“道路”：1‑Wire、RS485/Modbus、LIN、I²S、SDIO 各管一段。

3 道小测验默认 STM32F407 / STM32G474（Cortex‑M4F）

学习目标

  • ·能按“电气层 / 帧层 / 应用层”拆开 1‑Wire、RS485、Modbus、LIN、I²S，不再把标准、协议、外设混为一谈
  • ·能说出 RS485 的差分、共模范围、120 Ω 终端与半双工 DE/RE 控制，并解释为什么 Modbus 不是电气标准
  • ·能手工组出一帧 Modbus RTU 请求（地址 / 功能码 / 数据 / CRC），并用 CRC16 算出“低字节在前”的校验
  • ·能说出 1‑Wire 的 ROM ID、LIN 的单线主从、I²S 的三线时钟与 SDIO/eMMC 的定位

一句话解释

板级总线是芯片、模块与设备之间的“道路”：1‑Wire、RS485/Modbus、LIN、I²S、SDIO 各管一段。

生活化比喻

板级总线像小区里的几种“路”

1‑Wire 像门铃线：一根线既送电又传话；RS485 像对讲总线：两根双绞线差分传输，路的两头各放一个“吸波器”（终端电阻）；Modbus 像对讲时的用语规范——谁先问、报哪个编号、回几个字；I²S 则像音频专用的三根同步线：一根打拍子（SCK）、一根报左右声道（WS）、一根送数据（SD）。

为什么重要 / 用在哪里

  • 01现场设备几乎都是 RS485 + Modbus：电表、变频器、PLC、温湿度变送器、伺服驱动器……会组帧、会算 CRC，才谈得上“接得上、读得到”。
  • 02板内音频与存储离不开 I²S 和 SDIO：音频 codec、DAC、麦克风阵列走 I²S；SD 卡、eMMC、SDIO 接口的 Wi‑Fi 模组走 SDIO，时钟或数据线一旦接错，表现往往是“无声”或“识别不到卡”。
  • 031‑Wire 与 LIN 是低成本场景的常客：一颗 DS18B20 就能测温度，一根 LIN 线就能管车门车窗；理解时隙与主从调度后，接线和排错都快得多。
  • 04分层能力比背参数更值钱：先判断问题在电气层、链路层还是应用层，才能决定拿万用表、示波器还是逻辑分析仪去查。

先分层：板级总线在讲什么

同样叫“总线”，有的只规定电压，有的规定字节顺序；不先分层，排错一定找错地方。

板级总线与接口，指的是芯片、模块与现场设备之间的连接方式。有的只在一块板内跑（I²S、SDIO、1‑Wire），有的要出机箱、进现场（RS485、LIN）。它们看起来都是“几根线 + 一堆时序”，但解决的问题完全不同：电气层决定线上是什么电压、要不要差分、终端怎么接；帧层决定一帧从哪开始、到哪结束、怎么检错；应用层决定这些字节是什么意思、谁问谁答。

第 1 层

电气层

先问：线上是什么电压？单端还是差分？要终端吗？

  • ·TTL/CMOS 是单端电平，板内几十 cm 到 1 m 量级
  • ·RS485 用 A/B 差分，抗共模干扰，适合长线
  • ·差分总线通常在物理两端各接 120 Ω 量级终端
第 2 层

时序 / 位层

先问：一位多宽？什么时候采样？

  • ·1‑Wire 用“拉低时长”区分钟，主机控制时隙
  • ·UART 靠约定波特率，在每一位中间采样
  • ·I²S 由 SCK 打拍、WS 选声道，属于同步串行
第 3 层

帧层

先问：一帧从哪开始、到哪结束？怎么检错？

  • ·Modbus RTU 用 ≥3.5 个字符时间的空闲分帧
  • ·CRC16 放在帧尾，低字节先发
  • ·LIN 用 break + 同步场 0x55 + PID 定界
第 4 层

应用层

先问：这些字节是什么意思？谁问谁答？

  • ·Modbus 用功能码 + 寄存器地址表达“读/写什么”
  • ·一主多从，主机轮询、从机应答
  • ·异常用“功能码 | 0x80”加异常码回报
主从Master / Slave
主设备发起通信、提供时钟或轮询；从设备只能应答，不会主动抢占总线。
半双工Half-duplex
同一时刻只能一个方向传输；RS485 二线制就是典型，收发要切换方向。
现场总线Fieldbus
把多台设备串在同一条总线上、面向工业现场的通信系统，强调远距离与多节点。
终端电阻Termination Resistor
接在差分总线物理两端、用于吸收信号反射的电阻，常见 120 Ω 量级。
三个词，三层意思
RS485 / RS232 / TTL 是电气标准（电压、差分、距离）；Modbus 是应用层协议（地址、功能码、数据、CRC）；USART 是 MCU 里的外设（负责移位、采样、中断）。把 RS485 叫“协议”、把 Modbus 叫“电平”，排错时就会查错层。LIN 稍特殊：它是一套同时定义物理层与通信规则的完整规范，所以常被整体称作“协议”。

1‑Wire：一根线兼供电和通信

一根数据线，既传时钟信息又传数据，还能“偷电”——代价是时序极其严格。

1‑Wire 只用一根数据线（再加一根地）就能挂多个器件：总线开漏 + 上拉电阻，空闲为高；主机把线拉低产生时隙（time slot），用拉低的时长表示 0 或 1；器件只在主机“提问”的时隙里回答。因为所有器件共用一根线，同一时刻只能有一个在说话。

每次通信前，主机先发一个较长的复位脉冲，线上器件回一个存在脉冲（presence pulse），表示“我在”。每个 1‑Wire 器件出厂都带一个 64 位 ROM ID，主机用搜索 ROM（Search ROM）逐位枚举，遇到 0/1 冲突就靠 ID 位分叉——所以同型号器件挂多个也不会认错。

寄生供电（parasitic power）：总线空闲为高时，器件通过数据线给内部电容充电，靠这点电维持工作，所以可以只接两根线。但温度转换、EEPROM 写入这类动作电流明显变大，单靠上拉电阻供不上，需要强上拉——用一个 MOSFET 在转换期间把数据线直接拉到 VCC；要求更稳时干脆用三线接法，给器件单独供 VDD。

最常见的 1‑Wire 器件是 DS18B20 数字温度传感器：一根线读温度，多个器件可挂在同一总线上，靠 ROM ID 区分，非常适合布线困难的测温点。

  • 上拉电阻：典型 4.7 kΩ 量级（示意），太小增加功耗、太大边沿变慢；以总线电容和器件手册为准。
  • 线长：受总线电容限制，通常几米到几十米量级；线越长、器件越多，边沿越缓，越容易读错。
  • 时序：时隙是 µs 量级，主机拉低 / 释放的时机必须准；读的时候别被长中断打断，必要时关中断或用硬件辅助。
  • STM32 上的两种做法：GPIO 配成开漏输出 + 上拉，软件打时序；或把 USART 配成单线半双工模式，用波特率“凑”时隙（具体引脚与复用见数据手册）。
主机就是时钟
1‑Wire 没有独立时钟线，主机决定一切时序：读时隙由主机拉低启动，器件在时隙内把线保持高或拉低来说 0/1。所以“读错温度”十有八九是时序被打断，而不是传感器坏了。

RS485：差分、终端与半双工

RS485 只回答“电怎么传”：差分、抗干扰、能拉长线；它不规定字节含义。

RS485 用一对差分线 A/B 传信号：接收端看两线电压差判 0/1，而不是单根线对地的绝对电压。干扰会同时耦合到两根线上，差值基本不变——这就是差分抗共模干扰的原理。标准规定的共模范围约 −7 V ~ +12 V（量级，以收发器手册为准），超出这个范围接收器就可能判错，所以长线、跨机柜时常用隔离收发器。

终端电阻不是“随便加一个”：它要接在总线物理两端，阻值接近线缆特性阻抗（双绞线常见 120 Ω 量级），用来吸收信号到达末端后的反射。只在中间节点加终端、或者一条总线加了四五个 120 Ω，都会让总线负载过重、幅度变小。长线还常加偏置电阻（failsafe bias），保证空闲时 A/B 有确定电平，不会收出一堆随机字节。

二线制 RS485 是半双工：同一时刻只能一个方向传，所以收发器有 DE（Driver Enable，发送使能） 与 RE（Receiver Enable，接收使能，低有效）。发送前把 DE 拉高、关掉接收；发完等最后一个字节真正移出移位寄存器（TC，Transmission Complete）再把 DE 拉低，否则最后一位会被截断。STM32 的 USART 支持硬件 DE（CR3 的 DEM 位，把 RTS 引脚复用成 DE，具体引脚见数据手册），也可以用一个普通 GPIO 手动控制。

A/B 接反是 RS485 第一大坑
现象是完全收不到应答，或者收到一堆乱码；换一块板、换一个收发器又好了。不同厂商对 A/B 的标注与极性约定并不完全一致，接线前以收发器手册为准；排查时先交换 A/B 试，再用示波器 / 逻辑分析仪看发送时差分线上有没有波形。

现场还有两件事：地电位差和浪涌。两地相距几十米，地电位可能差出几伏，直接共地会把电流灌进收发器；工程上优先用隔离型收发器（数字隔离 + 隔离电源），并在接口处加 TVS 等防护。

Modbus RTU：跑在 RS485 之上

先把结论说死：Modbus 规定“说什么”，RS485 规定“怎么送”，两者不在同一层。

Modbus 是应用层协议：它定义 PDU（协议数据单元）= 功能码 + 数据，以及这些字节的含义；RTU 模式再在前后加上从站地址和 CRC16，组成 ADU。它最常跑在 RS485 上，也能跑 RS232，还能封装成 Modbus TCP 跑以太网——所以“Modbus 就是 RS485”是错的，RS485 只是它最常用的一条“路”。

Modbus 是主从（Master/Slave）结构：总线上只有一个主机，主机轮流点名，从机只在被点名且地址匹配时应答；从机不会主动发言。从站地址范围 1–247，0 是广播地址（所有从站执行但不回应），248–255 保留。

功能码 03（Read Holding Registers）：请求里给起始地址与数量（1–125 个），响应是 地址 + 03 + 字节数(=2×数量) + 数据 + CRC。功能码 06（Write Single Register）：请求给寄存器地址与 16 位数值，从站执行后原样回显这一帧表示成功。写多个寄存器用 0x10，读输入寄存器用 04，读线圈用 01——先掌握 03 / 06，其余看设备手册。

RTU 靠空闲时间分帧：一帧结束后至少静默 3.5 个字符时间，接收方才认为帧结束。19200 bit/s、8N1 下一个字符约 0.52 ms，3.5 字符约 1.8 ms 量级；波特率高于 19200 时，规范改用固定 1.75 ms 量级。帧内字节之间不能出现这么长的停顿，否则会被切成两帧。

从站出错时不会沉默：它把功能码最高位置 1（03 | 0x80 = 0x83）再跟一个异常码，常见 01 非法功能、02 非法数据地址、03 非法数据值、04 从站设备故障。主机看到 0x83 就该去查请求，而不是继续重发。

再强调一次：Modbus 不是电气标准
Modbus 不管 A/B 差分、不管 120 Ω 终端、不管共模范围；RS485 也不是协议，它不管地址、功能码和 CRC。把这两层混在一起，通信不通时就会在“改波特率”和“换从站地址”之间来回试，却不去查终端和 A/B。
寄存器编号 ≠ 协议地址
设备手册常把保持寄存器写成 40001、40002……这是文档编号，组帧时通常对应协议地址 0x0000、0x0001（减 1）；也有厂商直接用 0 基地址。以设备手册的“寄存器地址表”为准，别把 40001 直接塞进帧里。

LIN、I²S 与 SDIO/eMMC

三个不同场景：车里的低速控制、板上的音频、存储卡与模组。

LIN（Local Interconnect Network） 是单线、12 V、主从的汽车低速总线：一个主节点（通常就是车身控制器）调度，多个从节点应答，速率最高 20 kbit/s 量级（常用 19.2 kbit/s），用来管车门、车窗、后视镜、座椅、雨刮这类“不要求快、但要求便宜”的节点。一帧由间隔场 break + 同步场 0x55 + 保护标识 PID + 数据 + 校验组成，从节点靠同步场校准波特率。它是一套同时定义物理层与通信规则的完整规范。

I²S（Inter‑IC Sound） 是板内音频的同步串行接口，三根线：SCK（位时钟）、WS（字选择 / 左右声道时钟，也叫 LRCLK）、SD（串行数据）。主机产生 SCK 与 WS，从机跟随；Philips 标准里 WS 为低表示左声道，数据 MSB 先发。要同时录和放，需要两根 SD（或 TDM 多通道）。注意 I²S 只传音频采样，codec 的音量、采样率等寄存器通常另走 I²C 或 SPI。

SDIO / eMMC 是面向存储与模组的并行同步接口：SDIO 用 CLK + CMD + DAT0–3（4 位数据），eMMC 可到 8 位数据线，速率到几十 MB/s 量级。它适合 SD 卡、eMMC 芯片、SDIO 接口的 Wi‑Fi 模组。STM32F407 带 SDIO 控制器；G474 是否带 SDMMC 要以具体型号数据手册为准。

接线、配置与抓包：三视角

一段 Modbus 通信要从“电气 → 链路 → 帧 → 应用”四层依次确认，别一上来就改代码。

下面按“从接线到抓包”的顺序走一遍。真正容易漏的不是初始化，而是方向控制与帧边界——它们决定了你收到的是“一帧完整请求”还是“半截数据”。

  1. 先定层：设备是 RS485 差分还是 TTL 单端？需不需要收发器、隔离、终端？先把“路”铺对，再谈协议。
  2. 电气检查：A/B 没接反、两端各 120 Ω 量级终端、共地或隔离、收发器供电正常；用万用表量差分空闲电平，别只量单根线。
  3. 链路参数：波特率、数据位、校验、停止位与设备完全一致。Modbus 规范推荐的默认配置是 19200、8E1（偶校验）；工程上也有大量设备用 8N1，以设备手册为准。
  4. 方向控制：发送前 DE 拉高，等 TC 后再拉低；接收时 DE 保持低。硬件 DE（CR3 的 DEM）能省掉这段软件时序，但要配对引脚极性。
  5. 帧检查：地址、功能码、寄存器地址、数量、CRC 低字节在前；帧间留 ≥3.5 个字符时间的空闲。
  6. 应用检查：对着设备手册的寄存器表核地址与数据类型，读懂异常码；超时后重试要有上限，别在从站掉线时死等。
同一段 Modbus 通信：HAL / 寄存器 / 逻辑分析仪

三个视角看的是同一条总线：HAL 管“怎么配”，寄存器管“配成了什么”，逻辑分析仪管“线上到底发生了什么”。

抓包的正确顺序
用逻辑分析仪时，先看有没有波形，再看位宽，最后才解码：没有波形查 DE、收发器供电、A/B；位宽不对查波特率与时钟源；字节能解出来但 CRC 错，查字节序与“CRC 低字节在前”。差分总线最好用差分探头，或两通道相减，别只夹一根线就下结论。

把这一页收成一张图：电气层决定能不能出门（差分、终端、共模），链路层决定双方听不听得懂（波特率、帧格式），帧层决定这一包是不是给你的（地址、CRC），应用层决定读哪个寄存器。层分清了，工具也就选对了：万用表看供电，示波器看波形，逻辑分析仪解协议，手册查寄存器。

常见错误与排查

错误现象怎么查 / 怎么改
RS485 总线两端没加终端电阻（或到处乱加）短线、低速时正常，线一长或波特率一高就偶发误码、CRC 错，通信时好时坏只在物理两端各接一个 120 Ω 量级终端，中间节点不加；确认线缆是双绞线、特性阻抗接近 120 Ω；用示波器看末端波形有没有过冲 / 振铃。
RS485 的 A/B 接反完全收不到应答，或收到一堆乱码；换一块板、换一个收发器就正常对照收发器手册确认 A/B 定义（不同厂商标注可能相反），先交换 A/B 试；用示波器看发送时差分线上有没有波形，并确认 DE 在发送期间为高。
Modbus 从站地址冲突读一台设备时两台同时应答，数据打架 / CRC 错；或某台设备永远不响应逐台断电或用配置工具改地址，保证 1–247 内唯一；广播地址 0 只执行不应答；主机轮询表里的地址要与设备一一对应。
CRC 字节序搞反（或把多字节字段也按低字节先发）帧内容看起来完全正确，但从站一律不回或回异常；自己算的 CRC 与抓包对不上Modbus RTU 的 CRC **低字节先发**；寄存器地址、数量、数值等字段则是**高字节先发**，只有 CRC 特殊；校验时对含 CRC 的整帧计算应得 0。
DE/RE 切换太早，最后一个字节被截断发送多字节时最后一两个字节丢失或变形；波特率越低越明显；逻辑分析仪看到发送波形末尾被削等 TC（发送完成）再释放 DE，而不是等 TXE；中断 / DMA 发送要在 TxCplt 回调里拉低 DE；切回接收前确认 DE 已为低。

第 3 题判断入门

判断：RS485 二线制是半双工，发送前要把 DE 拉高，等最后一个字节发送完成（TC）后再拉低，否则可能截断数据。

记住这三句话

  1. 01先分层：TTL / RS232 / RS485 是电气标准，Modbus 是应用层协议，USART / I²S / SDIO 是 MCU 外设，三者不能混着叫。
  2. 02Modbus RTU 帧 = 地址 + 功能码 + 数据 + CRC16；CRC 低字节在前，帧间靠 ≥3.5 个字符时间的空闲分隔，它跑在 RS485 等电气层之上。
  3. 031‑Wire 一根线靠时隙与 ROM ID 认器件，RS485 靠差分与两端 120 Ω 终端跑长线，LIN 是车内单线低速主从，I²S 三线传音频，SDIO/eMMC 走并行数据线做存储。
