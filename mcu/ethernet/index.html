以太网Ethernet

以太网用 MAC 组帧、PHY 收发信号，靠 MAC 地址找同网段邻居，靠 ARP 把 IP 换成 MAC。

3 道小测验默认 STM32F407 / STM32G474（Cortex‑M4F）

学习目标

  • ·说清 MAC（数字侧）与 PHY（模拟侧）各管什么，以及 MII / RMII 的差别
  • ·按字段顺序读出一帧以太网，并解释最小帧长 64 字节与填充的来历
  • ·分清半双工的 CSMA/CD 与交换式全双工的差别，知道冲突检测什么时候该关
  • ·在 STM32F407 上用 HAL 读 PHY ID 判断链路是否通，并把 LwIP 放回 TCP/IP 分层里

一句话解释

以太网用 MAC 组帧、PHY 收发信号，靠 MAC 地址找同网段邻居，靠 ARP 把 IP 换成 MAC。

生活化比喻

MAC 是填单发件员，PHY 是运输车队

你要寄一个包裹：先在单子上写清楚收件人门牌（目的 MAC）、寄件人（源 MAC）、里面是什么（类型/长度），再贴一张防调包的封条（FCS）——这是 MAC 干的活，全是数字逻辑，不出芯片。包裹怎么变成马路上的车流、怎么过减速带、怎么在对方小区卸货，是 PHY 干的活，它负责把 0/1 变成双绞线上的电压。两者之间靠一条"装卸货带"（MII / RMII）交接，另有一条电话线（SMI 的 MDIO/MDC）让发件员随时问车队"你到哪了、现在几点"。

为什么重要 / 用在哪里

  • 01工业与物联网设备几乎都有网口：Modbus TCP、MQTT、HTTP、OTA 升级全靠它，网络不通时你得能分层定位到"是线、是 PHY、是 ARP，还是应用"。
  • 02HAL + LwIP 是 STM32 的标准组合：CubeMX 能生成 90% 的代码，剩下最容易错的 10% 正是 PHY 地址、50 MHz 时钟、MAC 地址和双工模式。
  • 03"能 ping 通"和"业务能用"隔着四道关：物理链路 → PHY 自协商 → ARP/IP → TCP/UDP 端口 → 应用协议，不按层查就只能反复重启。
  • 04以太网是"分层 + 组帧 + 校验 + 重传"的样板：学会它，USB、无线、CAN 的分层思路都能对上号。

MAC 与 PHY：谁组帧，谁收发

一颗 STM32 只做了以太网的一半，另一半在板上那颗 24 脚左右的小芯片里。

MAC（Media Access Control，媒体访问控制）在数字侧：它按规则组帧、算 CRC、按目的 MAC 做硬件过滤、用 DMA 把帧搬进/搬出 SRAM，半双工时还负责冲突检测与自动重发。STM32F407 片内的 ETH 外设就是"MAC + DMA 控制器"，它自己不会收发模拟信号。

PHY（Physical Layer Transceiver，物理层收发器）在模拟侧：负责线路编码、差分驱动与接收、自协商、链路状态检测，外面接隔离变压器和 RJ45。它由板厂选型，型号各异——所以本站不写任何具体 PHY 的寄存器地址与参数，一律以你手上那颗 PHY 的数据手册为准。

两者之间有两套接口：数据通路走 MII 或 RMII（并行数据 + 控制信号），管理通路走 SMI（Station Management Interface），只有 MDIO 与 MDC 两根线，MAC 通过它读写 PHY 内部寄存器——读 PHY ID、读链路状态、配自协商都走这条"电话线"。

RMII 的 50 MHz 是最经典的坑
RMII 只有 2 位数据，时钟必须是 50 MHz（2 位 × 50 MHz = 100 Mbit/s）。这颗时钟要由外部提供——板上有源晶振，或从 MCU 的 MCO 引脚输出，并且必须接到 REF_CLK 对应的复用引脚上。时钟没接、接错脚、频率不对时，初始化常常照样返回成功，但一个包都收不到，链路灯也不亮。

一帧的字段顺序与最小帧长

以太网帧是"定长头 + 变长数据 + 定长尾"，每个字段的位置都是硬约定。

线上真实的顺序是：前导码（7 字节）→ SFD（1 字节）→ 目的 MAC（6）→ 源 MAC（6）→ 类型/长度（2）→ 数据（46–1500）→ FCS（4）。前导码与 SFD 是给 PHY 做同步用的，通常不交给软件；软件看到的一帧从目的 MAC 开始，到 FCS 结束。

最小帧长 64 字节：从目的 MAC 算到 FCS（不含前导码与 SFD）至少 64 字节，也就是 6+6+2+46+4。数据字段不够 46 字节时，MAC 硬件自动补零。原因在线缆长度与冲突检测：最早的 10 Mbit/s 共享总线用 512 位时间作为"时隙"（slot time，10 Mbit/s 下约 51.2 µs，可推算、标量级），它约等于信号在最坏情况下走一个来回的时间。帧如果短于一个时隙，发送方可能在发完之后才知道撞了车，那时已经无法重发。所以帧不能太短——这条规则一直保留到今天。

FCS 只检错，不纠错
CRC-32 能高概率发现比特翻转，但不会把错的那一位改回来。校验失败的帧被整帧丢弃：跑 TCP 由重传补上，跑 UDP 就直接丢了。抓包时看到"FCS error / frame check sequence incorrect"，先怀疑线缆、接头、干扰和 PHY 配置，而不是应用代码。

最大帧长（不含前导码与 SFD）通常是 1518 字节；带 VLAN 标签会多 4 字节。超过这个长度的帧叫巨型帧（jumbo frame），需要链路两端都支持——教学阶段先按 1518 记。

冲突检测的过去与现在

CSMA/CD 是共享年代的老规矩，交换式网络里它基本退场了。

CSMA/CD（Carrier Sense Multiple Access with Collision Detection，载波监听多路访问/冲突检测）一句话：半双工共享介质上，先听信道空闲再发、边发边听有没有撞车、撞了就各自随机退避后再来。交换式网络里每个端口是点对点、全双工收发各用一对线，不会发生冲突，所以只有半双工才需要冲突检测——全双工时 MAC 的冲突检测应当关闭。

MAC 地址一句话：48 位，前 3 字节是厂商标识（OUI）、后 3 字节由厂商分配；全 F 是广播地址，首字节最低位为 1 表示组播。ARP（Address Resolution Protocol，地址解析协议）一句话：IPv4 下"已知 IP、要它的 MAC"，先广播问"谁是 192.168.1.1"，被问到的人单播回答，结果进 ARP 表缓存几分钟。

  • 自协商（auto-negotiation）：两端互相通报自己支持的速率与双工能力，取共同最优。两边都开自协商最省事；一端强制、一端自协商，常常协商成"一端全双工、一端半双工"。
  • 双工不匹配的症状：能 ping 通但丢包严重、延迟忽高忽低、交换机侧冲突计数上涨——因为半双工那端会把对方的正常发送当成冲突。
  • MAC 地址必须唯一：两块板子用同一个 MAC，交换机的 MAC 表项会来回震荡，表现为"时通时断"。F407 有 96 位唯一 ID，可以从中派生一个本地管理地址。
MAC 地址不要图省事
很多例程把 MAC 写成固定的 00:00:00:00:00:00 或全 F。全 0 会被部分交换机当成非法源地址，全 F 是广播地址，同一网段放两台就是地址冲突。要么用芯片 UID 派生，要么在生产时烧一个唯一值，别让两台设备抢同一个门牌。

TCP/IP 分层与 LwIP 的位置

以太网只是最底下那层"送 frame"的，上面的 IP、TCP 才是"送到对的程序"。

LwIP（Lightweight IP）的位置：一个"够小到能塞进 MCU"的 TCP/IP 协议栈，可以跑在裸机上，也可以挂在 FreeRTOS 下。它不关心 MDIO 时序、不关心 50 MHz 时钟，只通过 netif（网络接口） 与以太网驱动交换 pbuf（它自己的缓冲区结构）：驱动收帧 → 交给 LwIP → LwIP 查 ARP、剥 IP 头、按端口分发。往上你再选一种 API 写业务。

  • raw / callback API：最省资源，裸机首选，但把"异步收包"写成回调嵌套，可读性最差。
  • netconn API：LwIP 自己的一套阻塞式接口，可在 RTOS 任务里顺序写，比 raw 好懂。
  • socket API：兼容 BSD 风格，移植现成代码最省事，代价是 RAM 与 CPU 开销最大（需要 RTOS）。
  • pbuf 有引用计数：收到包后 pbuf 可能被多层共享，用完必须 pbuf_free；漏掉就是"跑几小时后不再收包"的经典内存泄漏。

在 STM32F407 上把链路拉起来

顺序很关键：时钟和引脚不对，后面所有寄存器配置都是白写。

  1. 开时钟：ETH MAC 在 AHB1 上，要先使能它的时钟；RMII 的 50 MHz 参考时钟则来自板上有源晶振或 MCO 输出，必须真的到引脚上。
  2. 配引脚复用：把 RMII 的 7 根信号线加 MDIO/MDC 配成复用功能，速度和上下拉按手册。
  3. 调 `HAL_ETH_Init`：把 MAC 参数（速率、双工、地址过滤）与 DMA 描述符链表写进寄存器——注意这一步成功不代表链路已 up。
  4. 读 PHY ID 验证 SMI：能读到两个标识寄存器，说明 MDIO/MDC 通、PHY 地址填对了；读回 0x0000 或 0xFFFF 基本就是这两项错了。
  5. 等链路 up：读 PHY 状态寄存器或看板上链路 LED，确认自协商完成、速率与双工一致。
  6. 交给 LwIP：netif 挂上驱动、设 IP/掩码/网关，再发 ARP 或 ping 验证端到端；这一层之后，发一帧就是 HAL_ETH_Transmit，取一帧就是 HAL_ETH_ReadData。
读同一个 PHY 寄存器的三种视角

三条路径最终都落到 `MACMIIAR` / `MACMIIDR` 这一对寄存器上；寄存器视角里的宏名是示意写法，位号请查参考手册 ETH 章节。

F407 不用关心的两件事
DMA 描述符与缓冲区必须放在 ETH DMA 能访问的 SRAM 里（CubeMX 会把它们放到正确段）；F407 是 Cortex‑M4，没有 D‑Cache，所以不存在"收包前要 invalidate cache"的麻烦——那是 H7/M7 才要处理的。看到别人贴 cache 维护代码，先确认芯片是不是 M7。

常见错误与排查

错误现象怎么查 / 怎么改
PHY 地址填错（照抄例程）`HAL_ETH_Init` 返回 HAL_OK，但读 PHY 寄存器读回 0xFFFF 或 0x0000，链路灯不亮、ping 不通按原理图确认 PHY 的地址 strap 引脚（上拉/下拉），把正确地址填进读寄存器的参数；先用 HAL_ETH_ReadPHYRegister 读两个标准 ID 寄存器验证 SMI 通了没有。
RMII 的 50 MHz 参考时钟没接或接错初始化一切正常，但一个包都收不到，`ping` 全超时，PHY 侧链路可能亮也可能不亮确认板上有 50 MHz 时钟（有源晶振或 MCO 输出）确实到了 REF_CLK 复用引脚、幅度与频率正确；先用示波器/频率计量一下这个脚，再怀疑软件。
MAC 地址全 0 或两台设备相同单台能用，接进交换机后时通时断；交换机侧 MAC 表项反复跳变用芯片 96 位唯一 ID 派生一个本地管理 MAC（首字节设置本地管理位），或生产时烧唯一值；调试期也不要用广播地址当源地址。
ARP 不通就怀疑硬件能读到 PHY ID、链路也 up，但 ping 不通，抓包看不到 ARP 应答按层查：IP/掩码/网关是否同网段 → 有没有发出 ARP 请求 → 对端有没有回 → 收到后 MAC 过滤是否把帧丢了；先在同网段直连一台电脑排除路由问题。
双工/速率不匹配（一端强制、一端自协商）能 ping 通但丢包严重、延迟抖动大，半双工那端冲突计数狂涨两端都设为自协商；必须强制时把速率与双工在两端都写成一样的固定值，并同步关掉自协商。

一块 STM32F407 板子上电后 ping 不通。下列哪些做法能帮你判断问题出在物理/链路层还是上层（ARP/IP/应用）？（多选）

第 3 题判断进阶

判断：交换式以太网里每个端口都是点对点、全双工收发各用一对线，不会发生冲突，所以此时 MAC 的冲突检测不需要工作；把“必须开启 CSMA/CD 冲突检测”当成硬性要求是错的。

记住这三句话

  1. 01MAC 管数字（组帧、CRC、地址过滤、DMA 搬运），PHY 管模拟（编解码与差分收发）；MII 是 4 位并行配 25 MHz 量级时钟，RMII 是 2 位并行共用一根 50 MHz 参考时钟，所以线少。
  2. 02一帧 = 前导码 + SFD + 目的 MAC + 源 MAC + 类型/长度 + 数据 + FCS；从目的 MAC 到 FCS 至少 64 字节，数据不足 46 字节由 MAC 补零；冲突检测只属于半双工的共享介质。
  3. 03LwIP 站在链路层之上：netif 收帧 → ARP 把 IP 换成 MAC → IP → TCP/UDP → 应用；"ping 不通"按 物理链路 → PHY ID/自协商 → ARP → IP/掩码/网关 → 端口 的顺序查。
