MCU 基础MCU Basics

MCU 是把 CPU、Flash、SRAM 和一堆外设塞进一颗芯片的“微型电脑”，它靠引脚与外界交换电信号。

3 道小测验默认 STM32F407 / STM32G474（Cortex‑M4F）

学习目标

  • ·能一句话说清 MCU、MPU、SoC 的区别，不再混用三个词
  • ·理解冯诺依曼与哈佛结构对“取指 / 取数”的影响
  • ·知道 Cortex‑M 系列与常见厂商产品线的大致定位
  • ·能完整说出“写一行代码 → 引脚变电平”要经过哪几步

一句话解释

MCU 是把 CPU、Flash、SRAM 和一堆外设塞进一颗芯片的“微型电脑”，它靠引脚与外界交换电信号。

生活化比喻

MCU 像一台“瑞士军刀式”的微型电脑

普通电脑是台式机：CPU、内存、硬盘、显卡各占一块板子；MCU 是把这些塞进一颗指甲盖大小的芯片，还顺手带了定时器、串口、ADC 这些“工具刀”。刀不大，但开瓶、锯木、拧螺丝都够用——这就是它统治小家电、玩具、传感器节点的原因。它甚至不需要操作系统：上电后从 Flash 第一条指令开始跑，跑的就是你写的那段循环。

为什么重要 / 用在哪里

  • 01一切外设配置都建立在这套结构上：时钟给谁、数据走哪条总线、中断怎么进来，都取决于芯片内部怎么连。
  • 02选型与排错的地基：知道 Flash 存程序、SRAM 存数据，就不会再问“为什么变量一多就 HardFault”。
  • 03看懂启动流程：程序为什么从 0x08000000 开始？main() 之前谁干了活？调试时这些都会遇到。
  • 04面试与项目都绕不开：Cortex‑M 内核、哈佛结构、指令集这些是嵌入式岗位的通用语言。

先分清三个名字：MCU / MPU / SoC

这三个词经常被混着用，但它们说的是三件不同的事。

MCU（Microcontroller Unit，微控制器）：一颗芯片里集成 CPU 内核、程序存储器（Flash）、数据存储器（SRAM）、总线以及若干外设。特点是不用外部存储也能独立跑，面向实时控制、低功耗、低成本。STM32、ATmega328P、ESP32 都属于这一类（ESP32 更接近"MCU + 无线 SoC"）。

MPU（Microprocessor Unit，微处理器）：只有 CPU（可能带 cache、MMU），必须外接 DDR 与存储才能工作。它跑 Linux 这类通用操作系统，擅长复杂计算与人机界面，但启动慢、功耗高、实时性靠软件调度。

SoC（System on Chip，片上系统）：强调"把整个系统集成到一颗芯片"，里面可以有 CPU 集群、GPU、NPU、无线基带、DDR 控制器等。ESP32、树莓派用的 BCM 芯片、手机主芯片都是 SoC。MCU 是 SoC 的一种特例（集成度低、资源少、以实时控制为目标）。

一句话记忆
MCU 是"自带干粮的小电脑"，MPU 是"需要外援的大脑"，SoC 是"把一整套系统装进一颗芯片"。看到"要不要外接 DDR"和"跑不跑 Linux"，基本就能判断是哪一类。

芯片里面有什么：冯诺依曼与哈佛

同一颗芯片里，程序和数据放在哪、走哪条路，决定了性能和调试方式。

冯诺依曼结构（von Neumann）：程序和数据共用同一套存储与总线，取指令和取数据要排队。结构简单、灵活，但存在"取指与取数抢总线"的瓶颈。哈佛结构（Harvard）：指令总线与数据总线分开（或至少地址空间分开），可以同时取指和取数。Cortex‑M 采用改进型哈佛结构：片内通过多条总线（I‑Bus / D‑Bus / S‑Bus）并行访问，对外仍是统一地址空间——所以你写 *(uint32_t*)0x40020014 = 1 也能改寄存器。

Flash（程序区）
放代码与常量，掉电不丢；F407 从 0x08000000 开始映射
SRAM（数据区）
放全局变量、栈、堆；掉电即失，容量通常远小于 Flash
总线（AHB/APB）
CPU 与外设之间的"高速公路"，不同总线频率不同
外设（Peripherals）
GPIO / USART / SPI / ADC… 挂在总线上，用寄存器控制
NVIC（中断控制器）
内核的一部分，管理所有中断的使能与优先级
为什么"变量一多就 HardFault"
SRAM 要同时放全局变量、栈和堆。默认启动文件给的栈只有 1 KB 量级（示意），递归太深、局部数组太大就会踩栈。看到 HardFault 时先看 _estack 和 Stack_Size，别急着怀疑外设。

指令集：CISC、RISC 与 Cortex‑M

指令集决定编译器生成什么机器码，也决定了芯片面向什么场景。

CISC（复杂指令集）：单条指令能做较复杂的事，编码长度可变，典型是 x86。RISC（精简指令集）：指令少而规整、长度固定、load/store 架构（只有访存指令能碰内存），典型是 ARM、RISC‑V、AVR。RISC 更容易流水线和低功耗，所以几乎统治了 MCU。

ARM 公司不生产芯片，只卖内核授权：ST 买 Cortex‑M4 内核，加上自己的 Flash、外设和总线，做成 STM32；NXP、GD、Nordic 同理。这也是"不同厂商的 Cortex‑M 芯片寄存器风格不同，但内核行为一致"的原因——内核是同一套，外设各写各的。

  • Thumb‑2 指令集：Cortex‑M 用 16/32 位混合编码，兼顾代码密度与性能；你不需要手写汇编，但调试时看到 0x0800xxxx 的机器码要能联想到它。
  • FPU 不是默认开的：Cortex‑M4F 的浮点单元要在启动代码里使能（__FPU_PRESENT / SCB->CPACR），否则浮点运算走软件模拟，慢一个数量级。
  • RISC‑V 是开放指令集：CH32V、E503 等国产芯片用 RISC‑V 内核，外设寄存器风格往往参考 STM32，迁移成本主要在启动文件、中断入口和工具链。

厂商与系列：选型先看四件事

同是 Cortex‑M4，ST、GD、NXP 的差异主要在外设数量、Flash/RAM 大小、封装、工具链和生态。新手最容易踩的坑是"照着教程买错型号"：教程用 F103，你买成 F407，引脚和时钟树都不一样。

  • 要什么外设：几路 UART？要不要 CAN？要不要 USB？ADC 几位？先列需求再选型。
  • 存储够不够：Flash 决定代码和字库，SRAM 决定缓冲区和 RTOS 任务栈；跑 GUI/网络时 RAM 往往先不够。
  • 封装与引脚：手焊选 LQFP，空间紧选 QFN；引脚数量决定能接多少外设。
  • 生态与工具：有没有现成 HAL/驱动、调试器是否便宜（ST‑Link、DAPLink）、社区资料多不多。
本站的口径
主线固定为 STM32F407 / STM32G474 + HAL，因为它的外设结构与文档最适合讲原理；ESP32 / AVR / RISC‑V 只在对照卡里比较差异，不展开成完整教程。

从一行代码到引脚电平

这是全站最重要的一条链路：你写的每个外设配置，最终都落在这五步上。

  1. 使能时钟：外设挂在哪条总线，就先打开那条总线的时钟门控（如 GPIO 在 AHB1）。没开时钟，后面写寄存器全部无效。
  2. 配置引脚：把引脚设成"通用输出"或"复用功能"，选推挽/开漏、上下拉、速度。
  3. 配置外设：波特率、数据位、采样时间、PWM 频率……这一步决定"协议参数"。
  4. 启动 / 使能：置使能位或调用启动函数，外设开始工作。
  5. 触发与处理：写数据寄存器发送、轮询状态位、或等中断/DMA 回调。

上电之后发生了什么

理解这 6 步，调试"程序没进 main"时就有方向了。

  1. 取栈顶：内核从 0x08000000 读第一个字，作为初始 MSP（主栈指针）。
  2. 取复位入口：从 0x08000004 读第二个字，就是 Reset_Handler 的地址。
  3. Reset_Handler 干活：初始化 .data（从 Flash 复制初值到 SRAM）、清零 .bss、调用 SystemInit() 配时钟。
  4. C 运行环境：__libc_init_array() 跑构造函数（C++ 全局对象、__attribute__((constructor))）。
  5. 进 main()：main() 返回会进入死循环（_exit），所以裸机 main 里必须有 while(1)。
  6. 中断向量表：默认在 Flash 起始处；改过 Bootloader 或重定位时要同步改 SCB->VTOR。
常见"进不了 main"的三类原因
① 时钟没配好就访问外设（总线挂死）；② 栈顶地址被链接脚本写错，一压栈就 HardFault；③ 用了 Bootloader 但没重定位向量表（SCB->VTOR），中断全跑到旧地址。

常见错误与排查

错误现象怎么查 / 怎么改
把 MCU 说成"小 CPU"面试或写文档时把 Flash/SRAM/外设漏掉，讲不清为什么它能独立运行记住定义：MCU = 内核 + 片内程序/数据存储 + 外设 + 总线，能独立跑裸机程序。
以为外设寄存器随时可写没使能时钟就配 GPIO，代码编译通过但引脚毫无反应所有外设操作前先查它在哪条总线、对应哪个时钟使能位；F4 上 GPIO 在 AHB1、USART 多在 APB1/APB2。
直接用绝对地址访问寄存器却不加 volatile开了优化后循环里读状态位永远读到同一个值，程序卡死硬件寄存器必须 `volatile`；更推荐用厂商头文件里的 `GPIOA->ODR` 这类带 volatile 的定义。
照着别的型号教程抄引脚与时钟PA5 在 F407 能用，换到别的封装/系列后引脚不存在或复用不同以自己芯片的数据手册引脚定义 + CubeMX 的引脚图为唯一依据，别跨型号硬搬。
