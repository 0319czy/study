通讯协议总览Protocol Overview

通讯协议 = 电气、时序、帧、应用四层约定的叠加；看懂分层，选型和排错都不会乱。

3 道小测验默认 STM32F407 / STM32G474（Cortex‑M4F）

学习目标

  • ·能用四层框架（电气 / 时序 / 帧 / 应用）拆开任意一个通讯协议
  • ·能说出串行与并行、同步与异步、单端与差分各自的取舍和典型场景
  • ·能分清电气标准、协议、外设三件事，不再说“RS485 协议”
  • ·能按距离 / 速率 / 线数 / 多设备四问，给一个小项目做初步选型

一句话解释

通讯协议 = 电气、时序、帧、应用四层约定的叠加；看懂分层，选型和排错都不会乱。

生活化比喻

通讯协议像寄快递：路、时刻表、运单、包裹

电气层是“路和车”——是乡道还是高速、货车能不能过（电平、差分、能拉多远）；时序层是“发车时刻表”——几点发、几点到、什么时候验货（时钟、波特率、采样点）；帧层是“运单”——收件人是谁、几件、怎么验货（地址、长度、校验）；应用层是“包裹里装的是什么”（温度、转速、一条命令）。四层里换任何一层，都能组合出不同的“协议”，但底层那层的物理限制永远绕不过去。

为什么重要 / 用在哪里

  • 01后面的 UART / I²C / SPI / CAN 都是这套框架的实例：先有框架再看细节，就不会把“波特率”和“电平”混在一句里。
  • 02选型错一次往往要改板子：协议选错不是改几行代码能救的，距离和拓扑在画原理图时就已经定死了。
  • 03排障必须按层来：不通先看电平和地，再看时序和采样点，再看帧里的地址与校验，最后才怀疑应用层——顺序对了，能少走一半弯路。
  • 04纠正一个流传很广的混用：“RS485 协议”“I²C 电平”这类说法在文档和面试里很常见，能当场分层说明才算真懂。

先分层，再看参数

任何通讯都可以拆成四层来问，四层问完，这个协议就懂了七成。

通讯协议（Communication Protocol，通信双方约定的规则集合）这个词常被用得很虚。落到工程上，它其实是四层约定的叠加：线怎么接、什么时候采样、一包数据长什么样、这些字节代表什么。四层里任意一层换了，通常就要换一个名字——TTL 串口和 RS485 串口的差别在电气层；I²C 和 SPI 的差别在电气层与帧层（开漏两线 vs 推挽四线、有地址和 ACK vs 无地址无 ACK）。

第 1 层

电气层

先问：几根线、什么电平、谁驱动？

  • ·单端看“对地的电平”（TTL/CMOS），差分看“两根线的电压差”（RS485/CAN/USB）
  • ·推挽能主动输出高和低（SPI 常用）；开漏只能拉低，高电平靠外部上拉（I²C）
  • ·共地、终端电阻（120 Ω 量级）、总线电容在这里决定“能拉多远、能跑多快”
第 2 层

时序层

先问：位在什么时候被采样？

  • ·同步靠独立时钟线对齐（SPI/I²C），异步靠双方约好波特率（UART）
  • ·每一位的宽度由时钟频率或波特率决定，采样点落在位中间最稳
  • ·时钟极性、采样边沿、建立/保持时间都归这一层
第 3 层

帧层

先问：一包数据从哪开始、到哪结束？

  • ·起始位、地址、长度、校验、停止位都是“包装”，归帧层
  • ·有地址才能多设备共用总线（I²C 的 7 位地址、CAN 的 11/29 位 ID）
  • ·校验（奇偶 / CRC / ACK）决定这一包错了能不能被发现
第 4 层

应用层

先问：这包字节代表什么？

  • ·是温度寄存器、电机转速，还是 Modbus 的功能码，由应用层定义
  • ·同一电气层能跑很多应用层：RS485 上既能跑 Modbus RTU，也能跑自定义帧
  • ·换应用层通常不用改板子；换电气层往往要改硬件
通讯协议Protocol
通信双方对“电气、时序、帧、含义”的整套约定，不是一个函数，也不是某一颗芯片。
电气标准Electrical Standard
只规定电平、线缆、阻抗、距离这类物理层要求，不规定字节含义，如 TTL、RS232、RS485。
拓扑Topology
设备怎么连成网、谁有资格主动发起通讯：点对点、主从、多主。
全双工 / 半双工Full-duplex / Half-duplex
全双工收发可同时进行（UART 的 TX/RX、SPI 的四线）；半双工同一时刻只能一个方向（I²C、两线 RS485）。
一句话记住四层
电气层决定“能不能连上”，时序层决定“什么时候看”，帧层决定“看得懂一包吗”，应用层决定“看懂后做什么”。排查问题时从下往上查，设计方案时从上往下想。

串行并行、同步异步

先看线怎么排（串行 / 并行），再看时钟从哪来（同步 / 异步）。

并行（Parallel）是每一位各占一根线，同时送出；串行（Serial）是一位一位排队，在少数几根线上跑。并行的直觉优势是“一次搬 8 位”，代价是线与线之间会歪斜（skew）：长度不完全一致、延迟不完全相同，频率一高就采样错位，所以并行很难提速。

同步（Synchronous）多一根时钟线，数据什么时候有效由时钟说了算，接收端在时钟边沿采样；异步（Asynchronous）没有时钟线，双方各自用本地时钟按约定波特率收发，靠起始位重新对齐、靠停止位收尾。所以同步只是“更容易对齐”，异步才是“把对齐的压力压到时钟精度上”。

  • 串行不等于慢：USB、PCIe、以太网全是串行，因为并行一提速就被歪斜卡住。
  • 异步不等于不可靠：UART 每个字节都用起始位重新对齐，代价只是每字节多两位量级的开销。
  • USART 名字里两个都有：STM32 的 USART 同时支持同步与异步，同步模式会额外占用一根时钟引脚；平时几乎都当异步 UART 用。

单端与差分：线决定距离

差分是“能拉远”的关键，代价是线数与收发器。

单端（Single-ended）一根信号线，电平相对地来判断：TTL 串口、I²C、SPI 都是单端。差分（Differential）用两根线传互补信号，接收端只看两者之差：RS485、CAN、USB、以太网都是差分。差分的价值不是“两根线更快”，而是共模干扰在相减时被抵消。

单端系统的瓶颈常常不在芯片，而在“线”：开漏输出只能拉低，高电平靠外部上拉慢慢充上去，上拉电阻 R 与整条总线的电容 C 就构成一个 RC，上升时间随电容线性变差。这也是 I²C 挂的器件越多、线越长就越容易出错的原因。

代入数字感受量级：R = 4.7 kΩ、C = 200 pF 时，t_r ≈ 0.847 × 4.7 kΩ × 200 pF ≈ 0.8 µs（示意）。而快速模式对上升时间的上限在几百纳秒量级（以 I²C 规范原文为准）。所以挂得多、线又长时，要么减小上拉（更费电、灌电流更大），要么减小总线电容（更短的线、更少的挂载），要么降速——上拉不是越大越省电越好。

差分不是万能药
RS485 不双绞、终端电阻（120 Ω 量级）不接，照样会被反射和干扰搞崩。差分解决的是共模干扰，不解决阻抗不匹配；单端解决不了的问题，换差分之前先确认线材和终端，否则只是把问题换个方式呈现出来。

拓扑：谁能发起对话

拓扑回答两件事：设备怎么连成一条网，以及谁有资格开口。

拓扑（Topology）在选型里的分量常被低估。它决定“多设备时会不会打架”，和速率、距离同等重要：同样是两线总线，I²C 靠地址点名，CAN 靠 ID 仲裁，冲突的处理方式完全不同。

  • 主从最省心：不需要仲裁逻辑，但实时性差——从设备想报警，也只能等主设备来问。
  • 多主最灵活：任何节点都能立刻上报，代价是要有仲裁与错误处理机制（CAN 的错误帧与错误计数器就是为这个存在的）。
  • I²C 靠地址，SPI 靠片选：I²C 两根线就能挂很多器件，但要处理地址冲突；SPI 没有地址，多一个从机就多一根 CS，引脚数随设备数线性增长。

电气标准 ≠ 协议 ≠ 外设
RS232、RS485、TTL 是电气标准：只规定“用什么电平、几根线、能拉多远”，不规定“帧长什么样、第几个字节是什么”。Modbus 是应用层协议：规定功能码与寄存器地址，既能跑在 RS485 上，也能跑在以太网上。I²C 和 SPI 是协议：定义了时序与帧，本身不带电平标准——所以“RS485 协议的 I²C”“I²C 电平”这类说法都是混了层。USART/UART 是 MCU 里的外设：给它接一个 RS485 收发器，它就变成了 RS485 的电气层。

同一套协议在不同 MCU 上的外设形态差别很大：寄存器名字、DMA 请求方式、FIFO 有无、是否支持 9 位数据与硬件流控都不一样。下面的对照卡看的是外设侧的差异，电气层则由外部收发器决定，与内核无关。

选型先问四个问题

选型不是背参数表，而是把需求压缩成四个问题。

把需求压缩成四个问题，答案通常就能把候选缩到一两个：多远、多快、还剩几根线、挂几台谁能主动说。四问的顺序很重要——距离最先定，因为它是画原理图时就锁死的那一条。

  1. 多远？ 板内几十厘米以内，I²C/SPI 最省事；几米到几十米，换差分（CAN、RS485）；上百米或跨楼，上以太网。距离一长，单端基本没戏。
  2. 多快、多频繁？ 先算有效带宽 = 每帧字节数 × 每秒帧数，再把协议开销（起始位、地址、ACK、帧间隔）加回去。大块数据（屏幕、Flash）选 SPI/USB；每秒几百字节的传感器，I²C/UART 就够。
  3. 还剩几根线？ 连接器只剩 2 根：短的用 I²C，长的用差分总线；有 4 根就能上 SPI；要热插拔、还要顺带供电，考虑 USB。
  4. 挂几台、谁能主动说话？ 一主多从、主问从答：I²C/SPI；多台设备都要能立刻上报：CAN；只有两台：UART 最便宜。

再补一条常被忽略的：干扰、隔离、热插拔、线材能不能买到，往往比速率更能决定方案。板子上每多一种协议，就多一套收发器、线材、示波器探头和调试时间。

一句话收尾
先用距离 / 速率 / 线数 / 多设备四问把候选缩小，再用干扰与隔离筛一遍；剩下的细节交给数据手册和示波器。下一页进入 UART——异步、单端、点对点，是这套四层框架最小的一个实例。

常见错误与排查

错误现象怎么查 / 怎么改
把 RS485 当成协议嘴上说“我们板子用 RS485 协议”，但一问帧格式、校验方式、地址怎么分配就答不上来先分层：RS485 只规定电气（差分、两线、终端电阻 120 Ω 量级）。帧格式要么用 Modbus RTU，要么自己写一份帧格式文档，两者要分开讲。
不共地就接单端信号两块板各用一套电源，只连一根信号线，能通一会儿，之后乱码、偶发复位用万用表量两块板 GND 之间的电压与纹波；超出发收器共模范围就必须共地，否则改用差分或加隔离。
I²C 挂太多器件后偶发 NACK示波器看 SCL/SDA 上升沿变圆变缓，降速率后又恢复正常按 t_r ≈ 0.847 × R × C 估一下：减小上拉、缩短线长、减少挂载或降速；先量波形再改参数，别靠猜。
两端波特率对不上单字节偶尔错、连续发送才明显出错，示波器上能看到停止位附近的采样点已经偏出核对 `USART1->BRR` 计算时用的总线时钟是不是你以为的那个频率，再用回环 + 串口助手做单字节验证。
以为 SPI 有应答从机没上电、CS 也没接对，程序照样发完不报错，读回全是 0xFFSPI 没有地址也没有 ACK，必须靠读器件 ID 或回读寄存器自证；调试时先读 ID 这一类的固定寄存器。
