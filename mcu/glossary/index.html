微控制器

MCU (Microcontroller Unit)MCU 核心

把 CPU 内核、Flash、SRAM 和一堆外设集成在一颗芯片里的“小电脑”，上电就跑固定程序去控制硬件，比如点灯、读数、发一帧串口数据。它的优势是成本低、实时性确定、不需要操作系统；要跑复杂界面或大程序时通常改用 MPU 或 SoC。

/foundations/core

内核

Core (CPU Core)MCU 核心

芯片里真正执行指令的部分，负责取指、译码、运算以及异常和中断的入口。Cortex-M 是 ARM 面向 MCU 的内核系列，同一颗内核可以被不同厂商配上完全不同的外设和存储。

/core/foundations

指令集

ISA (Instruction Set Architecture)MCU 核心

CPU 认识的那套指令、寄存器与寻址规则，C 代码必须先编译成对应指令集的机器码才能运行。ARM Cortex-M 使用 32 位 RISC 指令集（Thumb-2），同一份源码换内核就得重新编译。

/foundations/core

系统时钟

SYSCLK (System Clock)MCU 核心

整颗芯片跑多快的基准频率，由时钟树从晶振或内部 RC 经 PLL 倍频、分频得到，F407 的 SYSCLK 上限 168 MHz（以数据手册为准）。它决定 CPU 和外设总线的节奏，改频率时要同步改 Flash 等待周期，否则取指会出错。

/clock

时钟树

Clock TreeMCU 核心

从时钟源到 CPU 和各外设的时钟分配网络：选源、倍频、分频、门控，每一步都由 RCC 寄存器决定。外设时钟没使能或分频配错，外设就完全不工作，这是“代码没错却没反应”的头号原因。

/clock/lowpower

Flash

Flash MemoryMCU 核心

存放程序代码和常量、掉电不丢的非易失存储器，CPU 取指也从这里读。写入前必须先擦除整块，擦写次数有限（量级一万次，按器件手册），所以别拿它当频繁写的日志区。

/core

静态随机存储器

SRAM (Static RAM)MCU 核心

掉电即失的读写内存，放全局变量、栈和堆，也是 DMA 搬运数据的落脚点。容量通常从几 KB 到几百 KB 量级，栈溢出和数组越界都在这块内存上出事。

/core/dma

启动流程

Boot SequenceMCU 核心

上电复位后 CPU 做的第一串固定动作：从向量表取初始栈顶、跳转到复位处理函数，初始化时钟与 .data/.bss，最后进入 main。板级还有 BOOT 引脚决定从 Flash 还是系统存储器启动，具体见芯片手册。

/core/foundations

复位

ResetMCU 核心

把 CPU 和外设拉回初始状态的动作，来源有上电复位、外部复位引脚、看门狗复位和软件复位。复位后外设寄存器回到默认值，很多“重新初始化就不好使”的问题其实是没做完整复位。

/clock/debug

中断向量表

Vector TableMCU 核心

一张按异常和中断编号排列的入口地址表，CPU 响应中断时先从表里取出处理函数地址再跳过去。表的位置可以通过 SCB->VTOR 重定位，表填错或没重定位的典型现象是一进中断就掉进 HardFault。

/interrupt/core

栈

StackMCU 核心

函数调用时保存返回地址、局部变量和中断现场的后进先出内存区，Cortex-M 用 MSP 和 PSP 两个栈指针。中断也会压栈，栈给得太小会悄悄覆盖别的变量，表现成随机的死机或数据错乱。

/core/interrupt

低功耗模式

Low Power ModeMCU 核心

通过停时钟、关电源域来省电的几档状态，常见 Sleep、Stop、Standby 三档，唤醒源、唤醒时间和状态保留程度各不相同。选哪一档取决于你能接受多长的唤醒时间、要保留多少现场，具体功耗以数据手册为准。

/lowpower

通用输入输出

GPIO (General-Purpose Input/Output)外设

可以由软件定义成输入、输出、复用或模拟的引脚，是芯片和外界打交道的第一个接口。按键、LED、片选、软件模拟时序都从它出入，配置顺序通常是先开时钟再设模式。

/gpio

中断

Interrupt外设

外设或异常主动打断 CPU 当前流程、跳去执行处理函数，办完再回来继续的机制。它替代轮询，让按键、串口收字节、定时事件能被及时响应，代价是要处理共享数据和优先级。

/interrupt

嵌套向量中断控制器

NVIC (Nested Vectored Interrupt Controller)外设

Cortex-M 内核里的中断控制器，负责让哪条中断使能、给它什么优先级、能不能嵌套。STM32 上用 HAL_NVIC_EnableIRQ 和 HAL_NVIC_SetPriority 操作，底层就是 NVIC->ISER 和 NVIC->IP。

/interrupt

中断服务函数

ISR (Interrupt Service Routine)外设

中断触发后真正执行的那段函数，函数名必须和向量表里的入口对上。它应该短、快、不做阻塞等待，耗时的活交给主循环或标志位，否则会拖慢所有低优先级中断。

/interrupt/dma

抢占优先级

Preemption Priority外设

NVIC 优先级里的高位部分，决定一条中断能不能打断正在执行的 ISR，数值越小越急。抢占优先级相同的中断之间永远不会互相打断，哪怕子优先级不同。

/interrupt

子优先级

Subpriority外设

NVIC 优先级里的低位部分，只在多条中断同时挂起时决定谁先排队，永远不会打断正在跑的 ISR。HAL_Init 默认分组下子优先级的位数为 0，此时代码里填的值实际不起作用。

/interrupt

优先级分组

Priority Grouping (PRIGROUP)外设

用 SCB->AIRCR 的 PRIGROUP 把有限的优先级位切成抢占位和子优先级位，例如 4 位全给抢占，或 2 位抢占加 2 位子优先级（STM32 一般只实现高 4 位，以参考手册为准）。分组是全工程共享的全局设置，前后设成不同值会让优先级表现变得没法解释。

/interrupt

外部中断

EXTI (External Interrupt)外设

把引脚电平变化（上升沿、下降沿或双边沿）转成中断请求的片上模块，STM32 里还要用 SYSCFG 把某个引脚映射到中断线。按键唤醒、编码器计数、传感器脉冲都常用它。

/interrupt/gpio

直接存储器访问

DMA (Direct Memory Access)外设

让外设和内存之间直接搬数据、不经过 CPU 逐字节读写的机制，CPU 只负责启动和收完成中断。串口不定长接收、ADC 连续采样、SPI 刷屏靠它才能既不丢数据又不占满 CPU。

/dma

定时器

Timer外设

按内部时钟计数、在设定值触发中断或事件的片上外设，本职是定时、计数、PWM 和输入捕获。配置永远绕不开三件事：时钟源、预分频 PSC、自动重装 ARR。

/timer

脉宽调制

PWM (Pulse Width Modulation)外设

用固定频率方波、靠改变高电平占空比来等效调节输出功率或模拟量的方法。LED 调光、电机调速、舵机控制都用它，频率选低了会闪、选高了开关损耗大，要按负载来定。

/timer

模数转换器

ADC (Analog-to-Digital Converter)外设

把引脚上的模拟电压量成数字码的转换器，常见 12 位分辨率，参考电压决定满量程。读电位器、电池电压、热敏电阻都先经过它，采样时间和参考电压是最容易被忽略的两项。

/adc

数模转换器

DAC (Digital-to-Analog Converter)外设

把数字码变成模拟电压输出的转换器，可做可调基准、音频或简易波形。它并不是每颗 MCU 都有，分辨率和输出驱动能力以数据手册为准。

/adc

看门狗

Watchdog (WDT)外设

一个必须定期“喂”的倒计时器：程序跑飞没按时喂，它就复位芯片，是死机后的最后一道保险。喂狗要放在能证明主流程还活着的位置，放错地方反而会掩盖真正的卡死点。

/debug

复用功能

Alternate Function (AF)外设

把引脚从普通 GPIO 交给片上外设（USART、SPI、TIM、I²C）管理的模式，STM32 用 MODER=10 加 AFR 选择具体功能。一个引脚往往能复用成好几种外设，AFR 选错就会出现“配置全对但没有波形”。

/gpio

SysTick

SysTick外设

Cortex-M 内核自带的 24 位递减定时器，HAL 常把它配成 1 ms 系统节拍，驱动 HAL_Delay 和各类超时判断。它属于内核而不属于片上外设，系统时钟变了要跟着重配，否则延时会整体偏。

/clock/timer

协议

Protocol通讯协议

通信双方约定“怎么发、怎么收、怎么判错”的一整套规则，通常拆成电气层、时序层、帧层、应用层。分不清层次就会把 RS485 当协议、把 Modbus 当电平，排错时查错了地方。

/protocols

通用异步收发器

UART (Universal Asynchronous Receiver/Transmitter)通讯协议

没有时钟线的点对点串口：双方约定波特率，把每个字节拆成起始位、数据位、校验位、停止位逐位发送。调试打印、GPS、蓝牙模块的 AT 指令几乎都从它入门。

/uart

通用同步/异步收发器

USART (Universal Synchronous/Asynchronous Receiver/Transmitter)通讯协议

STM32 里串口外设的名字，比 UART 多一个同步模式，异步用法和 UART 完全一致。手册上写 USART 不代表必须用同步，配成异步就是普通串口。

/uart

波特率

Baud Rate通讯协议

每秒传输的符号数；二进制 UART 里一个符号就是一位，所以数值上等于 bit/s，115200 波特率下一位约 8.68 µs（示意）。双方偏差累积到约半个位时间就会采错，所以要选精确时钟源并算清分频误差。

/uart

异步

Asynchronous通讯协议

收发双方没有共享时钟线，各自按约定速率计时，靠起始位重新对齐。UART 是典型异步通信，线少、便宜，但速率不能太高，且对两端时钟精度有要求。

/uart/protocols

同步

Synchronous通讯协议

收发双方共用一根时钟线（或从数据里恢复时钟），由主设备打拍子，接收方在指定边沿采样。SPI、I²C、I²S 都属于同步通信，多一根线换来更高速度和更确定的时序。

/protocols/spi

全双工

Full Duplex通讯协议

同一时刻两个方向都能传数据，UART 的 TX/RX、SPI 的 MOSI/MISO 都是全双工。它不需要切换方向，但要求收发两套线路各自独立。

/uart/spi

半双工

Half Duplex通讯协议

同一时刻只能一个方向传数据，RS485 二线制、I²C、1-Wire 都是半双工。要么由主设备统一调度，要么加 DE/RE 方向控制，并等最后一个字节真正发完再释放总线。

/board-bus/i2c

集成电路总线

I²C (Inter-Integrated Circuit)通讯协议

两根线（SCL 和 SDA）的同步半双工总线，开漏输出加外部上拉，用 7 位或 10 位地址找从机，支持多主多从。读温湿度、EEPROM、OLED 屏最常见，上拉阻值和总线电容决定它能跑多快。

/i2c

串行外设接口

SPI (Serial Peripheral Interface)通讯协议

四线同步全双工总线（SCK、MOSI、MISO、CS），主设备给时钟、用片选挑选从机，没有地址和应答字段。它速度快、协议简单，适合屏幕、Flash 和高速传感器，代价是每个从机多一根片选。

/spi

MISO

MISO (Master In Slave Out)通讯协议

SPI 里从机发给主机的数据线，主机侧它是输入、从机侧它是输出。多个从机可以共用这一根线，靠各自的 CS 决定谁在驱动它。

/spi

MOSI

MOSI (Master Out Slave In)通讯协议

SPI 里主机发给从机的数据线，所有从机共用，片选没拉低的从机不理会线上的内容。MOSI 和 MISO 接反是最常见的“读回全 0 或全 1”。

/spi

时钟极性

CPOL (Clock Polarity)通讯协议

SPI 的时钟极性：CPOL=0 表示时钟空闲为低，CPOL=1 表示空闲为高。它和 CPHA 一起组成四种 SPI 模式，主机和从机必须选同一个模式。

/spi

时钟相位

CPHA (Clock Phase)通讯协议

SPI 的时钟相位：CPHA=0 在第一个时钟边沿采样，CPHA=1 在第二个边沿采样。模式配错的典型现象是数据整体错位一两位，看起来像“设备坏了”。

/spi

片选

CS (Chip Select)通讯协议

SPI 上每个从机一根、低电平有效的选择线，告诉总线这次跟谁说话。片选没拉低、多个同时拉低或者忘了接上拉，都会让总线上的数据变成随机数。

/spi

控制器局域网

CAN (Controller Area Network)通讯协议

差分、多主、广播式的现场总线，节点没有地址，靠报文 ID 和逐位仲裁决定谁先发，冲突不丢数据。汽车和工业设备里到处都是，CAN FD 则在数据段进一步提速。

/can

显性位

Dominant Bit通讯协议

CAN 总线上被主动驱动的位，逻辑 0：收发器把 CANH 拉高、CANL 拉低，两线间出现明显差分电压（量级 1.5–3 V，以收发器手册为准）。只要有一个节点发显性，整条总线就是显性。

/can

隐性位

Recessive Bit通讯协议

CAN 总线上“放手”的位，逻辑 1：没有节点驱动，两根线靠终端电阻回到同一电位，差分接近 0 V。显性覆盖隐性，这条电气规则正是逐位仲裁能无损分出胜负的基础。

/can

仲裁

Arbitration通讯协议

多个节点同时开口时逐位比较、按“显性覆盖隐性”决定谁继续发：发出隐性却读到显性的节点立即退出，稍后自动重发。CAN 的 ID 数值越小优先级越高，抢输的数据不会丢。

/can

Modbus

Modbus通讯协议

规定地址、功能码、数据和 CRC16 怎么排的应用层协议，常用 RTU 模式跑在 RS485 上，也能跑 RS232 或封装成 Modbus TCP。它和 RS485 不在同一层：RS485 管电怎么传，Modbus 管字节什么意思。

/board-bus

CRC

CRC (Cyclic Redundancy Check)通讯协议

把一段数据按生成多项式算出一个短校验值附在帧尾，接收方重算并比对，用来发现传输错误。Modbus 用 CRC16，经典 CAN 用 15 位 CRC（CAN FD 的校验更长）；CRC 只能检错，不能纠错，出错要靠重发。

/board-bus/can

应答

ACK (Acknowledge)通讯协议

收方回给发方的明确应答：这一帧或这个字节我收到了。I²C 每个字节后跟一个 ACK 位，CAN 在 ACK 槽由收方拉显性，UART 一般没有硬件应答。

/i2c/can

NACK

NACK (Not Acknowledge)通讯协议

否定应答，表示“没收到”或“不要了”。I²C 主机读完最后一个字节后回 NACK 告诉从机停止发送；地址阶段收到 NACK，通常说明从机不在线或地址写错。

/i2c

位填充

Bit Stuffing通讯协议

经典 CAN 帧为了防止连续相同电平过多导致失步，每连续 5 个同极性位就自动插入 1 个反极性位，接收方再把它删掉。它不改变数据内容，但会让线上的实际位数比帧表里写的多。

/can

最低有效位

LSB (Least Significant Bit)通讯协议

二进制数里权值最小的那一位，UART 默认先发 LSB。SPI 也有 MSB first 和 LSB first 两种顺序，配置和从机手册不一致时读出来的数据位序会整个反过来。

/uart/spi

最高有效位

MSB (Most Significant Bit)通讯协议

二进制数里权值最大的那一位，多字节数据还涉及“高字节在前还是低字节在前”的字节序。SPI 和 I²C 器件大多要求 MSB first，配置错了会看到数值被“拆错位”。

/spi/i2c

通用串行总线

USB (Universal Serial Bus)通讯协议

主机—设备结构的通用串行总线，设备靠端点收发数据，插入后先经过枚举让主机认识它。HID 键鼠、CDC 虚拟串口、大容量存储是 MCU 上最常见的三类设备。

/usb

MAC 与 PHY

MAC / PHY通讯协议

以太网的两个层次：MAC 负责组帧、算 CRC 和地址过滤，PHY 负责把数字信号变成线上的差分波形。MCU 通常内置 MAC 需要外接 PHY，两者之间用 MII 或 RMII 连接。

/ethernet

帧

Frame通讯协议

一次通信的最小完整单位，从起始标志开始到结束标志为止，中间是地址、数据、校验等字段。调试时先核对帧头、长度和校验，再去怀疑数据内容，能省一大半时间。

/protocols/uart

TTL 电平

TTL Level电气

一种单端逻辑电平标准：低电平在 0 V 附近，高电平在 3.3 V 或 5 V 附近，具体阈值各系列不同（以数据手册为准）。MCU 引脚直接输出的就是这类电平，板内短距离直连没问题，出板子就要换 RS232/RS485 或加收发器。

/uart/board-bus

RS232

RS232电气

单端、负逻辑的串口电气标准：逻辑 1 用负电压、逻辑 0 用正电压（量级 ±3～±15 V，以标准与收发器手册为准），抗干扰弱、传输距离短。它只规定电怎么传，不规定字节含义，所以 RS232 上同样能跑 Modbus。

/uart/board-bus

RS485

RS485电气

差分、二线制半双工的串口电气标准：用 A/B 两线的电压差判 0/1，共模范围宽、可挂多节点、能跑长线。它是电气层而不是协议，Modbus RTU 只是最常跑在它上面的应用层，两者要分开排查。

/board-bus

单端信号

Single-Ended Signal电气

用一根信号线对地表示高低电平的方式，TTL 和 RS232 都是单端。它省线，但长距离上两地的地电位差和干扰会直接叠加进信号里，所以远距离、强干扰场合改用差分。

/uart/board-bus

差分信号

Differential Signal电气

用两根线的电压差表示逻辑，而不是单根线对地的绝对电压；干扰会同时耦合到两根线上，差值基本不变。CAN、RS485、USB、以太网都靠差分抗共模干扰、延长传输距离。

/can/board-bus/ethernet

共模电压

Common-Mode Voltage电气

两根差分线对地的共同电位偏移，接收器只能在一定范围内正常工作（RS485 约 −7～+12 V 量级，以收发器手册为准）。长线、跨机柜、不同电源域之间共模会漂，必要时用隔离收发器或共模扼流圈。

/board-bus/can

终端电阻

Termination Resistor电气

接在差分总线物理两端的电阻，CAN 和 RS485 常用 120 Ω 量级，用来吸收信号反射、给隐性位提供泄放回路。它只该出现在两端，中间节点乱加会把总线负载拉重、通信距离反而变短。

/can/board-bus

上拉电阻

Pull-up Resistor电气

把线在没人驱动时拉向高电平的电阻，开漏输出、按键输入和 I²C 总线都靠它确定默认电平。阻值太小费电、太大边沿变慢，I²C 的上拉要按速率和总线电容选（常见几 kΩ 量级，以器件手册为准）。

/gpio/i2c

下拉电阻

Pull-down Resistor电气

把线在空闲时拉向低电平的电阻，常用于“按下接高”的按键和默认关断的使能脚。和上拉一样，它只负责定默认值，真正驱动信号还得靠输出级。

/gpio

推挽

Push-Pull电气

输出级上下两只 MOS 管成对工作：写 1 主动推高、写 0 主动拉低，边沿快、驱动强。代价是不能把两个推挽输出直接并在一条线上，否则一个推高一个拉低会形成大电流对灌。

/gpio

开漏

Open-Drain电气

输出级只有下管：写 1 等于放手，高电平靠外部上拉电阻拉回来，写 0 才主动拉低。多个开漏可以共线做“线与”，I²C 的 SDA/SCL 和 1-Wire 都是这种结构。

/gpio/i2c

线与

Wired-AND电气

多路开漏输出接在同一根线上，任意一路拉低整条线就是低，只有全部放手才为高，逻辑上相当于“与”。I²C 的多主仲裁和时钟同步都建立在这个电气特性上。

/i2c/gpio

高阻态

Hi-Z (High Impedance)电气

引脚既不输出高也不输出低，相当于从电路里“拔掉”，电平完全由外部电路决定。输入浮空会像天线一样乱跳，所以读按键必须配上拉或下拉；总线释放也靠高阻态。

/gpio

去耦电容

Decoupling Capacitor电气

放在芯片电源脚旁边的电容，就近提供瞬间电流、旁路高频噪声，常见 100 nF 量级再配一个大电容（以器件手册推荐为准）。它必须贴近引脚，走线一长基本就失效了。

电平转换

Level Shifter电气

把一种逻辑电平转换成另一种的电路，比如 3.3 V 的 MCU 和 5 V 的模块互通，常用专用芯片或 MOS 管做双向转换。先查引脚是否 5 V 容忍，直接硬接可能超出手册绝对最大额定值。

/gpio

上升沿与下降沿

Rising Edge / Falling Edge电气

信号从低跳到高叫上升沿，从高跳到低叫下降沿，常被当作触发条件：外部中断按边沿触发、SPI 在某个边沿采样。边沿越陡，时序越好做，但高频成分也越多、EMI 越大。

/gpio/interrupt

串行线调试

SWD (Serial Wire Debug)工具

ARM 定义的两线调试接口（SWDIO 数据线 + SWCLK 时钟线），能下载程序、打断点、读写内存和外设寄存器。STM32 板上的调试排针通常就是它，比 JTAG 少好几根线。

/debug

JTAG

JTAG工具

更老的多线调试与边界扫描接口，典型信号有 TCK、TMS、TDI、TDO，功能比 SWD 多但占引脚。很多 Cortex-M 芯片同时支持 SWD 和 JTAG，调试器模式选错时表现就是“连不上芯片”。

/debug

调试器

Debugger工具

把电脑上的下载、断点、单步命令翻译成 SWD/JTAG 时序的硬件，例如 ST-Link、J-Link、DAP-Link。它是定位“程序停在哪、变量是多少”的主要手段，也是烧录程序的常用通道。

/debug

断点

Breakpoint工具

让 CPU 执行到指定行或地址时停下来的调试机制，硬件断点靠内核里的比较器，数量有限（通常几个，具体看内核实现）。它能暂停程序，但也会改变时序，排查实时性问题时别只依赖断点。

/debug

单步

Step工具

一次只执行一行源码或一条指令就停下，用来确认分支走了哪条、变量何时被改写。单步会显著拖慢程序，中断、超时和通信超时类问题用它观察容易失真。

/debug

逻辑分析仪

Logic Analyzer工具

多通道抓数字波形并按协议解码（UART、I²C、SPI、CAN 等）的工具，能直接看到线上发了哪些字节、时序差多少。它只看逻辑电平，不评估信号质量，模拟问题还得靠示波器。

/debug/protocols

示波器

Oscilloscope工具

把电压随时间的变化画成波形的仪器，用来看上升沿、过冲、毛刺、电源纹波和差分信号质量。逻辑分析仪回答“0/1 对不对”，示波器回答“这个 0/1 长得像不像样”。

/debug

万用表

Multimeter工具

测电压、电流、电阻和通断的基础工具，上电前查供电和短路、怀疑上拉没焊时最先用它。它显示的是稳态或平均值，测不了高速波形和瞬态毛刺。

/debug

串口助手

Serial Terminal工具

电脑上收发串口数据的软件，用来看日志、发 AT 指令、手动拼一帧协议试设备。打开前要和固件对齐波特率、数据位、校验位、停止位，并确认 USB-TTL 模块的 TX/RX 是交叉接的。

/uart/debug

烧录

Flash Programming工具

把编译好的程序写进芯片 Flash 的过程，常见通道是调试器（SWD）、串口 ISP 和 USB DFU。烧不进去先查接线和供电，再查芯片是否被读保护或写保护，最后才怀疑程序本身。

/debug/core

交叉编译工具链

Toolchain工具

在电脑上把 C 源码变成目标芯片机器码的一整套工具：编译器、汇编器、链接器、启动文件和库。链接脚本、启动文件或库版本不匹配时，常见结果是能编译通过但一上电就进 HardFault。

/core/debug

单线跟踪输出

SWO / ITM工具

Cortex-M 的单线跟踪输出（Serial Wire Output），能在不占串口的情况下打印调试信息、做事件跟踪。需要调试器支持并在工程里配置 SWO 引脚与速率，很多廉价调试器只能下载不能跟踪。

/debug

CubeMX 配置工具

STM32CubeMX工具

ST 的图形化配置工具，选引脚、配时钟树、开外设后生成 HAL 初始化代码和工程骨架。生成结果只是起点，引脚分配和时钟仍要对照板子原理图与芯片手册核对。

/clock/gpio
