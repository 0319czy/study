SPISerial Peripheral Interface

SPI 用一根时钟线带着两根数据线，让主从移位寄存器同时交换数据：快、简单，但没有应答。

1 个交互实验 3 道小测验默认 STM32F407 / STM32G474（Cortex‑M4F）

学习目标

  • ·说出 SCK / MOSI / MISO / CS 四根线各自的方向与作用，能画出主从连接
  • ·用“两个移位寄存器交换”解释全双工，说明为什么读数据也必须发字节
  • ·拿到器件时序图能判断 CPOL/CPHA，并选对 Mode 0~3
  • ·说清 SPI 没有 ACK 的可靠性代价，以及 SCK 上限受什么限制

一句话解释

SPI 用一根时钟线带着两根数据线，让主从移位寄存器同时交换数据：快、简单，但没有应答。

生活化比喻

两个人面对面，同时交换手里的牌

主机和从机各拿一叠牌（移位寄存器），面对面站着。每敲一下铃（SCK 的一个周期），两人同时把最上面一张递过去、并接住对方递来的那一张；敲 8 下，两人手里的 8 张牌正好互换。谁被叫到名字（CS 被拉低），谁才参与这一轮；没被叫到的人站着别动。整个过程不需要说话确认——“你收到了吗”从来没人问。

为什么重要 / 用在哪里

  • 01外设生态最大：SPI NOR Flash、TFT 屏、传感器、SD 卡、无线模块、ADC 都常用 SPI，板级高速外设几乎绕不开它。
  • 02速度优势明显：同步、无地址、无应答开销，SCK 常见几十 MHz 量级，适合刷屏与大块数据搬运（量级以手册与器件为准）。
  • 03排错高频区：模式（CPOL/CPHA）配错、CS 时序不对、MISO 悬空——这三类问题占了 SPI 调试的大半。
  • 04理解“同步串行”的最佳样本：把移位寄存器想通，再看 QSPI/OSPI 与 I²S 都只是“多几根数据线”的扩展。

四根线，各管一件事

先记方向，再记名词——SPI 的坑大多出在“谁该驱动哪根线”上。

SPI（Serial Peripheral Interface，串行外设接口） 是一种同步、全双工、主从的板级串行总线：主机产生时钟，从机跟着节拍收发。它不需要地址、不需要应答，只用四根线就能跑到几十 MHz 量级（上限以芯片手册与从机器件为准）。

串行时钟SCK, Serial Clock
主机产生的节拍。每个周期传 1 位；8 位数据宽度时，8 个周期 = 1 字节。SCK 的空闲电平由 CPOL 决定。
主机输出 / 从机输入MOSI, Master Out Slave In
主机 → 从机的数据线。常规单主机 SPI 里只有主机驱动它。
从机输出 / 主机输入MISO, Master In Slave Out
从机 → 主机的数据线。从机没被选中时应输出高阻，主机这时读到的可能是悬空电平。
片选CS / NSS, Chip Select / Slave Select
一根 CS 管一个从机（ST 文档里常叫 NSS，低电平有效）。它不只是“选中”，还是这一帧数据的边界。
“四线”是最小集，不是唯一形态
只写不读的器件（部分屏幕）可以省掉 MISO，只读不写的可以省掉 MOSI；带 DC、复位、忙检测引脚的器件还要额外几根 GPIO。QSPI/OSPI 则是在 SPI 的基础上把数据线扩到 4 根/8 根——时钟、片选、移位这套本质没变。

全双工的本质：交换

“全双工”不是两根线各干各的，而是两个移位寄存器在同一个时钟下互换内容。

主机内部有一个 8 位移位寄存器，从机内部也有一个。每一次 SCK 周期，双方同时从自己的寄存器移出 1 位、并把自己收到的那一位移入。跑满 8 个周期，两个寄存器里的内容刚好互换：主机手里变成了从机原来的那份，从机手里变成了主机发来的那份。这就是“发一个字节的同时收到一个字节”的硬件来源。

  1. 主机把要发的字节装进自己的移位寄存器，从机把要回的字节装进自己的。
  2. SCK 每来一个有效边沿：主机从 MOSI 移出 1 位（常规是 MSB 先出），从机从 MISO 移出 1 位。
  3. 同一时刻，两边各把收到的位补进寄存器空出的位置——发送与接收是同一个动作的两面。
  4. 8 个周期后交换完成：主机读 DR 拿到从机的字节，从机读 DR 拿到主机的字节。

于是有两个绕不开的推论。第一，即使你只想发，也一定会收到对方准备好的数据；HAL 的 HAL_SPI_Transmit() 内部同样是全双工交换，只是把读到的字节丢掉了。第二，即使你只想读，也必须发点东西来产生 8 个时钟，通常发 0xFF 或 0x00 当“空转”占位。

读寄存器类器件的固定套路
你发命令字节的那个周期，从机的应答数据往往还没准备好——所以第一字节收到的内容无意义。真正的流程是：先发命令（收到的丢掉），再发占位字节（这时才收到数据）。读 Flash ID 就是典型：0x9F 命令后跟着 3 个占位字节，才换回 3 字节 ID。

多从机：独立 CS 与菊花链

SPI 没有地址，选谁全靠片选——这也是它比 I²C 多用引脚的原因。

标准 SPI 没有地址字段。所有从机的 SCK、MOSI、MISO 并联在一起，每个从机单独一根 CS，同一时刻只拉低目标从机的那一根。主机发出去的数据，只有被选中的从机在听；其余从机的 MISO 处于高阻，不干扰总线。

菊花链一句话：前一级从机的 MISO 接到下一级的 MOSI，主机发 N 个字节，数据像队列一样穿过每一级，最后一级的 MISO 回到主机——一根 CS 就能选中一串器件，代价是每次通信都要把所有级的数据移一遍（常见于移位寄存器、LED 驱动这类串行器件）。

多从机排错第一步：量 CS
CS 没拉低 = 从机根本没上线，读到什么都有可能；两个 CS 同时拉低 = 两个从机同时往 MISO 上推电平，读数会随器件“打架”而乱跳。先用逻辑分析仪或示波器确认“任意时刻只有一根 CS 有效”，再怀疑模式与速度。

CPOL / CPHA：四种模式

CPOL 只决定空闲电平，CPHA 只决定“第一个还是第二个边沿采样”，两两组合就是 Mode 0~3。

CPOL（Clock Polarity，时钟极性） 决定 SCK 空闲时停在高还是低：CPOL=0 空闲为低，CPOL=1 空闲为高。CPHA（Clock Phase，时钟相位） 决定数据在第一个边沿还是第二个边沿被采样：CPHA=0 用第一个边沿采样，CPHA=1 用第二个边沿采样。注意采样沿总是落在数据稳定的半个周期中间，另一个边沿用来换数据。

读表顺序很固定：先看 SCK 空闲电平定 CPOL（低 = 0，高 = 1）；再看采样发生在第一个还是第二个边沿定 CPHA（第一个 = 0，第二个 = 1）。CPOL/CPHA 配错时，时钟照跑、数据照发，但采样点错位，读回来常常是全 0xFF 或全 0x00，看起来像“器件没接”。

CPOL/CPHA 只改两件事：空闲电平与采样沿。切换 Mode 0~3，看“高亮当前采样沿”如何移动；再改数据位宽，观察一帧要多少个时钟。

主从必须同模式
Mode 0~3 是业界惯用编号，不同文档写法可能不同（有的直接写 CPOL/CPHA 数值）。配对原则只有一句：主机与从机的 CPOL、CPHA 必须完全一致，或至少让“采样沿”落在从机数据稳定的窗口里。

没有 ACK 的代价与速度边界

SPI 把确认和寻址都省了，换来的是速度；省掉的那部分，就得在软件里补回来。

SPI 总线上没有任何确认机制：主机按自己的节奏敲完 8 个时钟，数据发出去就算“完事”，从机有没有收到、是否在忙、命令是否合法，主机从总线状态上看不出来。I²C 正好相反——每发一个字节，接收方都要在 SCL 的第 9 个时钟拉低 SDA 回一个 ACK，不回就是 NACK，主机当场就知道“对方在不在、收没收到”。

所以 SPI 的可靠性是软件兜底的：写完命令要回读验证（读回寄存器、读状态/忙标志、读器件 ID、数据带 CRC）；上电或复位后从机可能还没准备好，先给延时或先读忙状态；写/擦类操作尤其要确认 CS 的上升沿有没有真正落下——很多 Flash 是 CS 上升沿才执行写、擦。

速度上限由三头共同决定：① 从机器件标称的最高 SCK；② 主机侧的 SPI 时钟（fPCLK 经分频，SPI1 在 F407 上挂在 APB2）；③ 走线与容性负载——线越长、并联从机越多、杜邦线越随意，边沿越缓、串扰与反射越明显，采样就越容易错。

工程做法：先用保守分频（几 MHz 量级）把通信跑通，再逐档提高直到出错，然后退回一档留余量；长线/多从机时缩短走线、降低 SCK、必要时串联小电阻（几十 Ω 量级，示意）抑制过冲。要靠 SPI 出板，通常改用差分/专用收发方案，而不是把四根线拉长。

上手：读一次 Flash ID

这是验证“接线 + 模式 + 分频”是否全对的最快一步：能读到正确的 ID，说明物理层与模式都通了。

  1. 时钟与引脚：打开 SPI1 时钟，把 SCK / MOSI / MISO 配成复用推挽（AF），CS 用普通推挽输出并初始拉高（不选中）。
  2. 配 SPI 参数：主机、8 位、MSB 先发、Mode 0、先给一个保守分频（几 MHz 量级）；NSS 用软件管理（SSM/SSI）或硬件输出都行。
  3. 拉低 CS：选中 Flash；CS 必须在“命令 + 数据”整段期间保持低，中途不能抖。
  4. 一次全双工交换：发 0x9F 命令 + 3 个占位字节 0xFF，用 HAL_SPI_TransmitReceive() 一口气完成。
  5. 释放 CS 并校验：拉高 CS 结束这一帧，把 rx[1..3] 与手册里的 ID 对照，确认模式与分频都对。
同一件事（发 1 字节、收 1 字节）的三种写法

寄存器写法只操作 SPI1 的 CR1 / CR2 / SR / DR；使能时钟与引脚复用见 GPIO 页。

常见错误与排查

错误现象怎么查 / 怎么改
CPOL / CPHA 与从机不一致通信“看起来在跑”，但读 ID、读寄存器全都是 0xFF 或 0x00，换一块板子有时又好了对照从机手册的时序图：SCK 空闲电平定 CPOL，采样落在第一个还是第二个边沿定 CPHA；先用逻辑分析仪量 SCK 空闲电平，再逐个模式试并用读 ID 验证。
CS 时序不对：提前释放或整段不释放命令时好时坏、写操作偶发不生效、连续两次读取结果串在一起CS 必须覆盖“命令 + 数据”整段，拉高才算一帧结束；写/擦命令尤其依赖 CS 上升沿。用逻辑分析仪看 CS 与 SCK 的边界，确认没有中途抖动。
MISO 悬空或从机压根没被选中读到恒定 0xFF（被上拉）或随机乱跳、手碰排线读数就变先确认从机供电与地、目标 CS 确实被拉低；再看 MISO 是否配成复用推挽。未选中时从机 MISO 应为高阻，读数异常往往就是“没人驱动这根线”。
主模式下 NSS 配置不当导致 MODF通信跑着跑着突然停住，或初始化后主模式直接失效单主机场景把 NSS 设成软件管理（SSM=1、SSI=1）；用硬件 NSS 时确保引脚配置与外部电路一致。查 `SPI1->SR` 的 MODF 标志。
SCK 太快或走线太长短杜邦线正常、换长排线或多接一个从机就偶发出错，降速后恢复把分频调大一档复测；缩短走线、减少并联负载、CS/SCK 远离干扰源。找到“能稳定工作的最高档”后退一档留余量。

第 3 题判断进阶

判断：SPI 没有 ACK 机制，主机把字节发出去后无法仅凭总线本身知道从机是否收到；而 I²C 的接收方会在每个字节后回 ACK 或 NACK。

记住这三句话

  1. 01四根线分工：SCK 给节拍、MOSI/MISO 双向传数据、CS 选人；SPI 没有地址，选谁全靠 CS。
  2. 02全双工的本质是两个移位寄存器在时钟下交换：发一个字节的同时必然收到一个字节，所以读也要发占位字节。
  3. 03CPOL 定空闲电平、CPHA 定第几个沿采样；没有 ACK，可靠性要靠模式核对、回读校验与合理降速来兜。
