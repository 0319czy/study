时钟与复位Clock & Reset

时钟是芯片的心跳：先选时钟源，经 PLL 倍频，再分频送到各总线与外设；复位则把这一切拉回默认起点。

1 个交互实验 3 道小测验默认 STM32F407 / STM32G474（Cortex‑M4F）

学习目标

  • ·说清 HSI / HSE / LSI / LSE 四个时钟源的差别与典型用途
  • ·能用 VCO = (fin / PLLM) × PLLN、SYSCLK = VCO / PLLP 手算任意 PLL 配置
  • ·解释 168 MHz / 42 MHz / 84 MHz 是怎么来的，以及 Flash 等待周期为什么必须跟着改
  • ·说出五类复位源，并知道复位后芯片默认跑在什么时钟上

一句话解释

时钟是芯片的心跳：先选时钟源，经 PLL 倍频，再分频送到各总线与外设；复位则把这一切拉回默认起点。

生活化比喻

时钟树像一套“自来水系统”

时钟源是水厂：HSI 像自备小水井，随时能用但水质一般；HSE 像外接水库，稳定但要等它注满。PLL 是加压泵，把低压水压成高压；AHB 是主干管，APB1 / APB2 是两条支管，各自有压力上限。每个外设是家里的一只阀门——总闸开了、阀门不开，水照样到不了；阀门开了但水压不对，龙头也出不了水。

为什么重要 / 用在哪里

  • 01任何外设配置的第一步都是时钟：先使能、再选对频率，否则波特率、定时周期、ADC 采样时间全是错的。
  • 02性能与功耗的总开关：要提高主频先改时钟树，要省电先降频、关掉不用外设的时钟门控。
  • 03“代码没错但跑飞”的常见根因：Flash 等待周期没跟上、APB 超频、PLL 没锁定，都发生在时钟树里。
  • 04复位与时钟共同决定上电后的第一行代码：看懂启动流程、排查异常重启，绕不开这两件事。

为什么先配时钟

数字电路是同步电路：没有时钟，寄存器不会动；时钟不对，寄存器写得进去，也不按你想的节奏工作。

时钟（Clock）是给数字电路定节拍的周期信号。CPU 每个时钟周期执行指令；外设也把时钟当尺子：定时器数周期得到时间，UART 用总线时钟分频得到波特率，ADC 用时钟决定采样节奏。所以时钟是“配置外设”的前置条件，不是可选项。

  • 外设时钟门控（Clock Gating）：每个外设的时钟默认是关的，用 RCC->AHB1ENR 这类寄存器单独打开。门控不开，外设寄存器写了也不生效——这是新手第一大坑。
  • 总线频率不同：CPU、SRAM、DMA 挂在 AHB；大部分外设挂在 APB1 / APB2。三条总线各有上限，F407 常见配置是 AHB 168 MHz、APB1 42 MHz、APB2 84 MHz（以数据手册为准）。
  • 参数依赖总线时钟：UART 波特率、定时器周期、ADC 采样时间都是从总线时钟分频算出来的，改了时钟树必须回头重算。
  • 功耗与时钟正相关：频率越高越费电；不用外设就关它的时钟，是最直接的省电手段。
顺序错了就是白干
正确顺序永远是：配时钟 → 开外设时钟 → 配外设。先配外设后开时钟，那几步配置很可能根本没写进去；HAL 里表现为“函数返回 OK，引脚却毫无反应”。

四个时钟源与 PLL 的算法

F4 有两条内部 RC、两条外部晶振通路；选谁，取决于你要精度还是省事。

RC 振荡器做在芯片内部，上电就能用，但精度受温度、电压影响；晶振（Crystal）要在外部焊石英晶体，起振慢一点，但频率准、稳定。四个时钟源的名字和定位如下：

HSIHigh-Speed Internal
内部高速 RC，F4 上典型 16 MHz，复位后的默认系统时钟。精度一般（百分比量级，见数据手册）。
HSEHigh-Speed External
外部高速晶振，F407 支持 4–26 MHz 范围，8 MHz 最常用（示意）。精度取决于晶振（ppm 量级），适合作 PLL 参考。
LSILow-Speed Internal
内部低速 RC，F4 上约 32 kHz 量级，精度较差；独立看门狗 IWDG 和低功耗 RTC 可选用它。
LSELow-Speed External
外部 32.768 kHz 晶振，专门给 RTC 走时；精度高、功耗低，需要外部焊晶体。

PLL（Phase-Locked Loop，锁相环）负责“倍频”：把低频参考变成高频系统时钟。F4 的 PLL 先对输入做 M 分频，再乘 N，最后按 P 分频得到 SYSCLK、按 Q 分出 48 MHz 给 USB 等外设。PLL 的参考源可以选 HSI 或 HSE（对应 RCC->PLLCFGR 的 PLLSRC）——用 HSI 省晶振，但精度和稳定性都差一档。

参数不是随便填的
PLLM 决定 VCO 输入频率（数据手册会给出推荐区间，常见 1–2 MHz 量级）；PLLP 只能取 2 / 4 / 6 / 8；PLLN、PLLQ 也各有取值范围，VCO 输出还有上限。动手前先查数据手册的 PLL 特性表，别照抄别的型号。

时钟树：晶振到总线

用一句话记住链路：源 → PLL → 分频器 → 总线 → 外设门控。

第 1 层

时钟源

先问：原始节拍从哪来？

  • ·HSI：16 MHz，复位默认，最省事
  • ·HSE：外部 8 MHz（示意），稳定，做 PLL 参考
  • ·LSI / LSE：约 32 kHz / 32.768 kHz，给看门狗与 RTC
第 2 层

PLL 倍频

先问：怎么把 8 MHz 变成 168 MHz？

  • ·VCO = (fin / PLLM) × PLLN
  • ·SYSCLK = VCO / PLLP
  • ·PLLQ 另外分出 48 MHz 给 USB 等外设
第 3 层

总线分频

先问：每条总线跑多快？

  • ·AHB（HPRE）：CPU、SRAM、DMA 的主干
  • ·APB1（PPRE1）上限 42 MHz，APB2（PPRE2）上限 84 MHz（F407）
  • ·分频系数不为 1 时，挂在该总线上的定时器时钟会 ×2（见参考手册 RCC 章节）
第 4 层

Flash 与门控

先问：CPU 追得上吗？谁通电？

  • ·FLASH->ACR 的 LATENCY 按 HCLK 设置等待周期
  • ·外设时钟门控（RCC->AHB1ENR 等）决定谁通电
  • ·改了频率，所有依赖总线时钟的外设参数都要重算

交互要点：切换 HSE / HSI、调 PLLM / PLLN / PLLP，实时看 SYSCLK、AHB、APB1、APB2 与 Flash 等待周期；单步顺序：上电默认 HSI → 使能 HSE → 配 PLL → 切换 SYSCLK → 分频到各总线。

换成 G474 要注意什么
STM32G474 的时钟树思路相同，但上限与参数不一样：SYSCLK 最高在 170 MHz 量级（以数据手册为准），PLL 多一个 PLLR 输出，分频表也不完全一样。跨系列移植时别直接照抄 PLLM / PLLN，先用 CubeMX 生成一份再对照参考手册。

配置时钟的六个步骤

这六步的先后顺序有因果：谁依赖谁，不能随意交换。

  1. 选源：要精度、要高速就用 HSE；图省事可先用 HSI，但 HSI 精度差，做 USB / 高波特率串口要谨慎。
  2. 先设 Flash 等待周期：按目标 HCLK 查数据手册的等待周期表，用 FLASH->ACR 的 LATENCY 设好；用 HAL 时这一步就是 HAL_RCC_ClockConfig() 的最后一个参数（如 FLASH_LATENCY_5）。
  3. 配 PLL 参数：在 RCC->PLLCFGR 填 PLLM / PLLN / PLLP / PLLQ / PLLSRC，确保 VCO 输入与 VCO 输出都在允许范围。
  4. 使能并等待锁定：打开 HSE、PLL，轮询 RCC->CR 的 HSERDY / PLLRDY；没锁定就切时钟，芯片会挂死。
  5. 切换 SYSCLK：把 RCC->CFGR 的 SW 写成 PLL，再轮询 SWS 确认切换真的完成。
  6. 分频到各总线：设 HPRE / PPRE1 / PPRE2 得到 AHB / APB1 / APB2，最后用 HAL 的频率查询函数核对实际值。
提速与降速的顺序相反
升频时要先抬 Flash 等待周期再切时钟；降频时要先切回低频再降低等待周期。反过来做，CPU 可能在等待周期不够的情况下取指，表现为随机 HardFault 或跑飞。

配置完别靠“感觉”验收：用 HAL_RCC_GetSysClockFreq()、HAL_RCC_GetHCLKFreq()、HAL_RCC_GetPCLK1Freq()、HAL_RCC_GetPCLK2Freq() 打印实际频率；也可以把时钟输出到 MCO 引脚，用示波器或逻辑分析仪直接量（MCO 的引脚与复用见参考手册 RCC 章节）。

为什么要先关 PLL 再改参数
PLL 正在输出时改 PLLCFGR，输出会瞬间失稳，CPU 可能直接跑飞。正确做法是关 PLL → 等 PLLRDY 清零 → 改参数 → 重新使能 → 等锁定；用 HAL 时这一串动作由 HAL_RCC_OscConfig() 内部完成。

复位：把芯片拉回起点

复位不是断电：它把内核与大部分外设恢复默认，然后让程序从向量表重新开始跑。

复位（Reset）会清掉大部分配置寄存器、让 PC 回到复位向量。系统复位通常不清 SRAM（上电复位会清），所以调试时可能看到“上次的变量还在”。五类复位源要能分清，排查“为什么重启”才有方向。

  • 周期性重启：优先怀疑看门狗（复位间隔很固定），其次查栈溢出、野指针与中断风暴。
  • 一上电就重启：先量供电和 NRST 引脚，排除电源跌落与外部复位电路。
  • 偶发重启：把复位标志、复位计数、关键变量打到串口日志里，复现时才有证据。

常见错误与排查

错误现象怎么查 / 怎么改
改完 PLL 参数却没切换 SYSCLK 源PLL 已锁定，但主频还是 HSI 的 16 MHz，串口波特率、定时器周期全不对检查 `RCC->CFGR` 的 SW 是否写成 PLL，并轮询 SWS 确认；用 HAL 时看是否漏调 `HAL_RCC_ClockConfig()`。
APB1 / APB2 分频没算，直接超频外设时好时坏、串口乱码、定时器计数不对；严重时总线挂死对照数据手册确认 APB1 42 MHz、APB2 84 MHz 上限（F407）；改 SYSCLK 后重算 HPRE / PPRE1 / PPRE2。
先提速、后设 Flash 等待周期随机 HardFault、跑飞、复位后又能跑一会儿；换编译优化等级就“好了”升频前先按目标 HCLK 设好 `FLASH->ACR` 的 LATENCY（168 MHz 常见 5 WS，示意）；降频时顺序相反。
忘记使能外设时钟就配置寄存器HAL 函数返回 OK，引脚/外设却毫无反应；读寄存器常读到 0先查外设挂在哪条总线，用 `__HAL_RCC_GPIOA_CLK_ENABLE()` 这类宏打开门控，再配置外设。
串口 / 定时器参数按错误的总线频率计算波特率偏差大导致乱码，或定时周期整体偏快/偏慢用 `HAL_RCC_GetPCLK1Freq()` / `HAL_RCC_GetPCLK2Freq()` 取实际总线频率再算分频，别手写死一个 MHz 数。

记住这三句话

  1. 01时钟链路是：源 → PLL（÷M、×N、÷P）→ AHB / APB 分频 → 外设门控；改动任何一环，都要重算依赖它的外设参数。
  2. 02PLL 计算靠 VCO = (fin / PLLM) × PLLN、SYSCLK = VCO / PLLP；168 MHz 是 F407 的 SYSCLK 上限（以数据手册为准），提速前先抬 Flash 等待周期。
  3. 03复位把芯片拉回 HSI 16 MHz 的默认状态；复位源有五类，原因可从 RCC->CSR 的复位标志观察（见参考手册 RCC 章节），软件复位用 NVIC_SystemReset()。
