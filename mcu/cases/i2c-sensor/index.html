I²C 读取温湿度

按“发命令 → 等转换 → 读原始字节”三步，经 I²C 读一颗温湿度传感器。

5 件硬件 8 步默认 STM32F407 / STM32G474（Cortex‑M4F）

目标

  • 把 I²C1 的 SCL/SDA 配成复用开漏，并说清为什么不能配成推挽
  • 用 HAL_I2C_IsDeviceReady 先探活，把“地址错 / 没上拉 / 没上电”三类问题分开
  • 按“发测量命令 → 等转换 → 读回原始字节”完成一次读取，并核对每一步返回值
  • 知道换算公式、CRC 与字节序都要照器件手册，案例只负责把原始数据正确拿回来

硬件清单

STM32F407 / STM32G474 开发板常见 I²C 温湿度传感器模块（如 SHT3x 类）外部上拉电阻（阻值按总线电容与速率核算）杜邦线逻辑分析仪（可选，用来看 ACK）

实现步骤

  1. 1① 先读手册，把三件事抄下来

    从器件手册或模块丝印上确认：7 位从机地址（丝印有可能印的是已左移的 8 位值）、触发测量的命令字或寄存器地址、一次测量返回多少字节以及转换需要多久。为什么先做这件事：地址、命令、长度、转换时间这四项只要错一个，现象都是“通信不通”，而代码本身看不出任何毛病。

  2. 2② 硬件先就位：上拉、供电、共地

    SCL/SDA 各接一个外部上拉到模块电源，确保模块上电并与 MCU 共地。为什么上拉是硬性要求：I²C 引脚只有开漏的下管，写 1 只是“放手”，没有上拉就根本没有高电平；内部弱上拉阻值很大，只够极短线的应急验证。

  3. 3③ 把引脚配成复用开漏

    PB6/PB7 配 GPIO_MODE_AF_OD，速度别选最低档，复用号按数据手册填（F4 上 I²C1 常见为 AF4）。为什么必须开漏：总线上多个器件共用两根线，推挽输出“推高”会与别的器件“拉低”直接对灌；开漏才允许线与，也才有多主仲裁。

  4. 4④ 初始化 I²C1 的外设参数

    ClockSpeed 先取 100 kbit/s（标准模式量级），7 位寻址，NoStretchMode 保持“允许时钟延展”，OwnAddress 设 0（只做主机）。为什么要允许延展：慢速传感器在转换期间可能拉住 SCL 不放，禁用延展会让这类器件直接被判超时。

  5. 5⑤ 探活：先只发地址，别急着读数据

    HAL_I2C_IsDeviceReady(&hi2c1, DevAddress, 3, 10) 只做 START + 地址 + 看 ACK。为什么值得单独一步：它能把“地址算错 / 没上拉 / 模块没上电”与“命令或数据理解错”彻底分开，后面的排查范围立刻缩小一半。

  6. 6⑥ 发测量命令，并检查返回值

    多数温湿度器件是“命令式”的：主机发 2 个字节的命令触发一次转换（有的器件是写寄存器）。命令长度、字节序、是否需要 CRC 都按手册来。为什么要检查返回值：HAL_ERROR 是 NACK 或仲裁失败，HAL_TIMEOUT 是总线卡住，两者的排查方向完全不同。

  7. 7⑦ 按手册等转换，再读回原始字节

    转换需要时间（具体见手册），等够之后用 HAL_I2C_Master_Receive 读回固定长度数据。为什么不能边发边读：从机在转换期间不响应数据请求，读早了会拿到旧值或 NACK；延时宁可留余量，也别“感觉差不多”。

  8. 8⑧ 先打印原始字节，再套手册公式换算

    把读回的每个字节打印出来，和手册里的示例数据格式对照：哪两个字节拼成一个量、字节序是高位在前还是低位在前、是否带 CRC。为什么停在这一步：换算系数与偏移是器件参数，必须来自手册；先确认“拿到的字节是对的”，再谈物理量算得准不准。

常见坑

错误现象怎么查 / 怎么改
SDA/SCL 没接外部上拉，或只靠内部弱上拉HAL_I2C_IsDeviceReady 一直失败；示波器看空闲电平只有 1 V 出头，上升沿是缓慢的“圆头”先万用表量空闲电平：开漏释放时两根线都应接近模块电源电压。不够就补外部上拉（按总线电容与速率核算），并确认引脚模式是 GPIO_MODE_AF_OD 而不是推挽。
地址没左移，或把丝印上的 8 位地址又左移了一次地址字节后的第 9 个时钟收到 NACK，探活一直失败；换个写法（比如把 0x?? 改成左移后的值）立刻通了HAL 的 DevAddress 要“7 位地址 << 1”。用 HAL_I2C_IsDeviceReady 扫一遍 0x08–0x77 找到真正应答的 7 位地址，再写进代码。
总线被从机拉死，BUSY 一直不释放上电第一次传输就超时，之后所有操作都返回 HAL_BUSY；示波器上 SDA 恒为低、SCL 空闲为高多半是从机在传输中途被复位、正拉着 SDA 等时钟。把 SCL 临时切成 GPIO 手动发 9 个以上时钟脉冲再补一个 STOP，然后重新初始化 I²C；长期方案是让从机先于 MCU 完成上电或加电源监控。
命令字、寄存器地址、字节序抄错探活能过，但读到的数据固定不变、或明显超出量程；换一个命令字就“活”了回手册核对：命令是 2 字节还是 1 字节、高低位谁先发、返回数据里是否夹着 CRC 字节。先把 raw[] 原样打印，和手册示例数据逐字节对照。
把读最后一个字节时的 NACK 当成通信故障，或干脆不检查返回值代码里一遇到 NACK 就报错退出，永远读不到数据；或者返回值不看，读到的全是 0 还以为是传感器坏了分清阶段：地址阶段的 NACK 才是“没人应答”，主机读最后一个字节回 NACK 是正常的收尾。用 HAL_I2C_Mem_Read 时这一步由 HAL 自动完成，不要自己再判错。
