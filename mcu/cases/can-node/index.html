CAN 节点收发

两块板各加一个收发器，配好位定时与过滤器，就能互相收到对方发来的 CAN 帧。

5 件硬件 8 步默认 STM32F407 / STM32G474（Cortex‑M4F）

目标

  • 说清 CANH/CANL 差分与显性/隐性，以及为什么只在总线两端各加一个 120 Ω
  • 按 PCLK1 与目标波特率算出 BRP/TS1/TS2，并说出采样点大约落在位时间的哪个位置
  • 用掩码模式过滤器只收关心的 ID，并在 FIFO0 回调里取帧、释放邮箱
  • 单板先回环自测、双板再上总线，能按 TEC/REC 与 ACK 错误定位物理层问题

硬件清单

STM32F407 开发板 × 2CAN 收发器模块 × 2（TJA1050 / SN65HVD230 一类）120 Ω 终端电阻 × 2双绞线一段 + 杜邦线USB-CAN 分析仪（可选，抓包与对照）

实现步骤

  1. 1① 先把物理层接对，再谈代码

    两个节点各一个收发器，CANH 对 CANH、CANL 对 CANL，用双绞线；只在总线两端各加一个 120 Ω。为什么第一步是接对线：CAN 的 ACK 与差分电平都在物理层，线不对时软件再对也发不出去。

  2. 2② 配时钟与复用引脚，确认 PCLK1

    打开 CAN1 与 GPIOB 时钟，PB8/PB9 配成复用推挽（AF9，具体复用号查数据手册复用表）。F407 上 CAN1 挂在 APB1，先记下 PCLK1 的频率——位定时的每个数都从它算出来。

  3. 3③ 算位定时，两个节点必须完全一致

    按 500 kbit/s 量级取一组参数：PCLK1 = 42 MHz 量级时，BRP=6、TS1=11、TS2=2，则 42 MHz / 6 / (1+11+2) = 500 kbit/s，采样点约 (1+11)/14 ≈ 85.7%（均为量级示意，必须按手册重算）。两边三个参数差一点，就会互相报位错误。

  4. 4④ 单板先回环自测

    把模式设成 CAN_MODE_LOOPBACK，自己发自己收，验证“过滤器 → FIFO → 回调”这条软件链路。为什么先回环：它把“软件写错”和“总线不通”两类问题分开了，排查范围立刻减半。

  5. 5⑤ 配过滤器：只放行你关心的 ID

    掩码模式下把标准 ID 左移 5 位放进 FilterIdHigh，掩码写 0x7FF << 5 表示 11 位全比较，命中进 FIFO0。不做过滤会把所有帧都收进来，CPU 来不及取就冲爆 FIFO，表现为“偶发丢帧”。

  6. 6⑥ 启动顺序不能颠倒

    HAL_CAN_Init → HAL_CAN_ConfigFilter → HAL_CAN_Start → HAL_CAN_ActivateNotification。过滤器必须在 Start 之前配好，否则启动瞬间收到的帧会因为“没有过滤器”被全部丢掉。

  7. 7⑦ 收发：发靠邮箱，收靠 FIFO

    HAL_CAN_AddTxMessage 把帧丢进空闲邮箱就返回，真正的仲裁、ACK 检查与重发全由硬件完成；接收在 HAL_CAN_RxFifo0MsgPendingCallback 里用 HAL_CAN_GetRxMessage 取帧，取完 FIFO 自动释放。

  8. 8⑧ 用错误计数器定位问题

    两块板对发，看 ID/DLC/数据是否符合预期；再用 MSR 里的错误计数器判断：TEC 飞涨基本是物理层（终端、波特率、没有第二节点应答 ACK），REC 涨则重点查接收侧采样点与过滤器。

常见坑

错误现象怎么查 / 怎么改
终端电阻没接，或只在板子上接了一个桌面上短线低速看着能通，一加长线或提速就满屏错误帧，TEC 飞涨直到总线关闭断电用万用表量 CANH 与 CANL 之间：两端各一个 120 Ω 时应量到 60 Ω 量级；量到 120 Ω 说明只有一个，量到很大说明一个都没接。终端只加在总线物理两端。
两个节点的 BRP / TS1 / TS2 不一致单板回环完全正常，一接总线双方都发不出去；逻辑分析仪量到的位宽与对方对不上按各自的 PCLK1 分别重算位定时（BRP = f_CAN / (波特率 × 位总 TQ 数)），核对采样点；两块板 PCLK1 不同则不能抄同一组参数。用示波器量一位的实际宽度交叉验证。
过滤器写错：ID 没左对齐、组没激活、FIFO 分配错TSR 显示发送成功，但 HAL_CAN_GetRxMessage 永远拿不到帧、接收中断不触发先把掩码全清零做“全通过”测试，确认硬件通路与中断没问题，再逐位收紧掩码。重点查 FA1R 是否激活、FFA1R 的 FIFO 分配、标准 ID 有没有左移 5 位。
总线上只有自己一个节点，却在正常模式下等发送成功AddTxMessage 返回成功，但邮箱一直不空，TEC 持续上涨并报 ACK 错误，最后总线关闭ACK 需要至少一个其他节点来拉低 ACK 槽。单板调试先改 CAN_MODE_LOOPBACK，或接第二块板/分析仪；这不是代码 bug，是拓扑缺了应答方。
两个节点用同一个 ID 发不同内容同一 ID 的报文时而来自另一个节点、内容被覆盖；同时发送时还会在数据段分叉、触发位错误与反复重传维护一张全网 ID 分配表（ID、发送节点、周期、含义），抓包按 ID 分组统计来源与周期。仲裁只解决“谁先说”，不解决“谁该用哪个 ID”。

第 1 / 6 步
步骤 1/6|① 总线空闲（隐性 1）

总线没人用时，CANH/CANL 都被终端电阻拉到同一电平，差分电压接近 0 → 逻辑 1（隐性）。任何节点检测到显性位（0）就开始同步。

第 1 / 7 步

场景固定：A、B、C 分别在 0.05 / 0.18 / 0.30（示意时间）请求中断，每段 ISR 用时相同——时间上有重叠，所以才会发生抢占。 调抢占优先级看"谁打断谁"，调子优先级看"同时挂起时谁先跑"。

A · 按键 EXTI0EXTI0_IRQHandler
B · 定时器 TIM2TIM2_IRQHandler
C · 串口 USART1USART1_IRQHandler
步骤 1/7|外设置起中断请求

按键按下 → EXTI 检测到边沿 → 置挂起标志（EXTI->PR 对应位）。注意：此时中断还没"发生"，只是"有请求"。定时器溢出、串口收到字节同理。
