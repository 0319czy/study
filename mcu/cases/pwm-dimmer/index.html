PWM 调光

在 TIM2_CH1 上输出 1 kHz PWM，只改 CCR 就改变 LED 亮度。

5 件硬件 8 步默认 STM32F407 / STM32G474（Cortex‑M4F）

目标

  • 用 f = TIMclk / ((PSC+1)(ARR+1)) 手算出 1 kHz，并说清两个 +1 的来历
  • 按“时钟 → 引脚复用 → 时基 → 通道 → 启动”的顺序配好一路 PWM
  • 运行中用 __HAL_TIM_SET_COMPARE 只改占空比，理解为什么频率不变
  • 知道 0% 与 100% 的边界条件，以及预装载（ARPE / OC1PE）如何避免毛刺

STM32F407 / STM32G474 开发板LED + 330 Ω 量级限流电阻（示意值）可选：N 沟道 MOS 管，用来驱动更大电流的灯带杜邦线示波器（可选，量频率与占空比）

实现步骤

  1. 1① 先确认 TIM2 的计数时钟是多少

    查你工程的时钟树：F407 上 TIM2 挂在 APB1，APB1 定时器时钟常见为 84 MHz（示意，以参考手册与 CubeMX 显示为准）。为什么先做这一步：后面所有频率计算都以 TIMclk 为分子，取错总线频率，频率就会差一倍，怎么调 ARR 都对不上。

  2. 2② 开时钟，把 PA0 配成复用推挽

    打开 TIM2 与 GPIOA 的时钟，把 PA0 配成 GPIO_MODE_AF_PP，复用号填 TIM2_CH1 对应的值（F4 上为 AF1，查数据手册确认）。为什么用复用而不是普通输出：PWM 波形由定时器比较器直接产生，CPU 不参与，波形稳定、无软件抖动。

  3. 3③ 用公式定 PSC 与 ARR

    84 MHz / (83+1) = 1 MHz 计数频率，1 MHz / (999+1) = 1 kHz。为什么要盯着 +1：实际分频是 PSC+1、一个周期是 ARR+1 个计数点，漏掉任何一个，频率就正好差一档。调频率优先动 PSC，调占空比才动 CCR。

  4. 4④ 配通道：PWM 模式 1 + 初始占空比

    OCMode 选 TIM_OCMODE_PWM1、Pulse 先给 300（30%）、OCPolarity 高有效。为什么高有效：LED 接在引脚与地之间时高电平点亮，占空比就等于亮度比例；如果驱动级是低有效，就改成低极性，别在代码里靠“取反 CCR”绕。

  5. 5⑤ 打开预装载并启动

    AutoReloadPreload 设为使能（等于 ARPE），HAL_TIM_PWM_ConfigChannel 会打开 CCR 预装载（OC1PE），最后 HAL_TIM_PWM_Start 同时启动计数器与通道输出。为什么必须 Start 两次都做：只开 Base_Start 时计数器在跑，但通道没接到引脚，示波器上什么都看不到。

  6. 6⑥ 主循环里按档位改 CCR

    把亮度分成 0–10 共 11 档，用 (step × (ARR+1)) / 10 算出 CCR，再 __HAL_TIM_SET_COMPARE 写进去。为什么只改 CCR：ARR 不动，一个周期的时间就不变，所以频率不变、只有高电平宽度改变——这就是“调光不调频”。

  7. 7⑦ 上板验证频率、占空比与边界

    示波器量周期应为 1 ms、高电平宽度应为周期的 30%；再把 step 调到 0 和 10，确认 0% 时恒低、100% 时恒高。为什么专门测边界：CCR=0 与 CCR≥ARR+1 是两种特殊情况，很多“调不到全亮/全灭”的问题就卡在这里。

  8. 8⑧ 按负载决定要不要驱动级

    小电流 LED 可以直接由引脚串限流电阻驱动；灯带、多个 LED 或电机必须经 MOS 管 / 三极管，并注意共地与续流。为什么：GPIO 的驱动电流有明确上限（见数据手册 I/O 特性），硬扛大电流会拉低电平、发热，甚至复位。

错误现象怎么查 / 怎么改
只调了 HAL_TIM_Base_Start，没有调 HAL_TIM_PWM_Start（或通道使能没打开）程序跑得很正常，示波器在引脚上却看不到任何波形，万用表量一直是低（或一直是高）确认调用的是 HAL_TIM_PWM_Start；再核对复用号、CCR 通道号与 CCMR/CCER 的通道使能，三重确认后再怀疑硬件。
PSC / ARR 忘了 +1，或把 PCLK1 当成定时器时钟实际频率正好是设计值的一半或两倍，怎么微调 ARR 都对不上用 HAL_RCC_GetPCLK1Freq 取实际总线频率，按手册判断定时器时钟是否要 ×2，再手算 TIMclk/((PSC+1)(ARR+1))，最后用示波器量一个周期验证。
运行中直接改 CCR / ARR，却没有开预装载每次调亮度或频率的瞬间，LED 闪一下、示波器上出现一个明显偏窄的脉冲打开 ARPE 与 OCxPE（HAL 里是 AutoReloadPreload 与通道配置），让新值在更新事件生效；改 PSC 后主动等一次更新事件再观察。
占空比按“百分数”直接写进 CCR，或想调 100% 却只写到 ARR亮度只能到一半左右；或者怎么加 CCR 都到不了全亮，最亮和最暗差得很少CCR 是计数点数不是百分数：CCR = 档位 × (ARR+1) / 总档数；100% 需要 CCR ≥ ARR+1，0% 则是 CCR = 0。
用 GPIO 直驱大电流负载，或驱动级没共地LED 偏暗、亮度不稳定；接灯带时引脚发热、电压被拉低，严重时一动作就复位引脚只出控制信号：加 MOS 管 / 三极管 / 恒流驱动，感性负载加续流二极管；(N)MOS 低边驱动时源极与 MCU 共地。电流上限见数据手册 I/O 特性。
