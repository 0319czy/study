按键中断点灯

按键拉出下降沿，EXTI 打断 CPU，主循环消抖后翻转 LED。

5 件硬件 8 步默认 STM32F407 / STM32G474（Cortex‑M4F）

目标

  • 把 PA5 配成推挽输出、PA0 配成带内部上拉的下降沿中断输入
  • 说出 PA0 → SYSCFG → EXTI → NVIC → ISR 这条链路，知道少一段会看到什么现象
  • 在回调里只记录时间戳，把消抖与点灯放到主循环，理解中断里为什么不能延时
  • 用 volatile 共享变量 + HAL_GetTick 时间戳写出不阻塞的按键处理

STM32F407 / STM32G474 开发板LED + 330 Ω 量级限流电阻（示意值）轻触按键（两脚或四脚均可）杜邦线 / 面包板ST-Link 或 DAP-Link 调试器

实现步骤

  1. 1① 建工程，先把时钟与 SysTick 定下来

    用 CubeMX 选芯片、把 HCLK 配到板子能稳定跑的频率（F407 上限 168 MHz 一类，以数据手册为准），生成 HAL 工程。为什么先做这一步：中断的响应延迟、HAL_GetTick 的 1 ms 时基都建立在系统时钟与 SysTick 上，时钟不对，后面所有时间判断都会跟着偏。

  2. 2② 开 GPIOA 时钟，先把 LED 点起来

    先调用 HAL_GPIO_WritePin 把 PA5 写成高电平，再把它配成 GPIO_MODE_OUTPUT_PP、低速档。为什么要先写初值：切成输出的那一瞬间 ODR 复位值是 0，会先把 LED 拉低闪一下；而时钟没开时写 MODER 等于写进空气，函数照样返回、引脚毫无反应。

  3. 3③ 把 PA0 配成中断输入

    gpio.Mode = GPIO_MODE_IT_FALLING、gpio.Pull = GPIO_PULLUP。为什么这样配：按键另一端接 GND，松开时必须靠上拉把电平定高，否则悬空引脚会随机跳变、反复触发中断；选下降沿是因为“按下”的那一刻正好是 1→0。

  4. 4④ 开 SYSCFG 时钟，确认 EXTI0 归属 PORTA

    调用 __HAL_RCC_SYSCFG_CLK_ENABLE()，HAL 会在 HAL_GPIO_Init 里写 SYSCFG->EXTICR[0] 把 EXTI0 接到 PORTA。为什么要单独开这个时钟：EXTI 线只按引脚号分组，PA0 / PB0 / PC0 共用 EXTI0，必须选一个端口；SYSCFG 时钟没开，这一步写不进去，现象是“NVIC 使能了、按键却完全没反应”。

  5. 5⑤ 配 NVIC，放行 EXTI0_IRQn

    HAL_NVIC_SetPriority(EXTI0_IRQn, 5, 0) 给优先级，HAL_NVIC_EnableIRQ(EXTI0_IRQn) 写 NVIC->ISER。为什么要两步：外设侧的 EXTI->IMR 只是第一道门，NVIC 不放行 CPU 根本不会跳进 ISR；优先级先给中间值（示意），日后加串口、定时器中断还有调整余地。

  6. 6⑥ 写 ISR 与回调，只记时间戳

    EXTI0_IRQHandler 里只调用 HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0)；回调里写 g_keyTick = HAL_GetTick()、g_keyEvent = 1。为什么这么克制：HAL 会先清 EXTI->PR 再回调，自己写容易漏清；回调里一旦延时或打印，中断被拉长，别的中断和主循环都会被拖慢。

  7. 7⑦ 主循环消抖，再翻转 LED

    等 (HAL_GetTick() - g_keyTick) >= 20 之后复读 PA0，仍为低才 HAL_GPIO_TogglePin。为什么要再读一次：机械按键按下瞬间会抖十几次，中断可能连着进好几次；隔 20 ms（示意值）再确认电平，才能把“抖动”和“真按下”分开，而且全程不阻塞。

  8. 8⑧ 上板验证，按链路逐段定位

    先量松开时 PA0 是否接近 VDD；再在调试器里看按下时 EXTI->PR 是否置位、NVIC->ISER 对应位是否为 1；最后看回调有没有进。为什么按这个顺序：它正好对应“引脚与上下拉 → EXTI/SYSCFG → NVIC/ISR”三段，能一次判断断在哪，而不是盲改代码。

忘记开 SYSCFG 时钟，或把 PA0 配成普通输入却没配中断模式NVIC 已使能、调试器里 EXTI->IMR 也像是对的，但按键按下时 EXTI->PR 不置位、回调永远不进先加 __HAL_RCC_SYSCFG_CLK_ENABLE()，再确认 gpio.Mode 用的是 GPIO_MODE_IT_FALLING 而不是 GPIO_MODE_INPUT；前者才会写 SYSCFG->EXTICR 与 EXTI 的边沿位。
上下拉方向配反，或按键引脚一直悬空不按也会自己触发、按一下 LED 连闪好几次；万用表量松开时 PA0 只有 1 V 出头甚至乱跳按键另一端接 GND 就必须配 GPIO_PULLUP（松开为高）。先量电平确认，再谈软件消抖；电平本身就是错的，消抖救不回来。
在 ISR 或回调里调用 HAL_Delay、printf 做“消抖”按键偶尔没反应、串口开始丢字节、别的中断响应变慢，甚至看门狗复位中断里只取时间戳、置标志；延时与打印全部移到主循环。要确认中断占用时间，可在 ISR 入口/出口翻转一个空闲 GPIO，用示波器量宽度。
共享变量没加 volatile，或 ISR 里漏清 EXTI->PR主循环一直看不到事件标志；或者只进一次中断，之后按键完全没反应给中断与主循环共享的标志加 volatile；ISR 必须走 HAL_GPIO_EXTI_IRQHandler 或自己写 EXTI->PR = 位掩码 清标志。用调试器看 EXTI->PR 是否一直为 1 最快。
同一编号的引脚在两个端口上都配了 EXTI两个按键只有一个能用，或者两个都时灵时不灵EXTI0 只能归属 PA0 / PB0 / PC0 中的一个：查 SYSCFG->EXTICR[0] 的值，确保只配置了实际使用的那个端口。
