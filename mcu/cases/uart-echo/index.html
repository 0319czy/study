UART 收发回显

把 USART1 配成 115200 8N1，收到字节进中断，放进环缓冲后原样回显。

4 件硬件 8 步默认 STM32F407 / STM32G474（Cortex‑M4F）

目标

  • 把 USART1 配成 115200 8N1，并说清 HAL_UART_Init 到底替你算了什么
  • 打通“外设中断使能 + NVIC 使能”两道门，写对 USART1_IRQHandler
  • 在回调里先重挂接收、再把字节放进环缓冲，由主循环负责发送
  • 用发 0x55 量位宽的方法，把乱码问题收敛到波特率与时钟源

硬件清单

STM32F407 / STM32G474 开发板USB-TTL 串口模块（CH340 / CP2102 一类）杜邦线（TX、RX、GND 三根）PC 端串口助手

实现步骤

  1. 1① 确认串口资源与引脚复用

    在数据手册里确认 PA9 / PA10 能复用成 USART1_TX / USART1_RX（F4 上常见为 AF7），并确认这两根脚确实引到了排针。为什么先查表：复用编号随型号与封装变化，抄错 AF 的典型现象是“初始化返回成功、引脚上一点波形都没有”。

  2. 2② 开时钟，配 TX/RX 引脚

    打开 GPIOA 与 USART1 的时钟；TX 配 GPIO_MODE_AF_PP（复用推挽），RX 配复用输入并加上拉。为什么要上拉：RX 在对方没驱动时容易悬空，弱上拉能让它保持空闲高电平，减少误起的起始位。

  3. 3③ 填初始化结构体：115200 8N1

    BaudRate = 115200、WordLength = 8 位、StopBits = 1、Parity = NONE、Mode = TX_RX、OverSampling = 16。为什么这些字段要一起看：它们共同决定 BRR 与 CR1/CR2 的最终值，任何一项与对端不一致，都会表现为乱码或帧错误。

  4. 4④ 调用 HAL_UART_Init

    HAL 用总线时钟与过采样算出 BRR 并写入，同时配好帧格式、使能收发。为什么它不够：HAL_UART_Init 不会帮你开 NVIC，也不会启动接收——这两件事必须自己做，否则“数据到了、回调不进”。

  5. 5⑤ 开 NVIC，放行 USART1_IRQn

    HAL_NVIC_SetPriority(USART1_IRQn, 5, 0) 再 HAL_NVIC_EnableIRQ(USART1_IRQn)。为什么是两道门：外设侧的 RXNEIE 只是“我想中断”，NVIC 的使能位才是“CPU 允许你打断我”，缺一个都不进 ISR。

  6. 6⑥ 挂第一次中断接收

    HAL_UART_Receive_IT(&huart1, &g_rxByte, 1)：收满 1 个字节进回调。为什么要强调“第一次”：这个函数是一次性的，收完 HAL 把状态改回 READY，必须再次调用才会继续收。

  7. 7⑦ ISR 与回调：先取字节、立刻重挂、再入环缓冲

    USART1_IRQHandler 只调 HAL_UART_IRQHandler；回调里先把 g_rxByte 拷到局部变量，马上重挂 HAL_UART_Receive_IT，再把字节写进环缓冲。为什么是这个顺序：先拷贝避免下一个字节覆盖，先重挂把“没在收”的窗口压到最小，写缓冲则是非阻塞的搬运动作。

  8. 8⑧ 主循环发送，并用 0x55 验证

    主循环从环缓冲取字节，HAL_UART_Transmit 发回 PC；串口助手应当逐字回显。为什么用 0x55：它的二进制是 01010101，线上是规整方波，量一个位的宽度就能反推实际波特率，比盯着配置项有效得多。

常见坑

错误现象怎么查 / 怎么改
TX/RX 没交叉，或两块板没有共地一边完全没数据、另一边毫无反应；偶尔收到了也全是乱码，手碰一下线又“好一会儿”先确认板 TX 接模块 RX、板 RX 接模块 TX，再确认 GND 相连；用示波器或逻辑分析仪看发送端 TX 有没有波形，没有就先查引脚复用与时钟。
只在初始化里挂了一次 HAL_UART_Receive_IT，回调里没有重新挂只能收到第一个字节，之后回调再也不进；调试器里句柄的接收状态一直是 READY 而不是 BUSY_RX在 HAL_UART_RxCpltCallback 末尾再次调用 HAL_UART_Receive_IT；要连续收大量数据就改成环缓冲 + DMA，别靠反复重挂硬撑。
中断函数名与向量表不一致，或忘了 HAL_NVIC_EnableIRQ数据确实到了，USART 的接收标志也置位，但回调从不执行，程序像“没收到”一样对照启动文件确认 USART1_IRQHandler 拼写，确认 NVIC 使能已调用、中断服务函数里调了 HAL_UART_IRQHandler；三步缺一不可。
双方波特率/校验位不一致，或一边用未校准的内部 RC低速勉强能通、高速必乱；偶发帧错误或校验错误，换块板子就好发 0x55 量一个位的宽度反推实际波特率，再套误差公式核对 BRR 量化误差与时钟源偏差；总误差先压到 2–3% 量级（以手册与实测为准）。
在接收回调里做阻塞发送、printf 或延时连续发数据时开始丢字节，接收溢出标志被置起，回显内容缺字符中断里只取数、入环缓冲；发送交给主循环或 DMA。出现溢出错误时补一个 HAL_UART_ErrorCallback，在错误处理后重新挂接收。

第 1 / 12 步
步骤 1/12|空闲：线保持高电平

没有数据时 TX 线保持高电平（空闲态）。接收方一直在等"从高变低"的那个跳变——这就是起始位的意义：它告诉对方"注意，一帧来了"。

步骤 1/7|外设置起中断请求

按键按下 → EXTI 检测到边沿 → 置挂起标志（EXTI->PR 对应位）。注意：此时中断还没"发生"，只是"有请求"。定时器溢出、串口收到字节同理。
