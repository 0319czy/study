嵌入式 Linux 系统构建:从工具链到能启动的镜像

方向目标:亲手产出一套最小系统——内核 + 设备树 + rootfs——再用目标 sysroot 交叉编译设备程序, 最后在 QEMU 或真实板卡上启动并验证。重点是每一步都能解释、每个产物都能检查,而不是照着命令粘贴。

对应学习路线阶段 04 / 07 · 前置:Linux 用户态入门 · C 与工程工具

  • 读出交叉工具链前缀每一段的含义,并判断它与目标架构、浮点 ABI 是否匹配。

3. 原理与图示

"构建一个 Linux 系统"不是编译一个程序,而是凑齐四个互相约束的部件:工具链负责生成目标代码,内核负责管硬件,DTB 告诉内核板子长什么样,rootfs 提供用户空间。四者版本与 ABI 必须对齐。

[交叉工具链]        [Linux 内核 + DTB]        [rootfs]
gcc/binutils/glibc   zImage / Image           BusyBox + libc
arm 或 aarch64       vexpress-*.dtb           /etc /lib /usr/bin
      │                    │                        │
      └────────────────────┴───────────┬────────────┘
                                       ▼
                        zImage/Image + dtb + rootfs.ext2
                                       ▼
             烧录 → BootROM → SPL → U-Boot → kernel + DTB → init → 你的程序

3.1 四个部件与检查点

部件是什么怎么确认
交叉工具链在 x86 主机上生成 ARM 指令、按目标 ABI 链接的 gcc/binutils/glibcarm-linux-gnueabihf-gcc -dumpmachine 应输出 arm-linux-gnueabihf
内核调度、内存、驱动、文件系统;由 defconfig 决定编进哪些驱动产物 zImage(arm)或 Image(arm64);启动日志第一行有版本号
DTB板级硬件的结构化描述:内存地址、串口、GPIO、MMC文件名与板子匹配;可用 dtc -I dtb -O dts 反编译核对
rootfs启动后挂载成 / 的目录树:init、库、配置、你的程序存在 /sbin/init、/etc/inittab;ELF 架构与内核一致

3.2 工具链前缀怎么读

arm-linux-gnueabihf-gcc
│    │      │    └── ABI:glibc + EABI5 + hard-float(硬浮点调用约定)
│    │      └─────── C 库:glibc(gnu)
│    └────────────── 目标系统:linux
└─────────────────── 目标指令集:arm(32 位)

aarch64-linux-gnu-gcc   → 64 位 ARMv8 + linux + glibc
arm-linux-gnueabi-gcc   → soft-float 约定,目标库不能与 gnueabihf 混用

名字里的 gnueabihf 不只是"编译器名字":它决定了浮点参数怎么传、结构体怎么对齐、链接哪个动态加载器。用 armhf 编译器链接 soft-float 的库,常见结果是能编译、上板就崩或直接跑不起来。

3.3 为什么主机 gcc 编译的程序不能直接上板

  • 指令集不同:主机产物是 x86-64,板端 CPU 不认;内核执行时直接 Exec format error。
  • 动态加载器路径不同:x86 程序写死 /lib64/ld-linux-x86-64.so.2,armhf 需要 /lib/ld-linux-armhf.so.3。板端没有这个文件,报 "No such file or directory"——注意报的是加载器,不是程序。
  • ABI 不同:long 在 arm32 是 4 字节、在 x86-64 是 8 字节;浮点传参、结构体对齐也可能不同。混用会静默算错。

3.4 sysroot / target / images 的分工

路径给谁用内容改动影响
output/<board>/staging/编译器(--sysroot)目标头文件、.so/.a、pkg-config只影响链接;不应手改
output/<board>/target/打包 rootfs运行期目录树(已裁剪)下一次 make 会被覆盖;程序要走 overlay 或 package
output/<board>/images/rootfs.ext2烧录/挂载ext2/3/4 镜像(Buildroot 固定名为 rootfs.ext2)最终交付物;大小与分区表要对齐
新手最常踩的坑:把程序 install 到 target/usr/bin,验证成功后跑一次 make,程序消失——因为 target/ 是构建产物。正确做法是放进 rootfs-overlay/ 或写成 Buildroot package,让每次构建都自动包含。

3.5 Buildroot 的输出目录

output/stm32mp1/
├── images/    zImage  stm32mp157c-dk2.dtb  rootfs.ext2  sdcard.img
├── target/    rootfs 的内容(构建产物,不要当源码目录)
├── staging/   sysroot:头文件 + 目标库
├── host/      主机侧工具(交叉工具链、mkimage 等)
└── build/     各软件包的构建目录与日志(排错先看这里)

Buildroot 的 ext 镜像固定命名为 rootfs.ext2;在 menuconfig 里选 ext4 变体时,它仍叫 rootfs.ext2,另外生成一个 rootfs.ext4 符号链接。不要把"文件名 ext2"误读成"文件系统只能是 ext2"。

Buildroot 与 Yocto 的取舍:Buildroot 是"一份配置 + 全量构建",简单直接,适合单一产品和小系统;Yocto 用层与配方做增量、可组合,适合多板型/长期维护但学习曲线更陡。本页选 Buildroot,是因为它能把"一次构建"压缩到可理解的范围。

3.6 启动链与三个高频失败点

BootROM → SPL/TPL → U-Boot → Linux + DTB → /sbin/init(BusyBox)→ 你的程序
  • DTB 不匹配:内核起来了但找不到串口/MMC,表现为串口静默或卡在 early boot。
  • root= 写错:内核打印 "No filesystem could mount root",通常是分区号或文件系统类型不对。
  • init 缺失或不可执行:内核打印 "Run /sbin/init as init process" 后 panic,检查 rootfs 里有没有 BusyBox 与 /etc/inittab。

    /* buildplan.c —— 交叉编译构建计划检查器(教学用,无任何外部依赖)
 *
 * 读取 key=value 形式的构建配置,在真正开跑前检查:
 *   架构(ARCH)与工具链前缀(CROSS_COMPILE)是否匹配、浮点 ABI 是否明确、
 *   内核镜像名/DTB 路径是否与架构一致,并输出内核、设备程序、rootfs 安装
 *   与校验命令。
 *
 * 编译: gcc -std=c11 -O2 -Wall -Wextra -Werror -o buildplan buildplan.c
 * 运行: ./buildplan build.env
 * 退出码: 0 = 通过(可能带 WARN);2 = 架构/前缀不匹配;1 = 用法或读文件错误
 */
#include <ctype.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define MAX_CFG 24

struct cfg {
  char key[64];
  char val[256];
};

static struct cfg g_cfg[MAX_CFG];
static int g_n;

static const char *cfg_get(const char *key)
{
  for (int i = 0; i < g_n; i++)
    if (strcmp(g_cfg[i].key, key) == 0)
      return g_cfg[i].val;
  return NULL;
}

static char *trim(char *s)
{
  while (isspace((unsigned char)*s))
    s++;
  size_t n = strlen(s);
  while (n > 0 && isspace((unsigned char)s[n - 1]))
    s[--n] = '\0';
  return s;
}

static int load_cfg(const char *path)
{
  FILE *fp = fopen(path, "r");
  if (!fp) {
    perror(path);
    return -1;
  }
  char line[512];
  while (fgets(line, sizeof line, fp)) {
    char *hash = strchr(line, '#');
    if (hash)
      *hash = '\0';
    char *s = trim(line);
    if (!*s)
      continue;
    char *eq = strchr(s, '=');
    if (!eq)
      continue;
    *eq = '\0';
    char *key = trim(s);
    char *val = trim(eq + 1);
    size_t vl = strlen(val);
    if (vl >= 2 && (val[0] == '"' || val[0] == '\'') && val[vl - 1] == val[0]) {
      val[vl - 1] = '\0';
      val++;
    }
    if (g_n >= MAX_CFG)
      break;
    snprintf(g_cfg[g_n].key, sizeof g_cfg[g_n].key, "%s", key);
    snprintf(g_cfg[g_n].val, sizeof g_cfg[g_n].val, "%s", val);
    g_n++;
  }
  fclose(fp);
  return 0;
}

/* 去掉末尾 '/',避免拼出 a//b */
static void clean_path(const char *in, char *out, size_t n)
{
  snprintf(out, n, "%s", in ? in : "");
  size_t l = strlen(out);
  while (l > 1 && out[l - 1] == '/')
    out[--l] = '\0';
}

/* ROOTFS_TARGET 以 /target 结尾时,同级的 staging 就是 sysroot */
static void derive_sysroot(const char *target, char *out, size_t n)
{
  clean_path(target, out, n);
  size_t l = strlen(out);
  const char *suffix = "/target";
  size_t sl = strlen(suffix);
  if (l > sl && strcmp(out + l - sl, suffix) == 0)
    out[l - sl] = '\0';
  strncat(out, "/staging", n - strlen(out) - 1);
}

static int mismatch(const char *arch, const char *prefix)
{
  if (!strcmp(arch, "arm")) {
    if (strncmp(prefix, "arm-", 4) != 0)
      return 1;
    if (!strstr(prefix, "gnueabi"))
      return 2;
  } else if (!strcmp(arch, "arm64")) {
    if (strncmp(prefix, "aarch64-", 8) != 0)
      return 1;
    if (!strstr(prefix, "gnu"))
      return 2;
  } else {
    return 3;
  }
  return 0;
}

int main(int argc, char **argv)
{
  if (argc != 2) {
    fprintf(stderr, "用法: %s build.env\n", argv[0]);
    return 1;
  }
  if (load_cfg(argv[1]) != 0)
    return 1;

  const char *board = cfg_get("BOARD");
  const char *arch = cfg_get("ARCH");
  const char *prefix = cfg_get("CROSS_COMPILE");
  const char *defconfig = cfg_get("KERNEL_DEFCONFIG");
  const char *dtb = cfg_get("DTB");
  const char *kdir = cfg_get("KERNEL_DIR");
  const char *rootfs = cfg_get("ROOTFS_TARGET");
  const char *app = cfg_get("APP_SRC");
  const char *app_out = cfg_get("APP_OUT");

  if (!board || !arch || !prefix || !kdir || !rootfs || !app) {
    fprintf(stderr, "缺少必填项: BOARD / ARCH / CROSS_COMPILE / KERNEL_DIR / ROOTFS_TARGET / APP_SRC(可选 KERNEL_DEFCONFIG)\n");
    return 1;
  }
  if (!defconfig)
    defconfig = "defconfig";
  if (!dtb)
    dtb = "board.dtb";
  if (!app_out)
    app_out = "build/device_app";

  char kdir_c[256], rootfs_c[256], app_c[256], app_out_c[256];
  char sysroot[1024], kernel_img[1024], dtb_path[1024], images_dir[1024], rootfs_img[1024];
  char app_dir[256];
  clean_path(kdir, kdir_c, sizeof kdir_c);
  clean_path(rootfs, rootfs_c, sizeof rootfs_c);
  clean_path(app, app_c, sizeof app_c);
  clean_path(app_out, app_out_c, sizeof app_out_c);
  derive_sysroot(rootfs_c, sysroot, sizeof sysroot);
  clean_path(app_out_c, app_dir, sizeof app_dir);
  {
    char *slash = strrchr(app_dir, '/');
    if (slash)
      *slash = '\0';
    else
      strcpy(app_dir, ".");
  }

  int is64 = strcmp(arch, "arm64") == 0;
  snprintf(kernel_img, sizeof kernel_img, "%s/arch/%s/boot/%s", kdir_c, is64 ? "arm64" : "arm",
           is64 ? "Image" : "zImage");
  clean_path(rootfs_c, images_dir, sizeof images_dir);
  {
    char *slash = strrchr(images_dir, '/');
    if (slash)
      *slash = '\0';
  }
  strncat(images_dir, "/images", sizeof images_dir - strlen(images_dir) - 1);
  snprintf(dtb_path, sizeof dtb_path, "%s/%s", images_dir, dtb);
  snprintf(rootfs_img, sizeof rootfs_img, "%s/rootfs.ext2", images_dir);

  int bad = mismatch(arch, prefix);
  int hard = strstr(prefix, "gnueabihf") != NULL;
  size_t pl = strlen(prefix);
  int prefix_ok = pl > 0 && prefix[pl - 1] == '-';

  printf("== 构建计划 / linux-build ==\n");
  printf("目标板      : %s\n", board);
  printf("架构        : %s (%s)\n", arch, is64 ? "64-bit, AArch64" : "32-bit, EABI5");
  printf("工具链前缀  : %s\n", prefix);
  printf("内核源码    : %s\n", kdir_c);
  printf("rootfs 根   : %s\n", rootfs_c);
  printf("sysroot     : %s\n", sysroot);
  printf("程序源码    : %s\n\n", app_c);

  printf("[静态检查]\n");
  if (bad == 0)
    printf("  OK    架构与前缀匹配(%s → %s)\n", arch, prefix);
  else if (bad == 1)
    printf("  FAIL  前缀与架构不匹配: %s 应使用 %s\n", arch,
           is64 ? "aarch64-*-gnu-*" : "arm-*-gnueabi*");
  else if (bad == 2)
    printf("  FAIL  前缀缺少 C 库标识(gnueabi / gnu)\n");
  else
    printf("  FAIL  不支持的 ARCH=%s(只接受 arm / arm64)\n", arch);

  if (!is64)
    printf("  %s  浮点 ABI: %s\n", hard ? "OK  " : "WARN",
           hard ? "hard-float(gnueabihf),与 Buildroot 默认一致" : "soft/softfp(gnueabi),确认板端 FPU 使用方式");
  printf("  %s  前缀以 '-' 结尾,可直接拼接 gcc\n", prefix_ok ? "OK  " : "WARN");

  if (strstr(sysroot, "/staging") != NULL)
    printf("  OK    sysroot 由 ROOTFS_TARGET 推导(同级 staging)\n");
  else
    printf("  WARN  rootfs 路径不以 /target 结尾,sysroot 可能不准\n");
  printf("  NOTE  本工具只做静态一致性检查,不访问内核/rootfs 文件系统\n\n");

  printf("[1/5] 内核与设备树\n");
  printf("  make -C %s ARCH=%s CROSS_COMPILE=%s %s\n", kdir_c, arch, prefix, defconfig);
  printf("  make -C %s ARCH=%s CROSS_COMPILE=%s -j$(nproc) %s dtbs\n\n", kdir_c, arch, prefix,
         is64 ? "Image" : "zImage");

  printf("[2/5] 设备程序(动态链接,使用目标 rootfs 的 sysroot)\n");
  printf("  mkdir -p %s\n", app_dir);
  printf("  %sgcc -O2 -Wall -Wextra --sysroot=%s -o %s %s\n", prefix, sysroot, app_out_c,
         app_c);
  printf("  %sstrip %s\n\n", prefix, app_out_c);

  printf("[3/5] 安装进 rootfs\n");
  printf("  install -D -m 0755 %s %s/usr/bin/device_app\n\n", app_out_c, rootfs_c);

  printf("[4/5] 产物路径\n");
  printf("  内核    %s\n", kernel_img);
  printf("  DTB     %s\n", dtb_path);
  printf("  程序    %s\n", app_out_c);
  printf("  rootfs  %s\n", rootfs_img);
  printf("  (dtb 由内核/Buildroot 安装到 images;若没有,在 %s/arch/%s/boot/dts/ 下按板名查找)\n\n",
         kdir_c, is64 ? "arm64" : "arm");

  printf("[5/5] 校验(在主机上做,不需要上板)\n");
  printf("  file %s\n", app_out_c);
  printf("  %sreadelf -h %s | grep -E 'Class|Machine'\n", prefix, app_out_c);
  printf("  期望    %s\n", is64 ? "ELF 64-bit, Machine: AArch64" : "ELF 32-bit, Machine: ARM");

  return bad == 0 ? 0 : 2;
}

        展开 device_app.c(本机 gcc 编译通过;目标端交叉编译待执行)
        
    /* device_app.c —— 最小设备自检程序(只用 libc,先在本机验证逻辑)
 * 编译: gcc -O2 -Wall -Wextra -Werror -o device_app device_app.c
 * 目标端: arm-linux-gnueabihf-gcc -O2 --sysroot=$SYSROOT -o device_app device_app.c
 */
#include <stdio.h>
#include <string.h>

static void first_line(const char *path, char *out, size_t n)
{
  FILE *fp = fopen(path, "r");
  if (!fp) {
    snprintf(out, n, "(missing)");
    return;
  }
  if (!fgets(out, (int)n, fp))
    out[0] = '\0';
  fclose(fp);
}

int main(void)
{
  char model[128] = {0};
  char uptime[64] = {0};

  first_line("/proc/device-tree/model", model, sizeof model);
  first_line("/proc/uptime", uptime, sizeof uptime);
  model[strcspn(model, "\r\n")] = '\0';
  uptime[strcspn(uptime, "\r\n")] = '\0';

  printf("board  : %s\n", model);
  {
    double up = 0.0;
    if (sscanf(uptime, "%lf", &up) == 1)
      printf("uptime : %.2f s\n", up);
    else
      printf("uptime : %s s\n", uptime);
  }
  printf("status : ok\n");
  return 0;
}

    6. 故障排查
    
      
    
        
    现象检查步骤预期结果下一分支
    
        
    内核打印 "No filesystem could mount root"核对内核 cmdline 的 root= 与镜像分区表:fdisk -l sdcard.img;确认 rootfs 文件系统类型(ext2/3/4,镜像名仍为 rootfs.ext2)且分区号对root= 指向真实存在的分区,文件系统类型匹配分区号错 → 改 root=/dev/mmcblk0pN;无分区表 → 查 genimage.cfg
    
        
    串口完全没有输出确认波特率 115200 8N1、TX/RX/GND 交叉连接、console= 与 DTB 串口一致;换一根线上电能看到 U-Boot 字符无 U-Boot → 查启动拨码/SPL;有 U-Boot 无内核 → 查 loadaddr 与镜像类型
    
        
    板端运行程序报 "No such file or directory"file device_app;readelf -l | grep interpreter;ls /lib/ld-linux-armhf.so.3解释器存在,ELF 架构为 ARM缺加载器/库 → 用目标 sysroot 重链或静态编译;架构错 → 换工具链前缀
    
        
    编译时报找不到目标头文件确认 --sysroot 指向 output/<board>/staging;ls $SYSROOT/usr/include;检查包是否已编头文件存在,路径拼写正确包未启用 → 开对应 BR2_PACKAGE_*;路径错 → 用 staging 而非 target
    
        
    Buildroot 构建中途失败或磁盘写满df -h;看 output/build/<pkg>/*.log 与 make 最后 30 行剩余空间 > 5 GB,错误能定位到具体包空间不足 → 清 build 目录或扩盘;下载失败 → 配 BR2_PRIMARY_SITE / 代理
    
        
    启动后 panic,提示找不到 init挂载 rootfs.ext2,检查 /sbin/init、/etc/inittab 权限;确认 BusyBox 已启用init 存在且可执行缺 BusyBox → 开 BR2_PACKAGE_BUSYBOX;权限错 → 检查 overlay 权限后重打镜像
