边缘 AI 模型部署:把模型压进 MCU

训练一个模型只是开始。边缘部署要同时过三关:精度不能掉出验收线、延迟要满足控制周期、 内存要装进 Flash/RAM。本页用"量化映射 + 三本账"把 FP32→INT8 讲清楚,给一个可直接执行的 IMU 手势识别部署项目,并用 gcc 核算量化误差、内存与算力下限。

3. 原理与图示

3.1 量化是什么:一条仿射映射

INT8 不是"把 float 截断成整数",而是用 scale 与 zero-point 把浮点区间线性映射到 0–255(或 -128–127), 推理时用整数乘加,输出再反量化。映射本身有误差,误差大小取决于区间、离群值和粒度。 

x ∈ [min, max](范围必须包含 0)      q ∈ [0, 255]
s = (max − min) / 255                 z = round(−min / s)
q = clamp( round(x / s) + z, 0, 255 )
x̂ = s · (q − z)

per-tensor:整个张量共用一个 s/z(激活常用)
per-channel:每个输出通道一组 s/z(权重常用,能缓解通道间离群值)
对称 int8:z=0,范围 [−127,127];非对称 uint8 保留 0 的精确表示

上图的 z 是 zero-point,不是"零点漂移";它保证浮点 0 能被整数精确表示。卷积/全连接的权重通常 per-channel 对称量化, 激活通常 per-tensor 非对称量化;具体以转换工具的支持矩阵为准。

3.2 三本账:内存、算力、带宽

账本估算式常见误判
内存权重 = 参数量 × 每参数字节(FP32 4B / INT8 1B)+ scale/zp;激活 = 峰值张量 × 字节;再加栈、allocator、双缓冲。只算权重,忽略 arena;INT8 权重 12KB,arena 却要 20KB,总 RAM 仍可能超。
算力计算时间 ≈ FLOPs × batch / (峰值算力 × 利用率)。INT8 峰值通常是 FP32 的 2×/4×,但取决于芯片与 SIMD。拿 datasheet 峰值当实测;忽略算子回退 FP32、padding、非线性与调度开销。
带宽访存时间 ≈ (权重 + 激活 × batch) / 带宽。权重在 batch 内可复用,激活随 batch 线性增长。以为 batch 越大越省;batch 增大后激活内存与带宽先撞墙,延迟不一定线性下降。
t_compute ≈ FLOPs · B / (TOPS · 1e12 · util)          // 秒
t_memory  ≈ (W + A · B) / (BW · 1e9)                  // 秒
t_est     ≈ max(t_compute, t_memory) + overhead       // 固定开销含调度/前后处理

W = 权重字节,A = 单样本激活字节,B = batch,BW = GB/s,util = 有效利用率
瓶颈 = 谁更大;优化先打瓶颈,否则只是把另一侧的空闲放大

3.3 精度损失从哪里来

来源表现对策 / 验证
舍入与截断每个权重/激活有半个 scale 的误差,逐层累积per-channel 权重;敏感层保留 FP32;固定测试集对比
离群值拉大 scale大部分值挤在少量整数格点,分辨率下降校准集覆盖真实分布;per-channel;QAT;裁剪极端值(需验证)
激活分布随输入变化校准时没见过的手势/噪声导致饱和校准集按人/场景分层;在线拒绝低置信度;滑动投票
算子不支持/回退部分层跑 FP32,速度与内存都不如预期转换前查算子表;替换/融合;测 op list 而不是只看总延迟
预处理不一致PC 上准确、板端乱答固定一条样本,逐层导出中间张量对比;归一化参数来自训练集
PTQ(训练后量化)快,适合先跑通;QAT(量化感知训练)能恢复部分精度,但成本更高。验收要写清楚: "在固定测试集上,相对 FP32 的 top-1 下降 ≤ X pp",而不是"看起来差不多"。

3.4 部署链路

数据/标签 → FP32 训练 → 导出 ONNX → 校准集 PTQ(失败则 QAT)
      → 转换(TFLite Micro / STM32Cube.AI 等)→ 算子支持检查
      → 内存规划(weights/arena/stack/.map)→ 固件集成(DMA/预处理/后处理)
      → DWT 延迟 + 固定测试集精度 + .map 内存 → 三张表 → 验收或回退

3.5 gcc 核算证据 compiled

怎么读这组数:离群值把 per-tensor 的 scale 从 0.0101176 拉到 0.0144314(分辨率约粗 42.6%); per-channel 把 ch0 拉回 0.0050196,mean 误差从 0.00175 降到 0.00087。但 per-tensor 的 max 误差(0.00439) 反而小于干净张量的 0.00494——因为误差还取决于数值落在格点的位置。这正说明:不能用一个 scale 或一个"典型掉点"推断精度, 必须用验证集实测。

内存 3.91× 而不是 4×,因为 INT8 还要存 102 个权重 scale + 10 个激活 scale;算力下限 2.00× 而不是 4×, 因为这里假设 M7 上 FP32 1 MAC/cycle、CMSIS-NN INT8 约 2 MAC/cycle,且不含调度与前后处理。 把这两个假设换成你板子的实测 cycles,才是可验收的数字。

展开 quant_check.c 源码(与上面输出逐行对应) 
#include <stdio.h>
#include <math.h>
#include <stdint.h>

#define N 8
#define NCH 2
#define CHN 4

typedef struct { float scale; int zp; } qparam;

static qparam make_qparam(const float *x, int n)
{
    float mn = 0.0f, mx = 0.0f;
    qparam p;
    int i;
    for (i = 0; i < n; i++) {
        if (x[i] < mn) mn = x[i];
        if (x[i] > mx) mx = x[i];
    }
    p.scale = (mx - mn) / 255.0f;
    if (p.scale <= 0.0f) p.scale = 1e-8f;
    p.zp = (int)lrintf(-mn / p.scale);
    if (p.zp < 0) p.zp = 0;
    if (p.zp > 255) p.zp = 255;
    return p;
}

static uint8_t to_q(float v, qparam p)
{
    long q = lrintf(v / p.scale) + p.zp;
    if (q < 0) q = 0;
    if (q > 255) q = 255;
    return (uint8_t)q;
}

static float from_q(uint8_t q, qparam p)
{
    return p.scale * ((float)q - (float)p.zp);
}

static void errors(const char *name, const float *x, int n, qparam per[])
{
    float maxe = 0.0f, sum = 0.0f;
    int i;
    for (i = 0; i < n; i++) {
        qparam p = per[i];
        float e = fabsf(from_q(to_q(x[i], p), p) - x[i]);
        if (e > maxe) maxe = e;
        sum += e;
    }
    printf("%-14s max=%.5f mean=%.5f\n", name, maxe, sum / (float)n);
}

int main(void)
{
    const float base[N] = {-1.28f, -0.75f, -0.20f, 0.00f, 0.33f, 0.91f, 1.27f, 1.30f};
    float outlier[N];
    qparam pt_base, pt_out, pc[NCH];
    int i, c;

    for (i = 0; i < N; i++) outlier[i] = base[i];
    outlier[N - 1] = 2.40f;

    pt_base = make_qparam(base, N);
    pt_out  = make_qparam(outlier, N);
    for (c = 0; c < NCH; c++) pc[c] = make_qparam(&outlier[c * CHN], CHN);

    printf("A. affine uint8 mapping, clean tensor, scale=%.7f zp=%d\n",
           pt_base.scale, pt_base.zp);
    printf("%-8s %-6s %-9s %-9s\n", "float", "uint8", "dequant", "abs_err");
    for (i = 0; i < N; i++) {
        uint8_t q = to_q(base[i], pt_base);
        float xh = from_q(q, pt_base);
        printf("%-8.2f %-6u %-9.5f %-9.5f\n", base[i], q, xh, fabsf(xh - base[i]));
    }

    printf("\nB. one outlier (2.40) in the last element\n");
    printf("per-tensor     scale=%.7f zp=%d\n", pt_out.scale, pt_out.zp);
    for (c = 0; c < NCH; c++)
        printf("  channel %d    scale=%.7f zp=%d\n", c, pc[c].scale, pc[c].zp);
    {
        qparam pt_all[N], pc_all[N];
        for (i = 0; i < N; i++) {
            pt_all[i] = pt_out;
            pc_all[i] = pc[i / CHN];
        }
        errors("per-tensor", outlier, N, pt_all);
        errors("per-channel", outlier, N, pc_all);
    }
    printf("note: max error depends on value alignment; mean is the stabler signal.\n");

    printf("\nC. memory budget | 11,686 params, 200x6 input\n");
    {
        long params = 11686;
        long act_fp32 = 7600 * 4L;
        long act_int8 = 7600L;
        long w_fp32 = params * 4L;
        long w_int8 = params + 102L * 4L + 10L * 4L;
        printf("FP32: weights=%ld B, arena=%ld B, total=%ld B\n", w_fp32, act_fp32, w_fp32 + act_fp32);
        printf("INT8: weights=%ld B, arena=%ld B, total=%ld B\n", w_int8, act_int8, w_int8 + act_int8);
        printf("reduction: %.2fx\n", (double)(w_fp32 + act_fp32) / (double)(w_int8 + act_int8));
    }

    printf("\nD. compute lower bound | 608,384 MACs @ 480 MHz\n");
    {
        double macs = 608384.0;
        double t_fp32 = macs / 480e6 * 1e3;
        double t_int8 = macs / 2.0 / 480e6 * 1e3;
        printf("FP32 1 MAC/cycle : %.3f ms\n", t_fp32);
        printf("INT8 2 MAC/cycle : %.3f ms\n", t_int8);
        printf("lower-bound speedup: %.2fx (overhead not included)\n", t_fp32 / t_int8);
    }
    return 0;
}

假设:INT8 峰值来自 datasheet 或实测,FP32 峰值 = INT8 × 所选比例;利用率包含 padding/调度损失。 这些都是预算,不是实测;INT8 权重未含 scale/zp(本例约 0.4KB,表 C 已计入);精度损失不在本表,必须用验证集测。

做三个对比: ① 保持 MCU 预设,把 batch 从 1 调到 8,记录 FP32/INT8 延迟与加速比,解释权重摊销与固定开销; ② 切到"边缘 SoC",比较 batch=1 与 batch=8,看瓶颈是否从访存转计算; ③ 把"固定开销"调到 0,观察加速比如何接近峰值比——这说明为什么端到端加速总小于算力比。

4.2 方向项目:IMU 手势识别的 INT8 部署 hardware-pending

目标:把一段 6 轴 IMU 手势分类模型部署到 Cortex-M7,并在固定测试集上给出精度、延迟、内存三张对照表。 模型刻意做小:输入 200×6(100Hz × 2s),两层 Conv1D + GAP + Dense 6 类,11,686 参数、608,384 MAC。

#步骤具体动作产出 / 验收
1数据与切分6 类手势(上/下/左/右/画圈/静止),3 人各 200 段;按人划分 train/val/test,禁止同一段数据跨集;归一化参数只从训练集算。切分清单 + 每类样本数;测试集完全不参与调参。
2FP32 基线固定随机种子训练 1D-CNN;记录 val/test top-1 与混淆矩阵;导出 ONNX;确认输入布局 [1,200,6] 与板端一致。FP32 测试集 ≥95%(目标);导出模型可复现。
3量化从训练集抽 200 段校准集;权重 per-channel、激活 per-tensor;记录每层 scale/zp 与逐层误差;若掉点 >1.5pp,做 3–5 epoch QAT。量化报告;PTQ/QAT 两版权重与验证集结果。
4转换ONNX → TFLite Micro 或 STM32Cube.AI;查算子支持表;Conv1D 常需 reshape 成 Conv2D;GAP/Softmax 是否融合;不支持的算子替换或手写。op list 中热路径无 FP32 回退;模型可在 PC 端解释器跑通。
5内存规划权重放 const Flash;计算 arena 峰值;用解释器 arena_used_bytes()/AllocateTensors() 返回值验证;查 .map 的 .rodata/.bss/.stack;给 DMA 双缓冲留空间。RAM/Flash 均低于预算;AllocateTensors() 返回 kTfLiteOk,arena_used_bytes() 在预算内。
6固件集成IMU 100Hz 采样,DMA 双缓冲;预处理(去重力/归一化/滑窗)与训练完全一致;invoke 后做阈值拒绝 + 3 帧滑动投票;串口输出类别/置信度/耗时。连续 30min 无看门狗复位;误触发率可量化。
7测量DWT cycle counter 包住 invoke,跑 1000 次取 mean/P99;GPIO 翻转 + 示波器复核;固定测试集跑板端精度;记录 .map 与 arena 实际大小。延迟 CSV、精度混淆矩阵、内存表三份原始数据。
8验收三张对照表 + 失败案例(哪些手势/人/噪声下错)+ 复现脚本;若精度或延迟不达标,回到量化/模型结构,不放宽阈值。报告可被第三人按 README 复现。
